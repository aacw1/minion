# GUI 视觉焕新（暖石主题）设计

- 日期：2026-10-18
- 状态：待评审
- 原型：`docs/superpowers/specs/assets/2026-10-18-ui-preview.html`（浏览器打开，顶部可切 A/B/C 三套方案）
- 选定方案：**A · 暖石**（暖中性色 + 陶土橙强调）

## 1. 目标与范围

### 1.1 目标

1. 统一色温与层级：正文 / 面板 / 浮层三级抬升，去掉「纯黑 + 蓝紫边框 + Material 高饱和色」的割裂感。
2. 建立字号与间距节奏：正文 14px、次级 12.5px、辅助 11px；4px 网格。
3. 收敛强调色：单一主色 `#d97757` + 成功 / 警告 / 错误三个语义色。
4. 让消息更像对话而非控制台日志：用户气泡右对齐、AI 身份行、工具调用卡片化、正文限宽居中。
5. **所有能打开的窗口统一**：主窗口、设置窗（5 页签）、列表类弹窗、表单类弹窗、小弹窗、补全弹层、高危确认卡片。
6. 弹窗改为无边框 + 自绘标题栏，消除 Windows 浅色系统标题栏与深色内容的割裂。

### 1.2 不在范围内

- 文件选择器 / 目录选择器（`FileChooser`、`DirectoryChooser`）：系统原生窗口，无法定制。
- 业务逻辑、工具行为、LLM 协议。
- 新增动画（呼吸点、齿轮旋转沿用现有实现）。
- 浅色主题 / 主题切换开关（本次只做深色 A 方案）。

### 1.3 验收基线

以原型 HTML 为准，允许 JavaFX 能力差异（见 §6 限制）导致 1-2px 级差异，但色板、层级、字号、组件形态必须一致。

**注意**：JavaFX 8 CSS 不支持 `var()`、`::before/::after`、`backdrop-filter`、`conic-gradient`、CSS transition。颜色值本身支持 `rgba(...)`，但无法复用变量；所有颜色写死，令牌名只作为 `theme.css` 注释中的规范（例如 `/* bg-panel #201e1b */`），便于后续统一替换。

对比度初校：`#f4efe7` on `#1b1a18` ≈ 13.5:1；`#b6afa2` on `#201e1b` ≈ 7.4:1；`#857f74` on `#201e1b` ≈ 3.6:1（仅辅助信息）；`#23130d` on `#d97757` ≈ 5.6:1。

### 2.2 字号 / 字重

| 用途 | 字号 | 字重 |
|---|---|---|
| 根（默认） | 14px | 400 |
| 品牌名 | 15px | 600 |
| 页签 / 会话名 / 分区标题 | 12.5–13px | 500–600 |
| 消息正文 / 输入框 | 14px | 400 |
| 次级说明 / 表单标签 | 12.5px | 400 |
| 辅助（时间、提示、徽标） | 11px | 400 |
| 代码 / diff | 12.5px | 400 |

字体栈：`"Microsoft YaHei UI", "Microsoft YaHei", "Segoe UI"`（保持现有，去掉不存在的 Cascadia）。
代码：`Consolas, "Courier New", monospace`。

**字重限制**：JavaFX 8 的 `-fx-font-weight` 实际稳定支持 `normal` / `bold`；原型中的 500/600 在落地时统一用 `bold`，不要写 500/600（可能被忽略或回退）。

**行高限制**：JavaFX 的 `TextArea` / `Label` 不支持 CSS `line-height`。消息正文的宽松行距无法 1:1 还原，只能通过段间距（`VBox` spacing / padding）改善。原型中 1.78 行高是 HTML 效果，落地后约 1.3，验收时以「可读、不拥挤」为准。

### 2.3 圆角 / 间距 / 阴影

| 令牌 | 值 |
|---|---|
| radius-lg | 14（输入框）、12（窗口 / 卡片） |
| radius-md | 9（按钮、列表、工具卡） |
| radius-sm | 6（chip、输入框内元素） |
| 间距 | 4 / 6 / 8 / 12 / 16 / 20 / 24 |
| 窗口阴影 | `dropshadow(gaussian, rgba(0,0,0,0.55), 28, 0, 0, 10)` |
| 卡片阴影 | `dropshadow(gaussian, rgba(0,0,0,0.35), 12, 0, 0, 4)` |

JavaFX 的 `dropshadow` 半径与 CSS `box-shadow` 语义不同，以实际观感微调。

### 3.2 消息区

**限宽居中**：`ChatView` 监听自身宽度，动态设置左右 padding，使正文宽度 ≤ 828px：
`pad = max(20, (width - 828) / 2)`。背景仍由 `ChatView` 铺满 `#1b1a18`。不改 `ScrollPane` 的 `fitToWidth`。

**用户消息**：`USER_MESSAGE` / `USER_SUPPLEMENT` 不再走 `append(...)` 普通段，改为 `appendUserBubble(text)`：

```
HBox(alignment CENTER_RIGHT)
└── MessageTextArea  (styleClass: msg-user-bubble, maxWidth ≤ 620)
```

- 气泡：bg `#332a22`、边框 `#45382c`、圆角 13/13/4/13、padding 10 14。
- `MessageTextArea .content` 必须设置为气泡底色（LCD 子像素渲染要求不透明层），否则文字发虚（沿用现有规则）。
- 不显示【输入】标签；`USER_SUPPLEMENT` 右上角加 10.5px「补充」小徽标。
- 保留原生拖选、Ctrl+C、右键菜单。

**AI 身份行**：每轮（一条用户消息之后）只插入一次，位置在该轮第一条 AI 输出之前：

```
HBox(6) : avatar 19×19（渐变圆角 6，字母 m） + "minion" 12.5/bold + 模型名 11.5/text-3 + 时间 11/text-3
```

- 模型名从 `ModelManager` 当前模型读取；`ChatView.forSession` 增加可选参数传入模型名，传入 null 时只显示 "minion"。
- 时间取事件时间戳；`EventList.Ev` 若无 ts 字段则用 `System.currentTimeMillis()`。
- 用户消息到达时置「本轮未出身份行」标记；下一个非用户事件渲染前插入并清除标记。

**AI 正文**：无标签，直接 `MessageTextArea`，样式 `log-body-reply` 保持白色系；段间距 12。

**思考**：沿用 `CollapsibleText`，样式改为：
- 左侧 2px `#3a362f` 竖线、padding-left 12、12.5px、`#857f74`、hover 变 `#b6afa2`；
- chevron 放最左；摘要文案「思考 · <首行 40 字>」；
- 展开内容同色系，不做高亮。

**工具调用**：`CollapsibleText` 外层加 `tool-card` 样式：
- 底 `#262320`、边框 `#3a362f`、圆角 9；
- 摘要行：状态图标 18×18（成功绿 / 失败红 / 运行中主色）+ 名称 12.5/550 + 详情 11.5/text-3 + 右侧增删统计（diff 时）+ chevron；
- 展开内容：`#151412` 底、`#2a2723` 顶边框、12px 等宽、行内 `+/-` 淡绿/淡红底。
- 需要 `CollapsibleText` 支持自定义摘要节点（已有）与卡片容器样式（新增 styleClass）。

**系统 / 错误 / 警告**：
- 普通系统行：12.5px、`#857f74`、无标签、左侧 2px 灰线。
- 错误：左侧 3px `#e08272` + 底 `#342321` + 圆角 6 + padding 8 10 + 12.5px。

### 3.4 设置窗与所有弹窗

**统一封装**：新增 `com.minion.gui.dialog.DarkDialogs`（工具类，替代直接 `new Dialog` / `new Alert`）：

```java
static <T> Dialog<T> create(String title, Node content, ButtonType... buttons);
static Optional<ButtonType> confirm(Window owner, String title, String message);
static void error(Window owner, String title, String message);
static Optional<String> textInput(Window owner, String title, String label, String initial);
```

实现要点：

1. `dialog.initStyle(StageStyle.UNDECORATED)`；`initOwner(owner)`；`initModality(Modality.APPLICATION_MODAL)`；
2. `DialogPane.setHeaderText(null)`、`setGraphic(null)`，避免默认 header 与自绘标题栏重复；
3. `DialogPane` 作为根，自绘标题栏（HBox：标题 13px/bold + 弹性空白 + 关闭按钮 30×30）；
4. 标题栏拖动：`setOnMousePressed/Dragged` 修改 `dialog.getDialogPane().getScene().getWindow()` 的 X/Y；
5. 圆角与阴影：`setOnShown` 时 `scene.setFill(Color.TRANSPARENT)`，`DialogPane` 设 `-fx-background-radius: 12` + dropshadow；
6. 按钮栏保留 `DialogPane` 默认布局，样式统一（次按钮 ghost、主按钮主色）；
7. ESC 关闭沿用 `DialogPane` 默认行为；关闭按钮调用 `dialog.setResult(...)` / `dialog.close()`；
8. **风险回退**：若 UNDECORATED Dialog 在 JavaFX 8 出现模态/焦点/拖动问题，退回「系统标题栏 + 内部深色」，并记录在实施计划中。

| `gui/StatusDot.java`、`RunningIndicator.java` | 颜色/胶囊 |
| **新增** `gui/dialog/DarkDialogs.java` | 自绘标题栏弹窗封装 |
| 旧样式类 | 保留为兼容别名（如 `.msg-textarea`、`.log-body*`、`.btn-ghost`），逐步迁移，避免漏改控件回退默认样式 |

## 5. 实施顺序

1. **阶段 1 · 壳层**：设计令牌 + 标题栏 + 侧栏 + 页签 + 输入区 + 滚动条 + 运行指示器。
2. **阶段 2 · 消息区**：限宽、用户气泡、AI 身份行、思考/工具/系统样式、代码块。
3. **阶段 3 · 弹窗**：`DarkDialogs` + 设置窗 + 数据源/SSH/浏览器/工作空间/重命名/确认类。
4. **阶段 4 · 打磨**：描边图标、文案、空态、DPI 125% 复核、性能回归。

每阶段结束执行 `mvn -q compile` + 相关测试，并启动 jar 手工核对；阶段 3 前先做 `DarkDialogs` 的原型 spike（一个弹窗），确认 UNDECORATED 在 JavaFX 8 可行后再铺开。

## 6. 约束与限制（务必知悉）

1. JavaFX 8 无 CSS 变量 / transition / `::before`，hover 切换是瞬时的；原型中的过渡动画不会 1:1 存在。
2. `TextArea` 不支持行高，正文行距比原型紧凑。
3. `ScrollPane` 内容的居中限宽通过动态 padding 实现，窗口极窄时正文宽度会小于 828。
4. 描边图标在 14px 下可能偏细，需要按实际渲染微调 `-fx-stroke-width`。
5. 无边框弹窗依赖 `StageStyle.UNDECORATED` 的拖动/模态行为，必须在目标机器（Win7/Win10 + JDK 8）实测。
6. 系统文件选择器保持原生浅色，无法统一。
7. **主窗口保持直角**：无边框 Stage 的窗口级圆角不在本次范围（需要透明场景 + 性能代价）；原型外框的 13px 圆角只是预览容器。弹窗内部圆角照常实现。

## 7. 风险与回退

| 风险 | 应对 |
|---|---|
| UNDECORATED Dialog 在 JavaFX 8 有焦点/拖动缺陷 | 先 spike；失败则退回系统标题栏，仅统一内部配色 |
| 字号整体调小导致固定尺寸布局挤压 | 阶段 1 逐窗核对；设置窗改为 920×560，输入框 minHeight 上调 |
| 消息结构重构破坏流式合并/复制 | 保留 `Seg`/`StreamBuffer` 逻辑，只替换行容器；跑 `ChatView*Test` |
| 限宽动态 padding 引起滚动抖动 | 监听 `widthProperty` 时做 1px 取整，避免频繁重排 |
| 深色弹窗阴影在无边框窗口外被裁剪 | 场景透明 + 根容器 padding 预留阴影空间；否则去掉阴影 |
| 设置窗尺寸调整后内容溢出 | 改为 920×560，内容区不滚动；若某页超长，仅该页使用细滚动条 |
