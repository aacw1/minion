# 2026-08-15 聊天正文模糊修复（探针实证，纠正 8-13「显式 LCD」假阳性）

## 1. 背景

用户报告：聊天消息正文「字不够清晰、有点糊」。此前 8-13（77b0116）已做过一次
修复（ChatView 根挂 `.chat-content` + `-fx-font-smoothing-type: lcd`），用户当时
目测通过；但 8-14 消息区改纯控制台风格（5e4db92）重写 ChatView 时删掉了
`.chat-content` 挂载行，主题 css 中的规则成了死规则。

## 2. 根因（像素探针实证，非猜测）

### 2.1 探针方法

`E:/javame/jdk8` + 真实 theme.css，构造 ScrollPane/TextArea/Label/裸 Text 各形态，
snapshot 后按区域统计**边缘像素 RGB 通道分离比例**（LCD 子像素渲染的边缘有彩色
条纹，灰阶抗锯齿边缘 R=G=B），并对比 `-Dprism.text=t2k` 光栅器。

### 2.2 证据链

| 形态 | 默认 Prism | T2K |
|---|---|---|
| TextArea `.content` 不透明深底（#0F1115） | **53.5% 彩色（LCD）** | 60.1% |
| TextArea 透明底（修复前现状） | 0%（灰阶） | 0% |
| Label 深底（8-13 时代正文形态） | 0%（灰阶） | 0% |
| 裸 Text（ScrollPane 内） | 0%（灰阶） | 0% |

- CSS 属性层：`.msg-textarea` 的 `-fx-font-smoothing-type: lcd` 已传到 TextArea
  内部 Text 节点（属性值 LCD），但**渲染层仍是灰阶**——属性层探针会误导。
- **真正的机制**：JavaFX 8 Prism（含 T2K）对**透明表面**只做灰阶抗锯齿，
  LCD 子像素渲染仅在**不透明表面**上可用；深色 UI 的透明背景 + Windows 125%
  缩放放大灰阶柔边 = 正文发虚根因。
- **8-13 的 `.chat-content` 修复从未生效**：探针证明该 lcd 声明连属性层都没传到
  子 Text（挂在 VBox 上，子 Text 属性仍 GRAY）；当时目测「通过」为假阳性
  （同期改动了设置页/页签，验证不严格）。
- T2K 光栅器在透明底同样灰阶、无优势，放弃（且需全局改启动参数，风险大）。

### 2.3 最小修复组合

只把 `.msg-textarea .content` 设为不透明深色背景（与 `.panel-dark` 同色 #121314，
视觉无缝）即可恢复 LCD（53.5%）；`.scroll-pane`/`.viewport` 保持透明即可
（v6 探针：content-only 与全链路无差异）。

## 3. 修复

`src/resource/theme/theme.css`：`.msg-textarea .content` 背景
`transparent` → `#121314`，注释同步记录机制与 8-13 纠正。

其余（`.msg-textarea` 自身/`.scroll-pane`/`.viewport` 透明）保留：
防 modena 白底透出「白色块」仍需自身透明。

## 4. 验证

- 探针复跑（修改后真实 CSS）：三种形态全部 53.5% LCD，修复前 0%。
- `mvn compile` + `mvn test` 全量通过。
- 用户真机目测（返回后验收）：聊天正文应锐利；若 LCD 色边不可接受，
  降级方案：改回透明底 + 接受平台限制（灰阶），或调大字号/字重观感补偿。
