# 终止仅鼠标触发：键盘不再终止运行 + 空输入 3 秒提示

日期：2026-09-14
状态：已实施（键盘路径永不终止 + 空输入 3 秒提示；鼠标点方块终止保留 500ms 防抖）

## 背景与问题

现象：会话运行中、输入框为空时，按「确认键」（发送键：默认设置下为 Enter，Ctrl+Enter 模式下为
Ctrl+Enter）会直接把当前运行终止。

根因（已核实代码）：

1. `InputView` 键盘过滤器（`KeyEvent.KEY_PRESSED`，InputView.java:145）把发送键交给与鼠标点击
   **共用的** `onAction()`；`onAction` 按 `buttonMode(running, askPending, hasContent)` 分发，
   「运行中 + 空输入」判定为 `BtnMode.STOP` → `manager.stop(current)`。
   **触发来源（键盘/鼠标）从未进入分发表**——这是根因。
2. 默认配置 `input.enterSends=true`（Enter 发送），因此默认设置下运行中空输入按 Enter 即等于
   点击终止按钮。
3. 次要路径：方块按钮获得焦点后按 Space/Enter 会激活按钮（JavaFX Button 默认键盘行为），
   同样经 `onAction` 落入 STOP。
4. 无其他键盘终止路径：无全局 Accelerator、无 /stop 命令；右键菜单「删除会话」与窗口关闭
   属鼠标/系统语义，不在本次范围。

历史补丁的局限：2026-09-13「四问题修复」为同一现象加了 `STOP_GUARD_MS = 500` 防抖，只挡
「发送后 0.5 秒内的重复按键」；窗口外再按仍会终止。本次改为**结构性根治**：键盘路径永远
不能到达终止动作。

## 目标

1. 终止动作**只能由鼠标点击发送行方块按钮**触发；任何键盘路径（输入框发送键、按钮聚焦时的
   Space/Enter）都不得终止运行。
2. 键盘在「输入框为空」时按发送键 → 弹 3 秒自动消失的提示「输入内容为空」（不写聊天历史、
   不改动输入内容、不打断输入）。
3. 保持不变：鼠标点击方块按钮仍终止；`STOP_GUARD_MS` 防抖保留（防鼠标双击发送按钮时
   第二击误终止）。

## 非目标

- 不改右键菜单/窗口关闭的终止路径（鼠标与系统语义）。
- 不改「提问挂起（askPending）」时的按钮语义与终止入口。
- 不引入全局快捷键系统；不改 Enter/Ctrl+Enter 的发送键语义。

## 方案

### 1. `onAction` 增加触发来源维度

`private void onAction(boolean byMouse)`：

- 键盘过滤器发送键分支 → `onAction(false)`；
- `sendButton.setOnAction` → `onAction(true)`。

分发规则（键盘路径永不进入 STOP）：

| 模式 | 键盘（byMouse=false） | 鼠标（byMouse=true） |
|---|---|---|
| SEND | 发送 | 发送 |
| SUPPLEMENT | 补充 | 补充 |
| ANSWER | 回答 | 回答 |
| SEND_DIM / ANSWER_DIM | 提示「输入内容为空」 | 维持现状（静默） |
| STOP | 提示「输入内容为空」，绝不终止 | 终止（保留 500ms 防抖） |

纯函数（可脱离 JavaFX 单测）：

```java
static boolean isKeyboardEmptyTrigger(BtnMode mode, boolean byMouse)
// 键盘 且 (SEND_DIM | ANSWER_DIM | STOP)
```

### 2. 方块按钮的键盘激活拦截

`sendButton` 加 `KeyEvent.ANY` 过滤器：按键为 SPACE/ENTER 且当前模式为 `STOP` 时 `consume()`
——方块按钮鼠标专用；其他模式下保持按钮原有键盘激活行为不变（最小变更）。

纯函数：

```java
static boolean blockButtonKeyActivation(KeyCode code, BtnMode mode)
// (SPACE | ENTER) && STOP
```

### 3. 3 秒提示浮层（InputView 内）

**位置**：输入框（居中 61.8% 宽的大框）**正上方悬浮、水平居中**，底边距输入框上沿 8px
（即盖在聊天区最底部一线之上）；不遮挡输入内容、不改变输入框布局、不挡鼠标操作。

- 新增 `Label toast`（样式类 `input-toast`），挂在包住 `frame` 的 `StackPane` 中：
  `mouseTransparent=true`（鼠标穿透）、`maxSize=USE_PREF_SIZE`，
  `translateY` 绑定 `-height-8` 实现上方悬浮；`managed` 保持 true（不参与布局的节点尺寸会停在
  0 而不显示）——toast 单行尺寸远小于大框，`StackPane` 的 pref 尺寸仍由大框决定，
  输入框布局不变。
- 时序：FadeTransition 150ms 淡入 → PauseTransition 3000ms → FadeTransition 250ms 淡出 →
  隐藏；重复触发先停旧动画再重放（计时重置）。
- CSS 落位：`src/resource/theme/theme.css` 输入区段落（`.input-frame` / `.input-divider`
  附近，约 103–130 行）新增 `.input-toast`，配色沿用现有色板：

```css
/* 键盘空输入提示（InputView toast）：悬浮输入框上方，3 秒自动淡出，不占布局 */
.input-toast {
    -fx-background-color: #232733;
    -fx-border-color: #3a4050;
    -fx-background-radius: 6;
    -fx-border-radius: 6;
    -fx-padding: 5 12 5 12;
    -fx-font-size: 12px;
    -fx-text-fill: #a8b0bb;
}
```

## 测试与验证

单测（纯函数，无 JavaFX toolkit）：

- `isKeyboardEmptyTrigger`：STOP/键盘=true、STOP/鼠标=false、SEND_DIM/键盘=true、
  ANSWER_DIM/键盘=true、SEND|SUPPLEMENT|ANSWER/键盘=false；
- `blockButtonKeyActivation`：STOP+SPACE=true、STOP+ENTER=true、STOP+其他键=false、
  SEND+SPACE=false；
- 既有 `shouldIgnoreTrigger` 防抖用例保持通过。

手工验收（GUI）：

1. 运行中空输入按 Enter / Ctrl+Enter → 不终止，弹「输入内容为空」，约 3 秒消失；
2. 运行中点击方块按钮 → 正常终止；
3. 发送后 0.5 秒内点击方块按钮 → 防抖忽略（既有行为）；0.5 秒后点击 → 终止；
4. Tab 聚焦方块按钮按 Space → 不终止（仅 STOP 模式拦截）；
5. 空闲、提问挂起时空输入按发送键 → 同样提示，不发送。

## 风险与回退

- 提示浮层：`managed=false` + StackPane 不裁剪，输入框位置不变；如异常可只移除 toast 挂载，
  其余修复独立成立。
- 按钮键盘拦截范围：仅 STOP 模式，纯函数单测 + 手工验收覆盖。
