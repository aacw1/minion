# 模型配置空文件自动初始化双供应商 设计

日期：2026-08-15

## 背景

`ModelManager.load()` 在 model.json 缺失、内容空/无效、损坏（备份 .bak）三种情况下会重建默认配置，但目前只生成单个 deepseek 默认模型。DeepSeekClient 已内置 qwen 供应商适配（`enable_thinking`、`include_usage`），README 与 `src/resource/config_qwen.properties` 也记录了千问推荐参数，缺的只是初始化入口：空文件重建时把千问配置也一并预填。

目标：模型配置文件为空（三种情况）时自动初始化 deepseek + 千问两套模型配置，除 apiKey 外全部按各自调用参数预填；已有合法文件零改动（不迁移、不合并）。

## 方案

代码内双默认模板：`createDefault()` 拆为 `createDeepseek()`（现值原样）+ 新增 `createQwen()`，`load()` 重建分支依次加入两套。

否决方案：
- classpath 资源模板文件拷贝：机制与现有代码构建默认值不一致，模板同步成本高。
- provider 模板注册表：当前仅两家供应商，YAGNI。

## 数据

| 字段 | deepseek（现状不变） | qwen（新增） |
|---|---|---|
| displayName / modelName | deepseek-v4-flash | qwen3-max |
| url | https://api.deepseek.com/v1/chat/completions | https://dashscope.aliyuncs.com/compatible-mode/v1/chat/completions |
| provider | deepseek | qwen |
| thinking | true | true |
| reasoningEffort | max | max（客户端对 qwen 忽略，仅发 enable_thinking=true） |
| maxContextTokens | 900000 | 131072 |
| compressThreshold | 0.8 | 0.8 |
| keepRecentMessages | 10 | 10 |
| apiKey | "" | ""（留空待用户填写） |

列表顺序 deepseek 在前 → 重建后 current 回退取第一个 = deepseek，首次运行默认行为不变。

## 结构改动

仅 `core/config/ModelManager.java`：

- `createDefault()` → `createDeepseek()`（改名，内容不变）
- 新增 `createQwen()` 静态工厂
- `load()` 重建分支：依次直接加入列表（`models.add(createDeepseek())`、`models.add(createQwen())`，与现有直插方式一致，不走公开 `add()` 的去重/current 副作用），`currentName` 仍取列表第一个（deepseek）

其余类零改动：SettingsDialog（新增模型仍手动填写）、DeepSeekClient（qwen 适配已存在）。

## 错误处理

现有 `backupCorrupt` 逻辑不动：损坏/结构无效 → 备份 .bak 再重建双默认。

## 测试（ModelManagerTest）

- 更新现有断言：缺失文件 / 损坏文件 / 结构无效 JSON 三种重建路径 → 2 个模型，current=deepseek，.bak 按原语义存在
- `load_nullDisplayNameEntryFiltered`：条目全被过滤落到重建分支 → 2 个模型（断言同步更新）
- 新增回归保护：合法 model.json（仅 deepseek 自定义模型）重载后不变——已有用户配置零迁移
- 新增断言：两套默认 apiKey 均为空、qwen 各字段值正确
