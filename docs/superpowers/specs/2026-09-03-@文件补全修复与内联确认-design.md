# @文件补全修复与内联确认 设计文档

日期：2026-09-03
状态：已实施

## 背景与问题

用户报告两个缺陷：

1. **@文件列表不全、部分文件搜不到**
   `FileSuggester` 设有 `MAX_RESULTS = 200` 条上限，`walkFileTree` 深度优先收集满 200 条即 `TERMINATE`，后续目录的文件整体缺失（实测：minion 工作空间 400+ 文件，仅收 200 条，`src/main/resources` 等目录完全不出现）。此外列表还混入 git 已忽略的目录（`target/`、`run/` 等，实测 run 8.3M/target 20M，全被扫入徒占名额）。

2. **部分文件按确认键/鼠标点击无效**
   鼠标确认路径：ListView 级 `setOnMouseClicked` 在 MouseClicked 时读取 `selectionModel.getSelectedItem()`——依赖 JavaFX ListView 按下-选择时序的瞬时状态，与点击行存在解耦/竞态（点击行 ≠ 选中行时确认失效或错位）。点击空白行还会直接关掉弹层，误关后需重新输入 @。

3. **交互诉求（用户提出）**
   @文件确认后**不再建块（chip）**，改为把 `@路径` 直接内联进输入框（Claude Code 风格），所见即所得。

## 决策（已与用户确认）

- FileSuggester **去掉条数上限**，收集全部非忽略文件；
- 跳过 **.gitignore 忽略的目录与文件**（仅解析工作空间根 .gitignore；不支持 `!` 反向规则——遇 `!` 开头行整体忽略该行，局限在文档注明）；
- 遍历结果按 **字典序排序**（无截断后仅为了稳定可预期）；
- 缓存改 **每工作空间独立一份（5 分钟 TTL）**：会话绑定即后台预热（首次打开会话开始扫描，后续切回/切会话直接命中，不重复扫描）；**缓存过期不阻塞输入**——先读旧缓存即时显示弹层，同时后台异步刷新，刷新结果与当前展示一致则跳过重建（免闪烁）；
- 保留跳过点目录（.git/.idea 等）的现有行为；
- **仅 @文件**改为内联确认；/命令、/技能、粘贴、图片仍建块；
- 鼠标点击确认改为 **cell 级**取 `cell.getItem()`，与选中态完全解耦。

## 实现方案

### 1. FileSuggester（src/main/java/com/minion/gui/input/FileSuggester.java）

- 删除 `MAX_RESULTS` 上限与两处 `TERMINATE` 截断；`preVisitDirectory` 增加 .gitignore 目录过滤；`visitFile` 增加 .gitignore 文件过滤；
- 读根目录 `.gitignore`（不存在/读失败则视为无规则）；
- 输出按 label 字典序 `Collections.sort`；
- 缓存改为 `Map<工作空间, Entry{files, at}>` 多项目独立缓存，TTL 5 分钟；新增三个接口：
  - `listStaleOk(dir)`：有缓存条目即返回（**含过期**）——@ 弹层先即时显示旧数据；
  - `isFresh(dir)`：缓存存在且在 TTL 内——UI 判定是否需要后台刷新；
  - `load(dir)`：仅新鲜命中直接返回，过期/无缓存才重扫写缓存；
- `CACHE_TTL_MS` 为包内静态非 final（测试临时改小模拟过期）；
- `walk` 保持纯静态可单测；新增包内静态 `parseGitignore(Path)` 供单测。

### 2. 新增 GitignoreMatcher（src/main/java/com/minion/gui/input/GitignoreMatcher.java）

简易 .gitignore 匹配器（仅根级、仅正向规则）：

- 每行 trim；空行与 `#` 注释跳过；`!` 开头行跳过（不支持反向，注明局限）；
- 行尾 `/` → 目录专用规则；无 `/`（除行尾）的模式匹配任意层级 basename；含 `/` 的模式锚定工作空间根相对路径；
- glob 支持：`*`（不含 /）、`?`、`**`（跨 /）；其余字符字面；大小写按文件系统（Windows 忽略大小写，转小写比较）；
- 目录判定 `matchesDir(relPath)`、文件判定 `matchesFile(relPath)`：
  - 目录规则命中即跳过；
  - 文件规则命中该文件即跳过；文件规则也可命中目录？gitignore 语义：`*.log` 只忽略文件；`*.iml` 对目录同样适用吗？——git 对目录本身用文件规则也可忽略（dir 名匹配规则时整目录跳过）。为稳妥：目录命中文件规则也跳过（与 git 行为一致，如 `*.iml` 不会命中目录，无影响；但 `abc*` 命中目录名会整目录跳——git 行为相同）。
- 转正则实现：`**` → `.*`（且允许前缀任意层级），`*` → `[^/]*`，`?` → `[^/]`，其余 `Pattern.quote` 单字符拼接。

### 3. SuggestionPopup（src/main/java/com/minion/gui/input/SuggestionPopup.java）

- 删除 ListView 级 `setOnMouseClicked`；改在 `setCellFactory` 的 cell 上注册 `setOnMouseClicked`：
  ```java
  cell.setOnMouseClicked(e -> {
      Suggestion it = cell.getItem();
      if (it != null && onConfirm != null) onConfirm.accept(it.insertText);
  });
  ```
  点击空行/空白：不回调、不关弹层（不再误关）；
- `hide()` 职责移回 InputView（与键盘路径统一：先 hide 再 runLater 插入，避免事件派发期间改文本）。

### 4. InputView（src/main/java/com/minion/gui/input/InputView.java）

- 统一确认入口 `applyConfirm(Token t, String insert)`（键盘 `confirmPopup` 与鼠标 `confirmInsert` 均调用，经 `Platform.runLater`）：
  - `t.mode == FILE`：`inlineJustInserted = insertionText(FILE, insert)`（即 `@路径`），`input.replaceText(t.start, t.end, inlineJustInserted)`，`positionCaret(t.start + len)`——**不建块**；
  - 其他模式：`addChipFor(t, insert)`（现状：建块并删除 token）；
- 弹层重开抑制：replaceText/positionCaret 会触发 text/caret 监听 → `onTextChanged` 重新解析，插入后的 `@路径`（光标在词尾）会被当作新 @ 词再次弹出补全。新增静态判定（可单测）：
  ```java
  static boolean isInlineQuietState(String text, int caret, String inlineJustInserted)
  ```
  条件：`inlineJustInserted` 非空 且 解析 token 为 FILE 且 `text.substring(t.start, t.end)` 等于 `inlineJustInserted` 且 `caret == t.end` → 静默（不 show 弹层）。
  光标移出该词 / 文本被改动后自动恢复正常补全（inlineJustInserted 保留即可，判定天然失效）；
- `confirmInsert`（鼠标回调）：`if (insert == null || lastToken == null) return;` → 捕获 token 后 `popup.hide()` + `runLater(applyConfirm)` + 清 lastToken + requestFocus 保持；
- **会话绑定即预热**：`bindSession` 里对当前工作空间调 `requestFileLoad`——首次打开会话后台就开始扫描，切回项目不再扫描（缓存命中零开销）；
- **过期缓存先用 + 异步刷新**（单加载通道）：
  - `showFilePopup`：`listStaleOk` 有数据先 `popup.show` 即时显示；`isFresh` 为 false 再 `requestFileLoad` 后台刷新；
  - `requestFileLoad`：`fileLoading` 防抖（同时至多一次 walk），加载中收到新目录记 `pendingLoadDir`，完成后自动续载（切项目连打 @ 不丢首词）；
  - `maybeShowFilePopup`（完成回调）：上下文校验（词仍 FILE、非安静态、工作空间未切）通过后，`SuggestionPopup.showsSame` 判定刷新结果与当前展示一致则跳过重建（免闪烁），有变化才 `show`；预热场景（未输入 @）仅缓存落地；
- SuggestionPopup 新增 `showsSame(allItems, query)`：过滤后与当前展示内容全等比较（含顺序），供刷新回调免重建。

## 风险与局限

- .gitignore 仅支持根级正向规则（! 反向不支持、嵌套 .gitignore 不支持）——局限明确，主流工程目录级忽略（target/ 等）已覆盖；
- 缓存快照语义：5 分钟内新建文件不出现（过期后异步刷新自动补齐，弹层先显示旧数据、刷新后免闪替换）；重启应用后各项目重新扫描预热一次。
