# minion 审查检查点提示词（SystemPromptBuilder 规则 2 扩充）设计

日期：2026-08-16
状态：已确认

## 背景

superpowers 技能工作流（brainstorming/writing-plans）要求"写完设计文档/实施计划后等待用户审查批准"，但该等待仅靠技能正文的软性要求（"Wait for the user's response"），宿主无强制闸门。minion 系统提示规则 2 只在"信息不足/指令不明确"时指引模型调用 ask_user——写完设计文档后模型自认信息充足，直接继续实施，审查检查点失效（用户实测：写完设计文档直接继续执行，未让用户审查）。

根因（调查结论）：
1. AgentLoop 主循环只在"模型不再调用工具"时停止，无写文档后的审查闸门；
2. 技能正文假设宿主有 plan mode/AskUserQuestion，minion 只有 ask_user，模型找不到停止入口；
3. 系统提示规则 2 把 ask_user 限定在"信息不足"场景，压制了模型主动确认的倾向。

## 方案（已确认方向 C：提示词层）

扩充 [SystemPromptBuilder.java](src/main/java/com/minion/core/agent/SystemPromptBuilder.java) BUILTIN 规则 2，把"需要用户审查的产出"纳入必须调用 ask_user 的场景：

现状：

```
2. 用户指令不明确、信息不足或存在多种可能理解时，先列出需要补充的问题，调用 ask_user 工具向用户提问，等待用户回答后再行动；不要猜测用户意图。
```

改为：

```
2. 用户指令不明确、信息不足或存在多种可能理解时，先列出需要补充的问题，调用 ask_user 工具向用户提问，等待用户回答后再行动；不要猜测用户意图。完成需要用户审查的产出（如设计文档、实施计划、关键方案）后，必须先调用 ask_user 请求审查确认，未获批准不得继续下一步。
```

关键点：
- **触发面可控**：仅"产出需审查"场景触发（写了设计文档/计划/关键方案后），普通任务不打扰。
- **复用现有机制**：ask_user 阻塞等待回答，回答经工具结果返回后模型继续（AskUserTool 已实现，无需改）。
- **不绑定 superpowers**：任何需要用户确认的产出（设计文档、实施计划、关键决策）都适用，与具体技能解耦。
