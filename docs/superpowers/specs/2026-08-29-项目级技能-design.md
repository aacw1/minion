# 项目级技能 + 工作空间文案调整 设计文档

日期：2026-08-29
主题：工作空间新增可空「项目级技能路径」，扫描出的技能与内置技能合并进系统提示词，随会话/工作空间切换；同时把工作空间弹窗的 `work.dir` / `project.md` 文案改为中文语义名并加宽弹窗。

状态：已实施

## 背景与现状

- 技能目前只有一个来源：`Main` 启动时用 `SkillManager(config.skillsDir())` 扫一层（`skills/<名>/SKILL.md` 或 `skills/<名>.skill.md`），得到全局 `List<Skill> allSkills`，经 `SessionManager` 的 `loop.setAllSkills(allSkills)` 分发给**所有工作空间的所有会话**（同一份列表引用）。
- `SystemPromptBuilder.build(allSkills)` 每轮重新拼装，技能只注入「名称 + 描述 + 源文件路径」目录段，正文由 `Skill` 工具按需加载（渐进式披露）。
- 工作空间配置 `WorkspaceConfig{workSpaceName, workDir, projectMd}` 落盘 `jarDir/workspace.json`；UI 在 `MainWindow.onNewWorkspace`（新建）与 `WorkspaceListView.doEdit`（修改）两处各写了一遍弹窗。
- 界面文案是原始字段名 `work.dir` / `project.md`，标签变长后现有弹窗宽度不够。

### 顺带修掉的串台缺陷

`projectMd` 现在把配置里的字符串原样交给 `SystemPromptBuilder`，由 `Paths.get(path)` 按**进程当前目录**（= jar 目录）解析。因此两个工作空间都填 `./project.md` 时，读到的是同一个文件——A 空间的项目介绍会出现在 B 空间的系统提示词里。本设计把这类相对路径的解析基准改为**该空间的项目路径**。

## 需求（用户确认结果）

1. 工作空间新增可空「项目级技能路径」，页面提供文件浏览选择；项目技能与内置功能一致，可 `/skill` 寻找，渐进式加载正文。
2. 同名技能：**项目级覆盖内置**。
3. 扫描结构：**支持递归嵌套**（不限一层）。
4. 生效时机：**纯快照，仅新会话生效**（与 `projectMd` 现有语义一致，弹窗提示写明）。
5. 来源体现：提示词仍为**单段** `=== 可用技能 ===`，每条标 `[项目]` / `[内置]`，段末给项目技能目录；`/skills` 与 `/` 补全同样带标注。
6. 提示词隔离：切换会话/工作空间时技能目录与项目介绍随之切换，**不得跨空间污染**。
7. 文案：`work.dir` → 「项目路径」，`project.md` → 「项目主说明文件」，新增「项目级技能路径」；弹窗按情况加宽。
8. JSON 键名 `workSpaceName / workDir / projectMd` **不改**——理由只是键名与字段名一致是本仓库既有约定、改名无功能收益；不是为兼容老配置文件（老文件与老会话都不做兼容处理）。

## 方案

**总原则：不写任何向后兼容代码**——不迁移旧 `workspace.json`、不为旧配置文件缺失字段设计兜底分支、不为改配置前的旧会话保留任何状态或访问权限。旧数据与旧会话一律按"重配/新建即可"处理。

### 1. 配置与路径解析

`WorkspaceConfig` 新增字段：

```java
public String projectSkillsDir;   // JSON 键 projectSkillsDir，可空/null；Gson 反射填充
```

构造器直接改成 4 参（**不留 3 参重载**）：`WorkspaceManager` 默认项生成、`add` 两处调用点与相关测试同步跟改。

新增 `core/config/WorkspacePaths.java`（纯函数，无状态）：

```java
/** 基准目录下的绝对化：空白→null；绝对→normalize；相对→按 baseDir（绝对）拼接 */
public static String resolve(String baseDirAbs, String path);
/** 项目主说明文件绝对路径：配置为空 → <workDir>/project.md */
public static String projectMd(WorkspaceConfig w);
/** 项目级技能目录绝对路径：未配置或目录不存在 → null */
public static String projectSkillsDir(WorkspaceConfig w);
```

解析基准的两层约定（务必按此实现，否则又串台）：

- `workDir` 本身仍按**进程当前目录（jar 目录）**解析——保持现状，`Workspace` 内部就是这么做的；
- `projectMd` / `projectSkillsDir` 的相对路径按**该空间解析后的 workDir 绝对路径**解析。

### 2. 扫描：SkillManager 增加递归模式

保留现有 `scan()`（内置目录，一层，行为不变）。新增静态入口：

```java
/** 递归扫描结果：技能列表 + 面向用户的告警（null=无告警；目录缺失/不可读/数量截断均走此通道，不抛异常） */
public static class ScanResult {
    public final List<Skill> skills;
    public final String warning;
}
// 递归收集目录树中所有 SKILL.md（技能名取父目录名）与 *.skill.md；
// 深度超过 maxDepth 或已收集数达到 maxCount 即终止遍历并在 warning 中说明
public static ScanResult scanTree(Path root, int maxDepth, int maxCount);
```

- 用 JDK8 `Files.walkFileTree` + `SimpleFileVisitor`：`visitFile` 命中即解析（visitor 回调自带 `depth` 参数，无需自己数层）；`preVisitDirectory` 按名字跳过；`visitFile` 返回 `TERMINATE` 触顶即停；
- 跳过目录名：`.git` `.svn` `.idea` `.vscode` `node_modules` `target` `build` `dist` `out` `bin` `obj` `session` `.session`；
- 上限：`maxDepth=6`、`maxCount=200`。技能名取 frontmatter `name`，缺失回退父目录名（与 `scan()` 一致）；解析失败沿用 `parse()` 现有降级路径；
- 目录不存在 / 无权限 / IO 异常 → 已收集部分照常返回，`ScanResult.warning` 填对应文案（数量截断也走同一字段）；`warning` 为 null 表示一切正常。

实例方法 `SkillManager.parse` 已包可见，直接复用；来源标注由调用方（`SkillSet`）负责，扫描本身不关心来源。

### 3. 合并：新增 core/skills/SkillSet.java

```java
/** 技能合并器：内置列表固定 + 按目录实扫项目技能，产出会话级不可变快照 */
public class SkillSet {
    public SkillSet(List<Skill> globals);   // 内置列表在构造时存入（private final，不对外暴露 getter）
    public static final int MAX_PROJECT_SKILLS = 200;
    public static final int MAX_SCAN_DEPTH = 6;
    /** projectDir 为 null/空 → 仅内置（等价现状，warning 恒为 null）；
        否则项目技能在前、同名顶掉内置；扫描异常/截断通过 warning 回传（不抛异常） */
    public Result resolve(String projectDir);
    /** 合并结果：不可变快照 + 面向用户的告警文案（可空） */
    public static class Result {
        public final List<Skill> skills;
        public final String warning;
    }
}
```

`SessionManager` 建会话时 `Result r = skillSet.resolve(dir)`，`r.warning != null` → `notifyError(r.warning)`（会话照常创建）。

- 去重键 = `name.toLowerCase(Locale.ROOT)`（与 `SkillTool` 现有的 `equalsIgnoreCase` 匹配口径一致）；
- 输出顺序：项目技能在前（按名排序），其后内置（按名排序）；结果 `Collections.unmodifiableList`；
- **不做缓存**：`resolve` 每次实扫。调用时机只有「创建会话」和「恢复会话」，不在每轮请求路径上，IO 可接受；少一层失效逻辑，少一类 bug（`MAX_PROJECT_SKILLS` 限制扫描规模）；
  > 实施修正：见文末「实施偏差」第 1 条——`SkillSet` 层仍无缓存，但扫描结果由 `SessionManager` 按空间缓存（补全弹层每次按键会取列表，实扫会卡 FX 线程）。
- `Skill` 新增 `public final String source`（常量 `Skill.SOURCE_PROJECT="project"` / `Skill.SOURCE_GLOBAL="global"`），**构造器改为 5 参、不留 4 参版本**（`SkillManager.parse` 增传来源参数，测试里 4 参 `new Skill(...)` 调用点全部跟改）；`hint()` 前缀 `[项目]` / `[内置]`，`CommandDispatcher`、`SlashSuggester`、提示词三处自动共用该标注。

### 4. 会话级快照与隔离（核心）

`SessionManager` 改动：

- 字段 `List<Skill> allSkills` → `final SkillSet skillSet`（构造入参仍是内置 `List<Skill>`，内部包一层 `SkillSet`，见第 8 节）；
- **不新增 `WorkspaceCtx` 字段**：技能目录与 `projectMd` 一律每次从 `workspaces.get(name)`（`WorkspaceManager` 内存态，`update` 已同步）现取现解析，与 `projectMdPath` 同一数据来源，避免两处状态漂移；
  > 实施修正：见文末「实施偏差」第 1、3 条——解析入口不变，但结果按空间名缓存在 `SessionManager.skillCache`，由 `updateWorkspace` / `renameWorkspace` / `deleteWorkspace` 三处失效；恢复会话时同空间共享一份快照。
- 新增私有方法：

```java
/** 该空间当次配置解析出的技能快照（项目级覆盖内置；未配置目录 → 仅内置）；
    返回 Result 以便 createSession 把扫描告警转 notifyError */
private SkillSet.Result skillsOf(String workspaceName) {
    return skillSet.resolve(projectSkillsDirOf(workspaceName));
}
/** 相对路径按该空间 workDir 解析后的绝对路径；未配置/空 → null */
private String projectSkillsDirOf(String workspaceName) {
    return WorkspacePaths.projectSkillsDir(workspaces.get(workspaceName));
}
/** 取代现有 projectMdPath：空配置回落 <workDir>/project.md，恒为绝对路径 */
private String projectMdOf(String workspaceName) {
    return WorkspacePaths.projectMd(workspaces.get(workspaceName));
}
```

- `createSession` / `restoreSessions`：先算一次 `snap`，同一份引用同时用于
  `new SystemPromptBuilder(mdAbs, workDir, tmpDir, placeholder, projectSkillsAbs)`、
  `TokenCounter.estimate(...build(snap))`、`loop.setAllSkills(snap)`；
  快照不可变且每会话独享 ⇒ 切空间/切会话/后台并发**结构上不可能互相污染**；
- 新增 `public List<Skill> currentSkills()`：`currentSession != null` 时返回其 `loop.allSkills()`（激活会话的快照），否则按当前空间实算——补全弹层与 `/skills` 的数据源，保证「没有会话时也对应当前项目」；
- `updateWorkspace(name, workDir, projectMd, projectSkillsDir)` 与 `addWorkspace(...)` 新增第 4 参：写 `WorkspaceConfig` 落盘 + `ctx.workspace.setWorkDir`（现状）+ 更新读取白名单（第 6 节，替换语义）。**已存活会话不刷新**（技能快照与提示词在建会话时定），弹窗提示写明「对新会话生效」，不为旧会话做额外兼容；
- `projectMdPath(workspaceName)` 改为返回 `WorkspacePaths.projectMd(cfg)` 的绝对路径（原 `return "./project.md"` 兜底随之消失）。

### 5. 系统提示词（SystemPromptBuilder）

技能段落格式调整。`SystemPromptBuilder` 构造器扩为 5 参：`(projectMdPath, workDir, tmpDir, emptyOutputPlaceholder, projectSkillsDir)`，文件内既有的 1/2/3 参便捷重载照旧（末参传 null）——这是延续本仓库既有风格，不是新写的兼容分支：

```
=== 可用技能 ===
当任务与某技能描述匹配时，调用 Skill 工具加载……（现有引导文字不变）
技能源文件可能在工作路径之外，如需读取技能参考文档，可直接用 Read 工具读取其绝对路径：
- [项目] my-deploy — 部署本项目到测试环境（D:\proj\skills\my-deploy\SKILL.md）
- [内置] brainstorming — You MUST use this before any creative work…（…\run\skills\brainstorming\SKILL.md）

项目级技能目录: D:\proj\skills（[项目] 技能随当前工作空间变化，同名时优先于 [内置]）
```

- 未配置项目路径时：不输出 `[项目]` 条目，也不输出末行目录说明（与现状字节级一致的段落，仅每条多 `[内置]` 前缀）；
- 内置段落文案补一句「`[项目]` 来自当前工作空间配置的技能目录」，帮助模型理解两类来源；
- `projectMd` 读的是绝对路径 ⇒ 项目介绍段随会话所属空间切换，且不再共享同一文件。

### 6. 文件工具放行

技能正文与 `references/*.md` 需能被 `Read`。做法**不改七个工具的构造签名**：

- `Workspace` 新增 `volatile List<String> extraAllowedDirs`（默认空列表）+ getter + `setExtraAllowedDirs(List<String>)`（**替换语义**，与 `setWorkDir` 同为热更新，不做旧目录保留）；`buildCtx` 与 `updateWorkspace` 都按当次配置写入；
- 不做「改配置后旧会话仍可访问旧技能目录」的兼容：旧会话保持旧技能快照，其参考文件是否仍可读取不作为设计目标（简化实现，去掉追加去重逻辑）；
- `PathsGuard` 守卫入口改为 `errorIfOutside(Workspace ws, String skillsDir, String tmpDir, Path p)`：按 `ws.workDir()` → `ws.extraAllowedDirs()` → `skillsDir` → `tmpDir` 逐项放行；**顺带删除 2 参/3 参便捷重载**（生产代码里无人调用，`PathsGuardTest` 两行跟改），避免再堆一层"多签名并存"；`resolve` / `inside` 保留；
- 工具内调用点由 `workspace.workDir()` 改为 `workspace`（Read/Write/Edit/Glob/Grep/BrowserScreenshot 各一行）；`ReadTool` 的「读逃逸」判断分支同步加上 extra 检查，保证已放行的技能目录不触发授权确认；
- `GlobTool` 现有的「技能目录也作为搜索根」逻辑本次不扩到项目技能目录（需要时显式传路径即可，越界守卫已放行）——避免额外改动。

### 7. 界面

`MainWindow.onNewWorkspace` 与 `WorkspaceListView.doEdit` 两份重复弹窗**抽取为** `gui/dialog/WorkspaceFormDialog.java`：

```java
/** 工作空间表单：名称 + 项目路径 + 项目主说明文件 + 项目级技能路径，含名称合法性预校验 */
public class WorkspaceFormDialog extends Dialog<WorkspaceConfig> {
    public WorkspaceFormDialog(String title, String header, WorkspaceConfig initial /* null=新建 */)
}
```

> 实施修正：见文末「实施偏差」第 4 条——实际构造签名为 4 参，冲突名称集合由调用方传入（新建给全量、修改排除自身）。

理由：两处原本逐行重复（校验、两个浏览按钮、红字提示），再加第三个路径行会继续放大重复；抽取后新字段只写一遍，行为一致。

- 行标签：`名称:` / `项目路径:` / `项目主说明文件:` / `项目级技能路径:`；
- 后三项 `promptText`：「（可空，默认 <项目路径>\project.md）」/「（可空，未配置则仅使用内置技能）」；
- 浏览：项目路径与项目级技能路径用 `DirectoryChooser`，项目主说明文件用 `FileChooser`（Markdown 过滤器，同现状）；
- 名称校验逻辑原样迁入（`WorkspaceManager.isValidName` + OK 禁用绑定 + 行内红字 + ACTION 事件兜底）；新建场景 existing 含全部名称，修改场景排除自身；
- 宽度：`getDialogPane().setMinWidth(560)`（三行标签最长 7 个汉字，现约 450 会把输入框挤到不可读；560 由内容测量定，实施时以实际截图为准微调）；
- `WorkspaceListView.doEdit` 头部文案：「工作空间「X」（重命名会同步迁移会话目录；项目路径 / 项目主说明文件 / 项目级技能路径 的修改对新会话生效）」。

### 8. 其他接线点

| 位置 | 改动 |
|---|---|
| `Main` | 不变：仍把内置技能扫描结果 `List<Skill>` 交给 `SessionManager` |
| `SessionManager` 构造 | **签名不变**（收内置 `List<Skill>`），内部 `this.skillSet = new SkillSet(allSkills)` —— 不新增入口、不改 15 处测试构造 |
| `addWorkspace` / `updateWorkspace` | 签名扩一个 `projectSkillsDir` 参数，**不留旧 3 参版本**；GUI 两处调用点与 `SessionManagerTest` 一处跟改 |
| `InputView` | 两处 `manager.skills()` → `manager.currentSkills()`（`/` 与 `/skill` 补全跟随当前会话） |
| `CommandDispatcher` | 不再持有全局列表：`skillsText/dispatchSkill` 用 `h.loop.allSkills()`；构造器去掉 `List<Skill>` 参数；`/skills` 空提示文案补「（工作空间 → 项目级技能路径）」 |
| `SessionManager.skills()` | 删除（UI 调用点改 `currentSkills()` 后即无调用者，不留多余入口） |
| `SubAgentLoop` / `TaskTool` | 无需改动：子 agent 提示词继承父 `loop.buildSystemPrompt()`，快照天然带上项目技能；`Skill` 工具在子 agent 仍禁用 |

## 边界与错误处理

| 情况 | 行为 |
|---|---|
| 路径为空 | 无项目技能：提示词只有 `[内置]` 条目、无目录末行（与今天看到的效果相同） |
| 路径不存在/不是目录/无权限 | 告警 + 空项目列表，会话正常创建 |
| 路径填成内置 `skills.dir` | 全部条目变 `[项目]`（同目录解析），无重复条目，不报错 |
| 路径在工作目录内（如 `d:/proj/skills`） | 已满足现有守卫，白名单叠加无副作用 |
| 目录里塞了整个仓库 | 深度 6 / 数量 200 截断 + 告警 |
| 同名（忽略大小写） | 保留项目级那条，内置那条不进快照 |
| 改项目技能路径 | 该空间已存在会话保持旧技能快照、白名单立即替换为新目录（不做旧目录保留），新会话用新配置（弹窗提示已写明） |
| 切工作空间/切会话 | `currentSkills()` 与每会话快照分别生效，提示词与补全同步切换 |
| 扫描耗时 | 只在创建/恢复会话时发生，规模受 200 上限约束，FX 线程上毫秒~几十毫秒量级 |

## 不做的事（YAGNI）

- 不做多技能目录列表（一个空间一条路径）；
- 不做运行时「立即刷新当前会话技能」的按钮/命令（改配置新建会话即可）；
- 不做项目技能开关配置项、不做 `config.properties` 新键（配置归属工作空间）；
- 不改 `workspace.json` 现有 JSON 键名；
- 不做扫描结果缓存与文件监听（每次建会话实扫，规模有上限）。

## 实施偏差

（Task 6 修复轮 1 与 Task 7 实施时与设计的出入；代码与文档以实施为准。）

- **空间级快照缓存（核心偏差）**：设计 §3「不做缓存：`resolve` 每次实扫，调用时机只有创建/恢复会话」在调用层被部分推翻——`SkillSet.resolve` 本身仍每次实扫、无缓存，但 `SessionManager.skillsOf` 新增按空间缓存 `skillCache: Map<String, SkillSet.Result>`，`updateWorkspace` / `renameWorkspace` / `deleteWorkspace` 时失效（防同名空间重建误命中旧结果），配置变更后首次调用重扫一次。原因：`currentSkills()` 无激活会话时按当前空间实算，补全弹层（`@`/`/`）每次按键都触发整树扫描——超出设计预期的调用路径；修复轮 1 将这条 Minor 提升为必修。§3「不做缓存」与 YAGNI「不做扫描结果缓存」相应修正为「SkillSet 层无缓存，扫描结果由 SessionManager 按空间缓存、配置变更失效」。
- **边界表「扫描耗时」行不准确**：除创建/恢复会话外，无会话时的补全 / `/skills` 读取也会触发扫描——修复轮后为缓存失效后的首次调用扫一次，此后命中缓存，不逐键扫描。
- **restoreSessions 共享快照**：Task 6 初始实现为循环内每会话各算一次快照（同一目录重复扫描，且注释误称「恢复会话保持落盘时的技能上下文」——技能清单并不落盘，恢复时按当前配置实扫）；修复轮 1 改为循环外每空间一次扫描、全部恢复会话共享同一不可变快照——与 §4「先算一次 snap」意图一致（快照不可变，共享仍无串台风险），注释更正为「恢复会话保持当前配置下的技能上下文」。
- **WorkspaceFormDialog 构造签名**：实际为 4 参 `(String title, String header, WorkspaceConfig initial, List<String> existingNames)`（设计 §7 写 3 参）——冲突名称集合由调用方传入（新建=全部现有名称，修改=排除自身），弹窗内部不再自行枚举；三个路径行的 `promptText` 措辞与设计样例不同（实际为「项目路径（留空 = 软件所在目录）」「项目主说明文件（留空 = 项目路径下 project.md）」「项目级技能路径（留空 = 仅使用内置技能）」）。
- **计划文档顺带修正**：Task 5 的 sibling 用例路径笔误（`projSkills.resolve("elsewhere")` → `projSkills.getParent().resolve("elsewhere")`）已直接在计划文档修正，实施代码本就按正确路径实现。
- **新增回归用例两条**（`SessionManagerTest`）：`currentSkills_noSession_invalidatedByUpdateWorkspace`（无会话补全缓存失效、配置变更后立即反映新目录）、`restoreSessions_shareSnapshotPerWorkspace`（恢复会话共享快照，技能清单正确）。
- **界面文案与宽度（验收后按用户要求两轮调整，取代上文第 4 条里的 promptText 样例）**：名称与项目路径**必填**，项目主说明文件与项目级技能路径**可选**——四个输入框空时的 `promptText` 统一为「必填」/「可选」；弹窗头部去掉括号说明（原「三个路径均可留空…」「重命名会同步迁移会话目录；…对新会话生效」），只留「新建工作空间」/「工作空间「X」」；输入框 `prefColumnCount` = 25（JavaFX 默认 12），`MIN_WIDTH` = 620（原 560，随输入框加宽后再收缩定稿）。`FileChooser` 的对话框标题不再复用 `promptText`（否则会变成「可选」），写死为「选择项目主说明文件」。
- **两个路径必须是「已存在的文件夹」，校验落在 core 层**：新增 `WorkspacePaths.isExistingDir(raw, baseDir)`（相对写法按 baseDir 解析后 `Files.isDirectory`；非法字符不抛、判为不可用），`WorkspaceManager.add` 与 `update`（后者由 `void` 改 `boolean`）经 `pathsUsable` 统一拒绝——项目路径空白/不存在/指向文件、技能路径填了但不是文件夹，一律返回 false 且**原配置不变、不落盘**；`SessionManager.updateWorkspace` 同步返回 `boolean`（false 时无副作用：不动 `skillCache`、不热更新 `Workspace.workDir`）。技能路径仍为**可选**（留空合法）。读取侧保留兜底：已落盘配置被手改成无效路径时 `WorkspacePaths.workDirAbs` 按软件所在目录解析（对不可信外部输入的容错，非兼容层）。
- **界面反馈分工**：必填类问题（名称非法/重名、项目路径空白）→ 「确定」按钮置灰 + 行内红字兜底；「填了但不是文件夹」类问题**不置灰**（否则用户不知原因），点「确定」时按字段弹出 ERROR 框（「项目路径必须是已存在的文件夹…」/「项目级技能路径必须…」），点框上「确定」回到本表单继续修改（`eventFilter` consume，表单不关闭）。`WorkspaceListView.doEdit` 在**改名之前**先校验两个路径，避免出现「改名成功而更新被拒」的半改状态。
