# 消息区文本选择与复制（设计文档）

日期：2026-08-14 · 状态：已实施

## 背景与根因

消息区正文无法鼠标拖动选择文本、无法直接复制。根因（已确证）：

- 消息全部用 `Label` / `TextFlow` / `Text` 节点渲染（ChatView + BlockNodeFactory），
  而 JavaFX 平台本身不支持这些节点拖选文本（`Label` 无选中能力，`TextFlow` 从未内置 selection），
  代码因此在 [ChatView.java:165](../specs/../../src/main/java/com/minion/gui/chat/ChatView.java#L165) 以
  「右键菜单复制 + 双击复制全文」作为替代途径——这是设计取舍，不是回归。
- 本机 Zulu 8u502 的 jfxrt.jar 实测：`TextFlow.hitTest`/`Text.hitTest` 公开 API 不存在
  （自实现 TextFlow 选中只能走 `com.sun.javafx` 内部 API，`impl_hitTestChar`/`impl_selection*`）。

## 方案（用户已确认）

**消息文本改渲染为只读 `TextArea`（纯文本）**，依赖 TextArea 原生能力：
鼠标拖选高亮、Ctrl+C、双击选词、右键菜单（复制/全选）——零自研选中逻辑，最稳定。

代价（已接受）：markdown 富文本样式（粗体/行内代码着色/表格边框）不再渲染，
正文退化为纯文本展示。通过现有 MarkdownRenderer 把 markdown 展平为**可读纯文本**
（去掉 `**`、`` ` `` 等语法记号），而非直接展示源码。

## 改动点

### 1. MarkdownRenderer 新增纯函数 `toPlainText(String md)`（可单测）

复用现有 `parse()`，块 → 纯文本展平规则：

| 块类型 | 展平规则 |
|---|---|
| PARAGRAPH | spans 文本直接拼接（span.text 已含软换行） |
| HEADING | text |
| CODE | text（保留原内容与换行，不加围栏） |
| LIST | 每项 `"• "` 前缀 + 换行 |
| QUOTE | text |
| TABLE | 每行单元格 `" | "` 连接 + 换行 |
| RULE | 忽略 |

块之间空行（`\n\n`）分隔，整体 trim。行内样式（bold/italic/code/strike）只取文本，语法记号消失。

### 2. 新组件 `MessageTextArea`（gui/chat 包内）

`TextArea` 子类，解决两个平台问题：

- **外观**：只读、`setWrapText(true)`、样式类 `msg-textarea`（CSS 见第 3 点）——
  透明内部（.content/.scroll-pane/.viewport）、去焦点环、选中高亮色、LCD 字型平滑。
- **自动高度（关键）**：TextArea 的 prefHeight 由 `prefRowCount`（默认 10 行）决定，
  不随内容变化。重写
  `computePrefHeight(width, top, right, bottom, left)`：
  用内部 `Text` 测量器（同字体、wrap 宽度 = width − 水平 padding），
  返回 文本高 + 垂直 padding + 小余量。宽高完全融入 VBox 布局，
  无需手动 listener，窗口缩放自动重排。
- 右键菜单/双击选词/Ctrl+C 全用 TextArea 原生行为，不挂任何自定义鼠标处理器。

### 3. ChatView 消息渲染改造

| 事件 | 现状 | 改为 |
|---|---|---|
| USER_MESSAGE | Label(msg-user) + makeCopyable | MessageTextArea(msg-user + msg-textarea)，raw text |
| USER_SUPPLEMENT | Label(msg-user) | tag Label + MessageTextArea |
| THINKING | Label 流式重建 | MessageTextArea 流式**就地 setText** |
| CONTENT | VBox + BlockNodeFactory 富文本块，流式重建 | MessageTextArea 流式就地 setText(toPlainText(md)) |
| 系统行（TOOL 卡片/TOOL_RESULT/ERROR/WARNING/STATS/SYSTEM/子任务） | Label/card + makeCopyable | **不变**（辅助信息行，保留右键+双击复制） |

- `makeCopyable` 不再挂在消息 TextArea 上（原生能力取代；且原双击复制与
  TextArea 原生双击选词冲突，必须移除）。
- 流式哨兵 `STREAMING_MARK` 保留：同一流式流（thinking 或 assistant）**就地更新文本不重建节点**
  （不丢焦点/选中态）；流式类型切换（thinking → content）仍按现有语义替换节点。
- `BlockNodeFactory` 富文本渲染路径保留（不被删除），仅 ChatView 不再调用；
  `makeCopyable` 保留给系统行。

### 4. theme.css

```css
/* 消息只读 TextArea 公共样式 */
.msg-textarea {
    -fx-highlight-fill: #3b6fe0; -fx-highlight-text-fill: #ffffff;
    -fx-focus-color: transparent; -fx-faint-focus-color: transparent;
    -fx-font-smoothing-type: lcd;
}
.msg-textarea .content { -fx-background-color: transparent; -fx-padding: 0; }
.msg-textarea .scroll-pane { -fx-background-color: transparent; }
.msg-textarea .scroll-pane > .viewport { -fx-background-color: transparent; }
```

`msg-user` / `msg-assistant` / `msg-thinking` 现有背景/圆角/padding 规则对 TextArea 同样适用，
与 `.msg-textarea` 叠加即可。

## 边界与取舍

- 富文本样式不再渲染（用户已确认接受）。
- 表格以 `a | b` 纯文本行展示；列表以 `• ` 前缀行展示。
- 流式期间就地更新：不重建节点、不打断用户操作。

## 终稿调整（目验后用户指示）：去块状容器，改原始流式输出行

目验后用户要求"最原始的输入输出显示，纯文字，有颜色，不要一块一块的东西"，
并指定四类标签。终稿实施：

- **所有消息行改为「彩色标签 + 纯文字正文」HBox，无背景块**（气泡/卡片全部移除）。
  标签与正文同类别色，标签加粗：`【输入】`蓝 / `【思考】`灰 / `【工具】`黄 / `【回复】`白；
  错误红 `【系统】`，警告黄 `【系统】`，统计/命令结果灰 `【系统】`，子任务归 `【工具】`。
- 工具卡片（含 ask_user 提问）与错误横幅等块状元素一并改为标签+纯文字行；
  `makeCopyable`（右键+双击复制）删除——所有消息行已是 TextArea，原生复制替代。
- 流式语义调整：思考流与回复流**各自成行、就地更新，不再互相替换**
  （原「内容到达时替换思考块」会吞掉【思考】行，与新分类展示意图冲突）。
- 新增 CSS 类 `.log-tag` / `.log-input` / `.log-think` / `.log-tool` / `.log-reply` /
  `.log-error` / `.log-warn` / `.log-sys`；旧 `.msg-*` / `.card` 样式保留
  （BlockNodeFactory 保留、SettingsDialog 仍用）。
- 空会话提示 hint 改 `.log-sys` 灰字。

## 终稿调整二（目验后用户指示）：控制台式整体文本流

目验后用户要求"纯文字显示，和控制台一样……所有的为一个整体在输入框里面"——
不要逐条成行，整个会话是一段连续文本：

- **ChatView 改 extends MessageTextArea**：整个会话渲染为**单一 TextArea 的连续文本流**，
  标签（【输入】【思考】【工具】【回复】【系统】）内嵌行首，段间空行分隔，
  像控制台输出；无任何块状容器/逐条行结构。
- **复制**：除局部拖选/Ctrl+C 外，Ctrl+A 全选可一键复制整个会话（单 TextArea 天然支持）。
- **流式**：维护段列表（Seg：文本 + 思考流/回复流标记）；同流事件就地重写末段，
  异流新起一段（互不覆盖）；每次变更全文重建 setText（会话量级下开销可接受）。
- **颜色取舍**：JavaFX 8 单 TextArea 无法局部着色（整体 ↔ 多色不可兼得），
  选定控制台灰白主色 `.log-console`（#d3d7de，含 16px 内边距）；
  删除上一稿的 `.log-*` 多色类。
- 空会话占位文本"输入消息开始新的会话"（只读 TextArea 不显示 promptText）；
  首段消息到达时清掉占位。

## 终稿调整三（目验后用户指示）：铺满正文 + 场景色 + 距输入框 1 行

用户要求：界面铺满整个正文窗口、距输入框 1 行距离、背景 rgb(18,19,20)、
白字为主且不同场景文字颜色有区别：

- **ChatView 恢复 VBox**（`extends VBox`）：每段一个 MessageTextArea，标签内嵌行首，
  段间无缝紧贴（spacing 0，连续控制台输出）；背景 `.panel-dark`（#121314）。
- **铺满**：MainWindow `chatScroll.setFitToHeight(true)`——内容少时 ChatView 拉伸到
  视口高（背景铺满），内容多时保持可滚动（fitToHeight 语义）。
- **距输入框 1 行**：ChatView 底部 padding 12px + 右栏 VBox spacing 8px ≈ 20px（一行行高）。
- **场景色（恢复多色，白字为主）**：`.log-input` 蓝 / `.log-think` 灰 / `.log-tool` 黄 /
  `.log-reply` 白（主文字色）/ `.log-error` 红 / `.log-warn` 黄 / `.log-sys` 灰。
  每段一个 TextArea 一色（JavaFX 8 单 TextArea 不能局部着色，故以段为单位着色，
  视觉仍为连续控制台输出流）。
