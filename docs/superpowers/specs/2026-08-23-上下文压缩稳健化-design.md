# 上下文压缩稳健化 设计文档

日期：2026-08-23
状态：已确认

## 背景与问题

现有压缩逻辑（ContextManager.compress）存在两个风险：

1. **压缩收益不足**：保留区固定为最近 keepRecent（默认 50）条原文。当最近 50 条消息占上下文 token 比例过高（>50%，常见于小窗口模型或长消息历史）时，可压缩的旧内容占比小，压缩后占比下降不明显，压缩意义有限。
2. **单次压缩输入过大导致失败**：把所有待压缩链一次性拼成一个大 batch 调用 LLM。历史很长时输入可达数万 token，易超模型单次处理上限而失败；且现有逻辑"全成或全弃"——失败即原样返回跳过本轮，消息继续追加，后续再触发再失败，最终可能突破窗口导致请求 400。

## 方案

### 一、保留区动态缩小（解决"压不出效果"）

在 compress 计算保留区时，从固定条数改为按 token 占比动态调整：

```
keep = keepRecent（默认 50）
循环：
  从后往前按链累计 token（TokenCounter），计算保留区占比 = 保留区 token / 全部待处理消息 token
  占比 ≤ 50% 或 keep ≤ 12 → 跳出
  否则 keep = keep / 2，重新从后往前累计
```

规则：

- 占比按 **token 估算**（TokenCounter），不按条数。占比分母 = 全部消息 token（含 system、pinned 技能正文——它们同样占用上下文窗口）。
- 保留区以**完整回合链为边界**（沿用 chunkChains），保证 tool_call↔tool 消息配对完整、不切断半轮。
- keep 是本次压缩的**临时参数**，不改写模型配置 keepRecentMessages（配置值保持 50，仅作起点）。
- 下限 12 条：覆盖当前回合及附近少量上下文，避免模型"失忆"。

### 二、分段递归压缩（解决"单次输入过大失败"）

整体压缩失败后，将待压缩链列表按 token 均衡二分，递归处理：

```
compressChains(链列表):
  if 链内消息总数 ≤ 30:            # 最小段
    整体拼批调用 LLM，成功返回摘要，失败返回 null（该段保留原文）
  else:
    整体拼批调用 LLM
    成功 → 返回摘要
    失败 → 按 token 均衡二分（以链为边界）→ 分别递归
          上半段摘要 + 下半段原文 → 再整体调用 LLM 得到合并摘要
```

规则：

- **段切分**：按 token 均衡二分，以链为边界（不切断回合链）。
- **摘要合并**：上半段先出摘要A，再把「摘要A + 下半段原文」作为输入调用 LLM 得到最终摘要——最终仍是**单个 summary 消息**，保持现有消息结构（Message.summary 标记）。合并轮（摘要A+下半段）失败时：若下半段链数 > 最小段，对下半段继续二分递归，摘要A保留；若下半段已是最小段，则降级为「摘要A（标记 summary）+ 下半段原文」作为结果——上半段已被压缩，部分成功仍生效。
- **部分成功自动应用**：某段递归到最小段仍失败时，该段保留原文不压缩；成功段照常出摘要。不再是"全成或全弃"。
- **最小段 30 条**：30 条以内不再递归（单次请求量级小，失败概率低）。
- **调用次数**：正常路径（整体一次成功）零额外调用；最坏情况约 1+2+4=7 次（仅当连续两轮二分都失败），可接受。
- 压缩系统提示词（COMPRESS_SYSTEM）与现有一致，不区分首轮与合并轮。

### 三、附带修正

AgentLoop.java 约 137 行注释"上下文涨至 200%+"表述不准确：实际是请求报错后消息继续追加、显示值虚高，并非真的发出超大请求。改为准确表述。

## 错误处理

- 任何 LLM 调用异常视为该段压缩失败，按上述规则降级（递归 / 保留原文），不抛异常中断会话。
- 返回空摘要视为失败，同前。
- 全部段失败时：等价于现有"失败原样返回"，消息列表不变。

## 测试

- ContextManager 单测：
  - 保留区占比 >50% 时 keep 减半生效（mock 长消息构造占比场景）
  - 下限 12 条不再减半
  - 整体压缩成功：结果与现有行为一致（摘要置前、保留区原文、pinned/system 保留）
  - 整体失败 → 二分成功：两段摘要合并为单个 summary
  - 二分后某段仍失败：成功段摘要 + 失败段原文
  - 最小段 30 条以内失败：整段保留原文
  - 链边界不被切断（tool_call↔tool 配对完整）
- 现有测试全部通过。
