# 工具输出截断与落盘设计

日期：2026-08-23
状态：待审查

## 背景与问题

编码代理的上下文预算有限，工具输出必须受控。对照业界实践，本项目已有基础但存在两个差距：

1. **BashTool 截断策略只有头部**：30k 字符硬截断（`MAX_OUTPUT`），流式读取时超限即丢弃后续。而编译/测试的错误总结（`BUILD FAILURE`、`ERROR:`）恰恰出现在**末尾**，当前策略丢掉的是最有价值的部分；截断后模型也没有任何途径查看被丢弃的内容。
2. **GrepTool 上下文爆炸 bug（实测）**：某机器上单次 Grep 调用上下文从 1% 涨到 400%。根因：
   - `GrepTool` 匹配行内容**完整 append，无长度限制**（`sb.append(...).append(lines.get(i).trim())`）——minified JS、单行 JSON、超长日志行一条匹配可达数百 KB~数 MB，250 条即可打爆上下文；
   - `maxResults` 可被模型参数放大；
   - `AgentLoop` 对 `ToolResult.output` 无字符级兜底（第 469-470 行直接入消息），**工具层是唯一防线**。

## 现状

- `ReadTool`：已支持 `offset`/`limit` 按行号范围读取、`lineNumbers` 行号前缀标注——文件读取层优化**已完成**，本次不动。
- `BashTool`：30k 字符硬截断（从头保留，尾部丢弃）；无落盘。
- `GrepTool`：默认 `maxResults=250` 条硬截断，超限即 `TERMINATE` 提前停止遍历（尾部从未收集）；匹配行无长度限制；无落盘。
- `AgentLoop`：工具返回全量入消息，无兜底。

## 设计目标

1. 修复 Grep 上下文爆炸：**单行内容截断 + 总字符上限双兜底**。
2. BashTool 截断升级为**头尾保留**：头部保留错误上下文、尾部保留错误总结，中间一行提示。
3. **超限输出落盘**：完整结果保存到工作区 `.minion/tmp/`，返回中告知路径，模型可用 `Read` 按需查看。
4. 约束：**不超限不落盘**——正常输出零磁盘痕迹，行为与现状一致。

## 方案细节

### 落盘位置与清理

- 目录：`<workDir>/.minion/tmp/`（与 `.minion/sessions/` 平级；在 PathsGuard 白名单内，模型可直接 `Read`）。
- 文件名：`bash-<时间戳>-<序号>.log`、`grep-<时间戳>-<序号>.txt`（时间戳防冲突）。
- 清理：应用启动装配阶段执行一次，**仅删除修改时间超过 3 天的文件**（最近 3 天保留，供回溯查看）。不超限的输出不产生文件，目录平时为空。

### BashTool

- 收集阶段：reader 线程每行同时（a）`appendTruncated` 进内存 StringBuilder——上限由 30k 改为**头部 18k**；（b）追加写入落盘文件（全量）；（c）累计总字符数。
- 返回阶段（在 `reader.join` 之后）：
  - 总字符 ≤ 30k：删除落盘文件，返回全量（现状行为不变）。
  - 总字符 > 30k：从落盘文件**末尾**读最多 12k 字符作为尾部（UTF-8 多字节边界：从 `len - 12k * 1.2` 字节处 seek 读入，截取最后 12k 字符，首字符若非法则丢弃），返回 = 头部 18k + 提示行 + 尾部 12k。
- 提示行：`... 输出已截断（共 N 字符，完整输出已保存到 <相对路径>，可用 Read 查看）...`
- 返回路径格式：cwd 内输出相对路径（模型可直接 Read），与 GrepTool 现有约定一致。
- 超时路径：落盘文件同样按上述规则处理（截断即落盘）。

### GrepTool

- **单行截断**（核心修复）：每条结果行内容截断为 200 字符（超长加 `...` 后缀）。落盘内容与显示内容同格式，保证文件大小可控。
- 收集阶段：遍历**不提前终止**，所有匹配行写入落盘文件（全量），同时内存保留显示用结果（前 250 条 + 30k 字符双上限）。
- 返回阶段：
  - 匹配条数 ≤ 250 且总字符 ≤ 30k：删除落盘文件，直接返回（现状行为不变）。
  - 超出任一上限：保留落盘文件，返回前 250 条（字符满 30k 即停），末尾提示：`... 共 N 条，完整结果已保存到 <相对路径>，可用 Read 查看`。
- `maxResults` 参数语义不变（显示层条数上限，默认 250）。
- 二进制约 束：现有 `TextFiles.readAllLines` 异常忽略逻辑保留。

### 错误处理

- 落盘文件写入失败：降级为纯内存截断（现有行为），不阻断工具执行；`System.err` 记录。
- 尾部读取失败：降级为仅返回头部 + 提示（无尾部）。
- 落盘文件被删除/不可读：`Read` 会自然报"文件不存在"，模型可重新执行命令。

### 测试

- BashTool：>30k 输出 → 头部 18k + 尾部 12k + 提示含路径；≤30k 输出 → 无落盘文件；输出为空/少行边界。
- GrepTool：>250 条 → 返回 250 条 + 提示；超长单行（如 1MB 单行文件）→ 每条 ≤ 200 字符，上下文总量可控；≤ 上限 → 无落盘文件。
- 清理：模拟 3 天内/外文件，验证只删超期的。
- 工具调用集成：落盘路径可被 `ReadTool` 读取。
