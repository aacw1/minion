# 报错信息点击复制：MCP 失败原因 + 运行指示器错误详情

日期：2026-09-17
状态：待实施

## 背景与问题

用户报两处错误信息显示不全、且无法完整复制（诊断/反馈需要全文）：

1. **MCP 初始化报错显示不全**：设置窗 → MCP 页列表项显示「失败: `shorten(failReason)`」，
   `shorten()` 只取首行并截断到 40 字符（`SettingsDialog.java:596`），
   完整失败原因（多行 stderr / 异常堆栈）用户看不到也拿不到。
2. **访问大模型报错的 JSON 显示不全**：左下角运行指示器重试态文案形如
   「正在加载中...(500服务报错，重试第2次{...json...})」，
   `RunningIndicator.bodyPart()` 把响应体截断到 `BODY_MAX_CHARS = 200`（`RunningIndicator.java:29`），
   且 Label 文字不可选中，完整 JSON（服务端 400/429/500 响应体）只能靠用户手抄。

两处均为「诊断信息源头完整、展示层截断」——展示层截断保留（防爆宽），另给点击复制全文的出口。

## 方案选择（用户确认）

| 候选 | 结论 |
|------|------|
| 取消截断、直接全文展示 | 否决：单行爆宽（指示器悬浮于左下角、MCP 列表项为固定高度行），视觉噪声且不可控 |
| 右键菜单复制 / 独立复制按钮 | 否决：多一步操作 / 占位；用户明确「点击文字可复制」 |
| **点击文字复制完整原文 + 短暂「已复制 ✓」反馈** | **采纳**：零新增组件，交互一步到位 |

用户澄清结论：

- 需求 2 的位置 = **左下角运行指示器**（非聊天区【系统】行，聊天区不动）。
- 复制内容 = **完整原始错误信息**（不含「重试第N次」等前缀）：指示器复制完整 `body` 原文，MCP 复制完整 `failReason` 原文。
- 反馈 = 点击后原文字短暂变「已复制 ✓」，约 1.5 秒后恢复。

## 设计

### 需求 1：MCP 列表「失败: xxx」点击复制

- **位置**：`SettingsDialog.mcpPane` 列表 cell 中 `meta` Label（仅 `FAILED` 态显示失败原因）。
- **可点条件**：`item.state == FAILED` 且 `failReason` trim 后非空。满足时 `Cursor.HAND`，否则默认光标。
- **点击行为**：完整 `failReason` 原文（含换行）写入系统剪贴板 → `meta` 文字变「已复制 ✓」→
  1.5 秒后（`PauseTransition`）恢复为原「失败: `shorten(failReason)`」文本。
- **cell 复用安全**：`updateItem` 每次重建节点（现有实现即如此），反馈计时器停止/重建自然随节点废弃；
  计时器到期对已脱离场景图的旧 Label `setText` 无可见影响；反馈窗口内列表 `refresh()` 重建 cell → 提示消失、恢复常规显示（可接受）。
- **纯逻辑抽函数**（无 JavaFX，供单测）：

  ```java
  /** 失败原因可复制文本：null/空白 → null（不可点）；否则返回原文（不截断） */
  static String copyableFailReason(McpServer s)
  ```

### 需求 2：运行指示器重试文案点击复制

- **位置**：整个指示器（`RunningIndicator` HBox；齿轮 + 文字），
  **仅当 `retryProgress != null` 且 `body` 非空**时可点（重试态且有错误详情），此时 `Cursor.HAND`。
- **点击行为**：`retryProgress.body` 完整原文写入系统剪贴板 → 文字变「已复制 ✓」→
  1.5 秒后**按当前状态重绘**（复用统一重绘口径：重试态 → `retryText(retryProgress, retryBase)`；
  压缩态 → `COMPRESSING_TEXT`；否则轮换文案）。
- **竞态处理**：
  - 反馈窗口内新 `setRetryProgress` / `setCompressing` 到来 → 停反馈计时、正常重绘（提示让位于实时状态，不卡「已复制」）。
  - `setVisible(false)`（隐藏/suspend）→ 停反馈计时（动画规约：隐藏前停全部计时器，防引用泄漏）；恢复可见时按状态重绘。
  - 非重试态点击 → 无动作。
- **纯逻辑抽函数**（无 JavaFX，供单测）：

  ```java
  /** 可复制错误原文：body 为 null/空 → null（不可点）；否则返回原文（不截断） */
  static String copyText(RetryProgress p)
  ```

## 影响面

| 项 | 变化 |
|----|------|
| `SettingsDialog` MCP 列表项 | 失败文字变可点（手型 + 点击复制 + 短暂提示）；`shorten` 展示逻辑不变 |
| `RunningIndicator` | 重试态整条可点；文案重绘逻辑抽 `renderText()` 统一口径；新增 `PauseTransition` 反馈计时器（隐藏时停） |
| 聊天区【系统】错误行 | **不变**（用户确认不做） |
| 剪贴板 | 系统剪贴板 `ClipboardContent.putString`，与 `InputView` 粘贴/`WorkspaceListView` 拖拽同机制 |
| 核心错误载体（`LlmException` / `RetryProgress` / `McpServer.failReason`） | 不变：`body` / `failReason` 本就是完整原文，无需扩接口 |
| 主题 CSS | 不变（沿用现有样式类；「已复制 ✓」沿用原 Label 样式类） |

## 测试计划（TDD）

纯逻辑单测（JavaFX 组件本体沿用现状不单测，交互手动验证）：

1. `RunningIndicatorTest.copyText_returnsFullBody`：HTTP 错误带 body → 返回完整原文（超 200 字符不截断）。
2. `RunningIndicatorTest.copyText_nullForNoBody`：`RetryProgress.none()` / body 为 null / 空串 → null。
3. `RunningIndicatorTest.copyText_networkDetail`：网络类（`ofNetwork`）→ 返回异常消息原文。
4. `SettingsDialogTest.copyableFailReason_*`：FAILED + 多行原文 → 原样返回；null / 空白 → null。
5. `mvn test` 全量通过。

手动验证（构建后运行 jar）：

- MCP 页：失败项手型光标；点击 → 粘贴得完整多行失败原因；文字短暂「已复制 ✓」后恢复。
- 指示器：构造 500/429 错误进入重试态；点击 → 粘贴得完整 JSON；文字短暂「已复制 ✓」后恢复重试文案；
  切走/隐藏再回来不残留提示；非重试态点击无反应。

## 不做的事（YAGNI）

- 不做右键菜单、复制按钮、tooltip（手型光标 + 点击反馈已足够可发现）。
- 不改聊天区【系统】错误行的复制/截断行为。
- 不取消/放宽 `shorten`（40 字符）与 `BODY_MAX_CHARS`（200 字符）的展示截断。
- 不引入全局 toast 组件。
