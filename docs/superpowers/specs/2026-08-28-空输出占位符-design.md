# 工具空输出占位符 设计文档

日期：2026-08-28
主题：工具执行成功但无输出时，发送给模型的 tool 消息内容替换为「输出内容为空」占位符（配置开关控制，默认关闭）

## 背景与根因

公司内网 LLM 网关资源紧张（429/500/502 混合，平均 3 次调用成功 1 次，重试最多 15 次内必成功）。

实测现象：当工具执行成功但无输出时（如 `mvn -q > file`、`read` 空文件），BashTool/ReadTool 返回
`ToolResult.success("")`（空字符串）→ `Message.toolResult(id, name, "")` → 请求体中 tool 消息为
`{"role":"tool","tool_call_id":"...","name":"Bash","content":""}`——content 为空字符串。

根因链：

1. 重试循环（AgentLoop 长重试）**没有次数上限，只有 20 分钟时间上限**，每次重试**重发同一个 request**（循环外构造）；
2. 公司网关"15 次内必成功"的前提是请求内容正常（失败为独立瞬时限流）；若请求内容本身触发服务端稳定拒绝
   （如严格校验空 content 的 tool 消息、上游异常包装 500/502、异常请求计入限流配额转 429），
   重试 240 次 = 240 次重发同一个必失败的请求 → **永不成功，直到 20 分钟超时**；
3. "工具返回空"留下的 `"content": ""` 是请求体中与正常轮次唯一的结构差异——即嫌疑触发点。

## 方案

配置开关 `agent.emptyOutput.placeholder`（boolean，**默认 false**；无该配置同样默认 false）：

- **开启时**：工具执行成功（`ok=true`）且输出为空（null 或 trim 后为空）→ 发送给 API 的 tool 消息
  content 替换为占位文本 **「输出内容为空」**，让服务端校验通过；同时系统提示词追加一条规则，
  告知模型占位符含义（命令成功、无输出，按成功处理，不要视为失败或重复调用同一工具）；
- **关闭时**：行为与现状完全一致（原样发送空串），提示词也不追加。

UI 显示不受影响：`ui.onToolResult` 仍使用原始 result（界面保持透明，显示真实空输出）。

### 占位文本

固定硬编码「输出内容为空」（不做配置项，保持改动最小）。

### 提示词内容（仅开关开启时追加，作为第 9 条规则）

```
9.工具执行成功但无输出时，返回结果将为「输出内容为空」（如 mvn -q 输出重定向、读取空文件）：
  表示命令成功、无输出内容，请按成功结果处理，不要视为失败或重复调用同一工具。
```

## 改动点

| 文件 | 改动 |
|---|---|
| `src/resource/config.properties` | 新增 `# ===== 工具空输出占位 =====` 段 + `agent.emptyOutput.placeholder=false`（含注释说明） |
| `src/main/java/com/minion/core/config/Config.java` | 新增 `emptyOutputPlaceholder()` 读取方法（默认 false） |
| `src/main/java/com/minion/core/tools/ToolResult.java` | 新增静态辅助 `outputForApi(String output, boolean placeholder)`：开启且空输出时返回「输出内容为空」，否则原样返回（null 安全） |
| `src/main/java/com/minion/core/agent/AgentLoop.java` | ① 新增 public 字段 `emptyOutputPlaceholder = false`（与 `retryPolicy` 同风格，测试可覆写）；② 组装 tool 消息处（`session.messages.add(Message.toolResult(...))`）经 `ToolResult.outputForApi` 替换；③ `setSubAgentRunner` 创建 SubAgentLoop 时传递开关 |
| `src/main/java/com/minion/core/agent/SubAgentLoop.java` | 新增 public 字段 `emptyOutputPlaceholder`；组装 tool 消息处同样替换 |
| `src/main/java/com/minion/core/agent/SystemPromptBuilder.java` | 新增 boolean 字段 + 4 参构造重载（旧构造委托 false）；`build()` 开启时追加第 9 条规则 |
| `src/main/java/com/minion/gui/session/SessionManager.java` | 两处创建 AgentLoop 后注入 `loop.emptyOutputPlaceholder = config.emptyOutputPlaceholder()`；4 处 `new SystemPromptBuilder` 改传开关 |

不改动：UI 渲染（保持真实输出）、重试策略（RetryPolicy 不动）、LlmException 判定。

## 测试

- 新增/更新单测：
  - `ToolResult.outputForApi`：开启+空输出→占位；开启+非空→原样；关闭+空输出→原样空串；null 输入安全
  - `SystemPromptBuilder`：开关开启时提示词含占位规则；关闭时不含（规则 1-8 原样）
  - Config：默认 false；配置 true 时读 true
- 回归：`mvn compile` + `mvn test` 全量通过
