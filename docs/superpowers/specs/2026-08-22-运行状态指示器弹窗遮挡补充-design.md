# 运行状态指示器：弹窗遮挡补充设计

> 日期：2026-08-22
> 前置：docs/superpowers/specs/2026-08-22-运行状态指示器-design.md（原设计，已实施）
> 本文为原设计的增量补充，涉及两处缺陷修复，不动原设计其余部分。

## 背景

原运行状态指示器（正文区左下角悬浮齿轮 + 动态文案）存在两个体验缺陷：

1. **工具提问弹窗期间齿轮误导**：高危工具确认（ConfirmSheet 底部卡片）弹出时，AgentLoop 处于"等待用户点击"状态但运行态仍为 true，齿轮持续旋转、文案显示"正在加载中..."，用户容易误判为卡死。需求：弹窗显示期间隐藏指示器，弹窗关闭后若会话仍在运行则恢复显示。
2. **窗口化时遮挡最后一行正文**：ChatView 底部 padding 仅 12px，而指示器悬浮覆盖范围 = 距底 10~27px（margin 10 + 齿轮高约 17）。滚动到底时最后一行底边距视口底 12px，被指示器遮住约 15px。全屏时视口高、消息不满屏（ScrollPane fitToHeight 拉伸 ChatView），最后一行离底较远，故不遮挡。需求：任何窗口尺寸下滚动到底都不遮挡最后一行。

## 决策

- **弹窗隐藏方式**：整个指示器（齿轮+文案）隐藏。弹窗期间 AgentLoop 语义是"等待用户输入"而非运行，齿轮与加载文案均不适用（用户经 AskUserQuestion 确认选 1）。
- **遮挡修复方式**：增大 ChatView 底部 padding（12px → 40px），正文最后一行让出指示器空间，视觉上即"指示器位于正文之下"。全屏时本就位于正文下方空白处，视觉不变。

## 设计

### 1. RunningIndicator：可见性自洽 + 挂起/恢复

现状：`setRunning(false)` 内部已做"停动画 + 隐藏 + 复位压缩态"；动画规约（StatusDot 同款）：隐藏前必须停全部 Timeline，防动画强引用节点泄漏。

新增：

- **visibleProperty 监听**（构造器中注册）：
  - `visible == false` → `stopAnimations()`（停 spin/rotateText 并置空引用，防泄漏）
  - `visible == true && running` → `text.setText(displayText(compressing, pickText(rnd)))` + `startAnimations()`
  - 动画启动逻辑由此收敛到可见性监听，`setRunning(true)` 改为只 `setVisible(true)`（触发监听）；`setRunning(false)` 保持现状（内部已停动画并隐藏，setVisible 监听再次触发 stopAnimations 幂等无害）
- **`suspend()`**：弹窗显示时调用——仅 `setVisible(false)`，保留 `running`/`compressing` 状态（由 visible 监听自动停动画）
- **`resume()`**：弹窗关闭时调用——`running` 为 true 则 `setVisible(true)`（恢复动画与文案），否则保持隐藏（幂等 `setVisible(false)`，覆盖"弹窗期间会话已结束"的竞态）

### 2. ConfirmSheet：可见性回调

静态类，沿用 `setHost` 的注册模式：

- 新增静态字段 `private static Consumer<Boolean> visibilityListener;` 与 `setVisibilityListener(Consumer<Boolean>)`
- `display()` 中 `showing = true` 后回调 `visibilityListener.accept(true)`
- `finish()` 中淡出完成、`showing = false` 后回调 `visibilityListener.accept(false)`
- 并发语义：`pending` 队列串行，`finish` 出队下一个 `display` 时先回调 false 再 true，顺序天然正确
- 未注册时回调为 null，判空跳过

### 3. MainWindow：注册联动

`ConfirmSheet.setHost(rightStack)` 处追加：

```java
ConfirmSheet.setVisibilityListener(showing -> Platform.runLater(() -> {
    if (showing) runningIndicator.suspend(); else runningIndicator.resume();
}));
```

回调本身来自 FX 线程（ConfirmSheet 所有操作均在 FX 线程），Platform.runLater 包装为防御性一致（与 4 处状态同步同款）。

### 4. ChatView：底部留白

构造函数内联样式 `-fx-padding: 16 16 12 16` → `-fx-padding: 16 16 40 16`，注释更新为"底部 40px 为运行状态指示器让位（覆盖范围距底 10~27px，滚动到底不遮挡最后一行）"。

### 5. 测试与验证

- 无可自动化测试：suspend/resume/visible 监听依赖 FX 节点，ConfirmSheet 回调依赖 FX 线程与 host，均不在"gui 测试只测纯静态逻辑"范围内
- 验证：`mvn compile` + 全量测试（587 用例）无回归；人工目验：
  1. 窗口化（非全屏）长会话滚动到底，最后一行不被齿轮遮挡
  2. 触发高危工具确认弹窗 → 指示器立即隐藏；点选后会话继续运行 → 指示器恢复
  3. 弹窗期间切走会话（running 变 false）→ 弹窗关闭后指示器保持隐藏
