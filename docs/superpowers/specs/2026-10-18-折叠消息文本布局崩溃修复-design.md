# 折叠消息文本布局崩溃（整页渲染错乱）修复

日期：2026-10-18
状态：已实施（2026-10-18，全量用例 1261 项通过 + 真实 JavaFX 探针验证）

## 现象

用户报告：点击会话列表中的某个历史会话（1.1MB、344 条消息）后，整个界面渲染错乱：

- 左侧会话列表区不显示
- 右侧正文区（消息区）不显示
- 输入框左下角"上传按钮"与"上下文环形按钮"重叠
- 输入框打字时光标永远停最左

同一会话在运行到后段时就已经出现该现象；重启软件后点击该会话必然复现。

## 根因证据

### 复现

探针（加载会话 → `SessionController.replayHistory` → 真实 Scene 中 `ChatView.bind(true)` → `layout`）
在该会话上稳定复现，FX 线程未捕获异常：

```
java.lang.ArrayIndexOutOfBoundsException: 26
    at com.sun.javafx.text.TextRun.getWrapIndex(TextRun.java:291)
    at com.sun.javafx.text.PrismTextLayout.layout(PrismTextLayout.java:1074)
    at com.sun.javafx.text.PrismTextLayout.getBounds(PrismTextLayout.java:246)
    at com.sun.javafx.scene.control.skin.Utils.computeTextHeight(Utils.java:138)
    at com.sun.javafx.scene.control.skin.TextAreaSkin$ContentView.computePrefHeight(TextAreaSkin.java:156)
    at com.sun.javafx.scene.control.skin.ScrollPaneSkin.computeScrollNodeSize(ScrollPaneSkin.java:937)
    at com.sun.javafx.scene.control.skin.ScrollPaneSkin.layoutChildren(ScrollPaneSkin.java:822)
    at javafx.scene.control.Control.layoutChildren(Control.java:578)
    ...
    at javafx.scene.Scene.doLayoutPass(Scene.java:552)
```

异常发生在 **Scene 的布局 pass** 中：一个节点的皮肤布局抛异常 → 整个 `doLayoutPass` 中断 →
其后的兄弟/祖先节点本轮不再布局、也不会重绘。因此表现为"正文不显示、列表不显示、按钮全叠在 (0,0)、
TextArea 光标原点错位"这类**全局**错乱，而不是某一条消息显示异常。

### 触发事件

逐事件定位（单事件重建 ChatView + 手动 layout），命中唯一事件：

- 会话 `20261018-163648-795-0001` 第 420 个 UI 事件
- `TOOL_RESULT`，`Bash` 工具输出：Maven surefire 报告片段，677 字符、8 行
- 文本含 69 个 `U+FFFD`（`�`，GBK 输出被按 UTF-8 解码产生的替换字符）

### 最小触发条件（探针实测）

| 变体 | 结果 |
| --- | --- |
| 折叠态（unmanaged）+ 原文 | **崩溃** AIOOBE 26 |
| 折叠态 + 把 U+FFFD 换成 `?` | OK |
| 折叠态 + 纯 ASCII / 纯中文（同长度） | OK |
| 展开态（managed）+ 原文 | OK |
| 折叠态 + 内容 `setText("")` | OK |
| 单独该"最长行"渲染（900px 宽） | OK |
| 可见 TextArea 强制宽度 20px + 原文 | **崩溃** |
| 可见 TextArea 强制宽度 40/60/120/300/600px + 原文 | OK |

结论：触发需要 **"换行宽度极小/为 0" + "特定文本内容（本例为含 U+FFFD 的换行组合）"** 两者同时成立。

### 为什么折叠态宽度是 0

`CollapsibleText` 折叠时把内容体 `content.setVisible(false) + setManaged(false)`，但 **文本已经写入
TextArea**（构造时 `new MessageTextArea(text)`）。该 TextArea 不在父布局管理范围内，宽度保持 0；
而 JavaFX 8 仍会对 skin 内部控件执行布局，于是 `TextAreaSkin$ContentView.computePrefHeight`
以 0 宽做换行计算 → `TextRun.getWrapIndex` 索引越界（JDK 内部缺陷）。

工具输出 ≥500 字符即默认折叠（`CollapsibleText.COLLAPSE_THRESHOLD`），所以**任意会话只要有一条
大于等于 500 字符、且内容恰好落入该 JDK 缺陷的折叠工具输出，就会整页崩坏**。

### 为什么无法 catch

`Parent.layout()` 是 `final`，内部皮肤的 ScrollPane 由 JavaFX 自行递归布局；覆盖
`MessageTextArea.layoutChildren()` 捕获不到（探针实测：捕获计数 0，异常照常上抛）。

## 修复方案

### 1（根因）折叠时不把文本交给 TextArea

`CollapsibleText` 折叠态内容体不设置文本（`setText("")`），展开时再写入原文。
这样"宽度 0 + 有文本"的组合在任何字符下都不存在，从结构上消除触发条件。

- 新增纯逻辑判定 `contentText(boolean expanded, boolean hasText, String text)`：
  展开且有内容 → 原文；否则 → 空串。
- `update()` 中按判定结果同步 `content` 文本（值相同不重复 set，避免流式高频 relayout）。
- `setStreamText()`（流式思考强制展开）先展开再写文本，同一次 FX 线程内不会插入布局，安全。

### 2（数据防御）U+FFFD 显示为 `?`

`MessageTextArea` 写入文本时把 `U+FFFD` 替换为 `?`：该字符只是"解码失败"的占位符，本身无信息价值；
替换后视觉等价，同时让展开态极窄宽度等边界场景也不再命中该 JDK 缺陷（探针已验证替换后 OK）。

### 不采用的方案

- **catch 布局异常**：`Parent.layout()` 为 final，异常从皮肤内部 ScrollPane 抛出，无法拦截。
- **折叠时移除内容节点**：效果同 1，但节点增删会打断 CSS/布局缓存与选中态，改动面更大。
- **禁用 wrapText**：长行需横向滚动，破坏现有消息区交互。

## 影响面

- `src/main/java/com/minion/gui/chat/CollapsibleText.java`：折叠/展开时内容体文本同步
- `src/main/java/com/minion/gui/chat/MessageTextArea.java`：文本入口清洗 U+FFFD
- 折叠段在折叠期间 `contentArea().getText()` 为空（展开即恢复）；现有代码只在渲染路径使用该控件
