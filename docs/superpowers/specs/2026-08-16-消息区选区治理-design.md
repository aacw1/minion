# minion 消息区选区治理（多块选中误导） 设计

日期：2026-08-16
状态：已确认（用户选定「只要焦点清除」；「单击整段全选」方案被否决，保留原文备查）

## 背景

消息区（ChatView）正文每段是独立的只读 TextArea（MessageTextArea）。用户反馈：

1. 拖动鼠标选块 A 的文字，再拖动选块 B → 两个块**同时显示**选中效果，但 Ctrl+C 只复制最后一块的选区（A 的选区复制不出来）。
2. 期望：点击或选择某个块时，其他块的选中效果消除；若可能，最好能直接复制整块内容，不要逐个块断开。
3. 用户明确：**不要复制按钮**，保持「鼠标选中文字 → Ctrl+C 手动复制」的原生范式。

## 根因

- TextInputControl 的选区是**控件私有状态**：每个 TextArea 各自维护 selectionStart/End，失焦后选区仍保留。
- theme.css 的 `.msg-textarea` 把 `-fx-highlight-fill` 固定为 `#3b6fe0` 且**不区分 `:focused`**（[theme.css:214-222](src/resource/theme/theme.css)）→ 失焦块的选区与聚焦块**同色显示**，视觉上"多块同时选中"。
- Ctrl+C 复制只作用于**焦点控件**的选区（JavaFX 行为）→ 只有最后交互的块能复制。

**技术限制（如实说明）**：JavaFX 原生不支持跨 TextArea 的连续拖选选区（选区属于单个 TextInputControl），"一次拖动选中多个块并复制全部内容"在原生机制下不可行；自绘跨块选区需拦截拖选/绘制/复制，工作量大且易碎（wrap、滚动、字体缩放），不做。

## 方案（用户确认版：只做焦点清除，无按钮、无单击全选，保持原生选中+手动复制范式）

### 1. 焦点转移清除其他段选区（核心）

每段正文挂 `focusedProperty` 监听：获得焦点 → 遍历其余段 `deselect()`。保证任意时刻**至多一个块有选区**，显示与复制行为一致（拖选块 A → 拖选块 B 时 A 的选区立即消失；点击块 A → 点击块 B，A 的选区被清，只剩 B）。

### 2. CSS 失焦/聚焦高亮色区分（防御纵深）

```css
.msg-textarea { -fx-highlight-fill: #232a38; }                  /* 非聚焦：淡灰，几乎不可辨 */
.msg-textarea:focused { -fx-highlight-fill: #3b6fe0; }          /* 聚焦：亮蓝（现状色） */
```

即使存在未清理的残留选区（如焦点停在输入框时），非聚焦块的选区也呈淡灰，不会误导为"当前选中"。

### 实施落点

- [ChatView.java](src/main/java/com/minion/gui/chat/ChatView.java)：`append()` 创建段后给 `body` 挂焦点监听（排除自身，遍历 `segs` 其余段 `deselect()`；hint 占位行不参与）。
- [theme.css](src/resource/theme/theme.css)：`.msg-textarea` 高亮色拆分 `:focused`。

## 测试

1. 焦点清除为 JavaFX 控件交互，项目无 TestFX 设施，手工验证清单：
   - 拖选块 A → 拖选块 B：A 选区立即消失，B 有选区，Ctrl+C 复制 B
   - 拖选块 A → 点击块 B：A 选区消失，B 无选区（点击不产生选区），Ctrl+C 无内容（行为一致不再误导）
   - 单击/双击选词/Ctrl+A/右键复制/流式更新：行为不变
2. 全量 `mvn test` 回归。

## 影响面

- 仅 ChatView/MessageTextArea/theme.css 三处；不改事件流、不改消息历史、不新增 UI 元素。
- 原生选中/复制/右键菜单/双击选词/Ctrl+A 全部保留。
