# 消息区改造：纯控制台风格（设计文档）

日期：2026-08-14 · 状态：待实施确认

## 背景与根因

用户要求消息区改为"最原始的纯控制台输入输出显示效果"：
纯文字、有颜色、整个会话为一段连续文本流（该换行换行，不要块状容器）、
背景整区 rgb(18,19,20)、文字白色、铺满正文且距输入框上边缘 1 行。

当前实现（工作区）已接近该目标（VBox + 每段一个 MessageTextArea，标签内嵌行首，
段间 spacing 0），但目验发现两个实际问题，即用户反馈的"一块块白色""每块有单独滚轮"：

1. **白色块根因**：theme.css 的 `.msg-textarea` 只透明了内部
   `.content`/`.scroll-pane`/`.viewport`，未设置 TextArea 自身背景透明。
   JavaFX 8 modena 中 `.text-area` 默认背景为
   `-fx-text-box-border, -fx-control-inner-background`（白底），
   从透明子节点后面透出 → 每条消息显示为一块白底。
   （对照：`.input-frame .input-textarea` 显式设了 transparent，故输入框无此问题。）

2. **内部滚动条根因**：MessageTextArea 重写 `computePrefHeight(width)` 想让
   TextArea 高度随内容自适应，但 JavaFX 8 中 TextArea 的 prefHeight 计算
   会被其 skin（TextAreaSkin）内部机制覆盖/不严格遵循，且测量器宽度硬编码
   600（`width > 0 ? width : 600`），实际窗口变窄时测量偏高偏少 →
   TextArea 实际高度未撑到内容高度 → 内容超高 → 每个 TextArea 内部
   出现独立滚动条，与"全部直接打印"的控制台语义冲突。

## 方案（用户已确认）

**每条消息 = 一行 HBox（彩色加粗标签 Label + 白色正文 MessageTextArea）**，
标签与正文分节点（JavaFX 8 单 TextArea 不支持富文本，段内只能一色）：

```
【输入】c盘的空间还有多少          ← 标签蓝粗体，正文白
【思考】客户想知道C盘空间，调工具  ← 标签灰粗体，正文白
【工具】bash xxxx                  ← 标签黄粗体，正文白
  并显示结果
【回复】C盘剩余 xx G               ← 标签白粗体，正文白
```

- 标签固定 `【输入】【思考】【工具】【回复】【系统】` 前缀，加粗 + 场景色；
  正文一律白色。
- 段间 spacing 0 无缝紧贴（连续控制台流）；HBox 内正文 TextArea `Hgrow=ALWAYS`
  吃满剩余宽度正常换行；正文换行后续行顶格（控制台续行语义）。
- TextArea 保留原生拖选/Ctrl+C/右键菜单复制能力（上轮已确认的价值）。
- 流式语义不变：思考流/回复流就地 `setText` 更新正文，不重建节点。

## 改动点

### 1. MessageTextArea：手动高度自适应（核心修复，消灭内部滚动条）

弃用 `computePrefHeight` 重写，改为**监听驱动的手动高度管理**：

- 监听 `textProperty` 与 `widthProperty`（含 `padding`/字体变化兜底），
  变更时用同字体 `Text` 测量器按**实际内容宽度**重算：
  `wrapWidth = getWidth() − 左右 padding`，`prefHeight = 测量高 + 上下 padding + 小余量`。
- `setPrefHeight(重算值)` 同步 `setMaxHeight`（防止 VBox 布局上限压回）。
- 效果：TextArea 高度恒等于内容高度，内部滚动条永不出现，
  内容全部展开直接打印；整区滚动只由外层 ScrollPane 负责。
- 首次布局宽度未定（width 为 0）时先按 `computePrefWidth` 兜底，
  宽度确定后立即重算。

### 2. ChatView：Seg 改为「标签 + 正文」HBox 结构

| 事件 | 标签（Label，加粗+场景色） | 正文（MessageTextArea，白） |
|---|---|---|
| USER_MESSAGE | 【输入】蓝 | 用户文本 |
| USER_SUPPLEMENT | 【输入】蓝 | 补充文本 |
| THINKING | 【思考】灰 | 流式就地更新 |
| CONTENT | 【回复】白 | 流式就地更新（toPlainText 展平） |
| TOOL_CALL | 【工具】黄 | 现有 `🔧 name\n{args摘要}` / ask_user 提问 |
| TOOL_RESULT | 【工具】黄（失败时【系统】红） | 现有 ✅/❌ 文本 |
| ERROR | 【系统】红 | 错误文本 |
| WARNING | 【系统】黄 | 警告文本 |
| STATS/SYSTEM | 【系统】灰 | 统计/命令结果 |
| SUB_AGENT_START/DONE | 【工具】黄 | 现有 ▶/✓ 文本 |

- Seg 持有（Label tag, MessageTextArea body, boolean think）；
  `stream()` 同流就地更新 body，异流新起一段（现有语义不变）。
- 空会话占位"输入消息开始新的会话"：单个 MessageTextArea 灰字（不变）。

### 3. theme.css

```css
/* 修复白块：TextArea 自身背景透明（modena 默认白底，此前只透明了内部子节点） */
.msg-textarea {
    -fx-background-color: transparent;
    -fx-control-inner-background: transparent;
    /* 保留原有：highlight/focus/边框透明等 */
}

/* 消息标签（叠加在现有 log-* 色类上）：加粗 */
.log-tag { -fx-font-weight: bold; }

/* 消息正文：统一白色 */
.log-body { -fx-text-fill: #f0f2f6; }
```

- 标签色类复用现有 `.log-input`（蓝）/`.log-think`（灰）/`.log-tool`（黄）/
  `.log-reply`（白）/`.log-error`（红）/`.log-warn`（黄）/`.log-sys`（灰），
  与 `.log-tag` 叠加。
- 正文统一 `.log-body`（白）；`.log-*` 不再直接用于正文 TextArea。

## 测试与验证

- **构建**：`JAVA_HOME="E:/javame/jdk8" mvn compile` + `mvn test` 全绿
  （MarkdownRendererTest.toPlainText 用例已覆盖纯文本展平，逻辑不变）。
- **目验**（minion.bat 启动）：
  1. 无白色块——整区背景统一 rgb(18,19,20)；
  2. 标签彩色加粗、正文全白；
  3. 长回复/长工具结果**全部平铺展开**，段内无滚动条，滚动只由外层 ScrollPane 进行；
  4. 段间连续无缝隙（多轮对话为连续文本流）；
  5. 内容少时背景铺满正文，底部距输入框约 1 行（padding 12 + VBox spacing 8）；
  6. 拖选/Ctrl+C/右键复制仍可用；流式输出就地更新正常。

## 边界与取舍

- JavaFX 8 单 TextArea 不能富文本着色 → 段内单色，标签/正文分节点实现多色；
  视觉上标签+正文紧密排列，仍为连续控制台流。
- 正文不再整行着场景色（输入/思考/工具正文一律白色），场景区分全靠标签颜色
  （用户已确认的配色方案）。
- 富文本 markdown 样式不渲染（延续上轮 toPlainText 展平，语法记号已去除）。
- 标签不可选中复制（Label 无选择能力），正文可选中；整条复制 = 拖选正文或
  逐段选择（上轮已确认接受此取舍）。
