# 输入发送键切换设计

日期：2026-08-15
状态：已确认（用户审阅通过前为草案）

## 背景与问题

输入框目前固定 Ctrl+Enter 发送、Enter 换行。用户希望支持「Enter 发送」模式，并在基础设置里增加选项，可实时生效（勾选立即生效，无需点「应用」，也无需重启）。

## 目标

- 两种发送键模式可切换：
  - 模式一（默认，现状）：Enter 换行，Ctrl+Enter 发送
  - 模式二：Enter 发送，Ctrl+Enter 换行（对称互换，用户已确认）
- 基础设置页新增选项，勾选/取消勾选**立即生效**（写回 config.properties 持久化，输入框下一次按键即用新键位）。
- 提示文案（输入框 prompt、按钮 tooltip）随模式动态显示发送键名。

## 非目标

- 不做 Shift+Enter 换行（用户已确认用 Ctrl+Enter 对称互换）。
- 不改动补全弹层（/命令、@文件）的 Enter 确认行为——弹层打开时 Enter 始终确认选中，两种模式一致。
- 不做热键动态配置（仅二选一开关）。

## 关键约束

- **JDK 8**，无新依赖。
- **零回归**：默认模式（enterSends=false）下按键行为与现状完全一致（Ctrl+Enter 弹层开着也发送，同现状）。

## 配置项

### config.properties（src/resource/config.properties）

放「确认开关」后新增：

```properties
# 输入框发送键：false=Ctrl+Enter 发送（Enter 换行）；true=Enter 发送（Ctrl+Enter 换行）
input.enterSends=false
```

### Config.java

新增 getter，风格与 `confirmSkip()` 一致：

```java
/** 输入框发送键：true=Enter 发送（Ctrl+Enter 换行）；false（默认）=Ctrl+Enter 发送（Enter 换行） */
public boolean enterSends() { return Boolean.parseBoolean(get("input.enterSends", "false")); }
```

- 已存在的用户外部 config.properties 无此键 → `get` 回落默认 false，无需迁移。

## InputView 键位逻辑

### 构造器注入

`InputView(SessionManager manager)` 改为 `InputView(SessionManager manager, Config config)`，存字段；MainWindow 构造处传 `MinionApp.config()`。

### 按键过滤器改造（capture 阶段）

提取静态可测判定方法：

```java
/** 当前发送键模式下，该按键事件是否为「发送」（弹层打开时由调用方先分流，不算发送） */
static boolean isSendKey(KeyEvent e, boolean enterSends)
```

分支顺序（两种模式）：

| 事件 | enterSends=false（默认） | enterSends=true |
|------|--------------------------|-----------------|
| Ctrl+Enter，弹层关 | 发送（`onAction()`，最先检查，同现状） | 换行：`input.replaceSelection("\n")` + consume（JavaFX TextArea 对 Ctrl+Enter 无默认换行绑定，须显式插入） |
| Ctrl+Enter，弹层开 | 发送（同现状） | 确认弹层选中 |
| Enter，弹层开 | 确认弹层选中（同现状） | 确认弹层选中 |
| Enter，弹层关 | 换行（默认行为） | 发送（`onAction()`） |
| Tab/↑↓/Esc 等 | 不变 | 不变 |

- 发送键统一调现有 `onAction()` 全分发（SEND/SUPPLEMENT/ANSWER/STOP 全语义，与按钮点击一致），两种模式行为一致。
- 默认模式下 Ctrl+Enter 仍在弹层检查之前 → 行为零变化。

## 设置页 UI（实时生效）

BasicPane 新增 CheckBox，放「确认开关」行后：

```java
enterSends = new CheckBox("Enter 发送消息（Ctrl+Enter 换行）");
enterSends.setSelected(config.enterSends());
// 勾选立即生效：直接写回 Config（内存+落盘），不依赖「应用」
enterSends.selectedProperty().addListener((obs, ov, nv) ->
    config.set("input.enterSends", String.valueOf(nv)));
```

- 实时生效原理：InputView 每次按键读 `config.enterSends()`；`Config.set()` 更新内存 map + 落盘 → 勾选后下一次按键即新键位，无需重启、无需「应用」。
- `apply()` 不重复写该键（实时已写，注释说明）。

## 提示文案动态化

- 输入框 prompt（`updatePrompt()`）与按钮 tooltip（`updateButton()`）中的发送键名改为按模式生成：

```java
/** 发送键显示名：Enter / Ctrl+Enter */
static String sendKeyLabel(boolean enterSends)
```

- 刷新时机：
  - `updateButton()` 在文本/光标/运行态变化时刷新（现有机制已覆盖大部分场景）。
  - `focusedProperty` 监听补一次 `updateButton() + updatePrompt()`——用户勾选后点回输入框，文案立即正确（勾选瞬间输入框不在焦点，无需实时推送文案，此为接受取舍）。
