# Win7 正文方块：JavaFX 字体回退修复（2026-10-29）

## 现象

另一台 Windows 7 机器运行 minion 时，正文（消息区）里的 `→`、`•`、`✓` 等字符显示为方块（tofu），
复制这些文字粘贴到 Notepad++ 却完全正常。编码/剪贴板数据没问题，问题在 JavaFX 渲染层。

## 根因

1. **JavaFX 8 不按 CSS 字体列表逐项回退**：`-fx-font-family: "Microsoft YaHei UI", "Segoe UI", sans-serif;`
   只取第一个族；第一个族不存在时直接落到 `System`，后面的族不会尝试。
   （openjfx-dev 2022-04 邮件确认；本机 JavaFX 8 探针同样复现：首族缺失时 Label 实际字体为 `System`。）
2. **Win7 没有 `Microsoft YaHei UI`**：Win7 自带的是 `Microsoft YaHei`，中文环境 JavaFX 暴露的族名是
   `微软雅黑`（本机探针也确认 `"Microsoft YaHei"` 不是可解析族名，`"微软雅黑"` 才是）。
   因此 Win7 上 `.root` 的字体实际变成 `System`（通常是 Segoe UI）。
3. **JavaFX 8 的符号回退链不完整**：复合字体回退主要覆盖 CJK，箭头/勾选/emoji 等符号可能找不到字形
   （JDK-8217392 "Need more code point coverage in composite fonts on Windows"）。
   Notepad++ 走系统 DirectWrite/GDI 回退，所以同一段文字能正常显示。
4. 现有 `IconFactory` 已把界面图标改成 SVG，但 **用户/模型正文和工具摘要仍是普通文本**，仍会受该缺陷影响。

## 修复

- 新增 `gui/theme/UiFonts`：从 `Font.getFamilies()` 中按序选择第一个已安装族：
  `Microsoft YaHei UI` → `微软雅黑` → `Microsoft YaHei` → `SimHei` → `SimSun` → `宋体`
  → `Segoe UI` → `System`；结果缓存。纯选择逻辑拆成 `resolve(List<String>)` 便于单测。
- `MainWindow` 给带 `.root` 的 BorderPane 追加行内 `-fx-font-family`；`Theme.style(Dialog)` 给
  DialogPane 追加同样的行内样式。行内样式优先于样式表，绕开 CSS 列表缺陷；Win10 仍用 YaHei UI，
  Win7 自动落到微软雅黑。
- `theme.css` 的 `.root` 改为单一兜底族 `"微软雅黑"`，并注明 JavaFX 8 不支持逗号列表回退，
  防止后续再写成“看起来有 fallback、实际不生效”的列表。
- 不替换正文中的 Unicode 字符，不打包第三方字体（体积/授权），不改变复制内容。

## 验收

- 单测：`UiFontsTest` 覆盖 Win10 优先 UI、Win7 无 UI 回退“微软雅黑”、英文族名、宋体兜底、全缺回退 System。
- Win10 本机：原主题字体仍为 `Microsoft YaHei UI`，界面观感不变。
- Win7 现场：正文 `→`/`•` 等不再显示方块；`✓`/emoji 若仍缺失，属 JavaFX 8 复合字体覆盖上限，
  内容与复制不受影响，可在 README 排查段落说明。
