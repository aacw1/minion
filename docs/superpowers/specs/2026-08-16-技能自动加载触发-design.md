# minion 技能系统重构——渐进式加载（正文以 user 消息注入）

日期：2026-08-16
状态：已确认（用户决策：不做 /unskill；不做强制幂等、工具报告状态由模型判断；`<skill>` 块内容豁免上下文压缩；skills.dir 默认值不变）

## 背景

当前技能机制：`SkillManager` 扫描技能目录后，目录（名—描述）与**已加载技能全文**都拼进系统提示词（SystemPromptBuilder.java:43-48），每轮重建。问题：

1. **前缀缓存失效**：加载/卸载技能即改变 system 前缀，DeepSeek 前缀缓存全量失效，LLM 请求成本随技能加载陡增
2. **渐进式披露缺失**：技能正文无论当前任务是否需要，加载后每轮常驻 system，与"少量目录常驻、完整正文按需加载"的设计原则相悖
3. **无自动加载能力**：13 个工具中无 Skill 工具，模型只能建议用户手动敲 `/skill <名>`，superpowers 链式技能（brainstorming → writing-plans → executing-plans → requesting-code-review）每跳都要用户介入

（上一版同日设计文档"技能全文注入系统提示词 + /unskill"已作废：正文进 system 正是前缀缓存失效的根源；unskill 在正文入历史的方案下无实际撤回能力。）

用户目标：技能文件夹 `E:\javame\code\skills`（superpowers 15 技能，内容零改动）只改自身代码兼容；模型按描述自动路由加载技能，自动跑通 需求澄清→设计→实现→审核 全流程。

## 方案

### 1. 系统提示词目录段（SystemPromptBuilder）

- 删除「已加载技能」段（正文不再进 system）
- 「可用技能」段改为路由引导：

> 当任务与某技能描述匹配时，调用 Skill 工具加载（正文将作为一条用户消息注入，立即生效）。技能描述是路由条件——先看"何时用/何时不用"，匹配才加载，不匹配不要加载。同一技能不要重复加载；技能正文中引用的 Claude Code 专属机制（plan mode、ExitPlanMode、/loop 等）在本环境中不可用，相关审查确认用 AskUserQuestion 代替。

- 目录行沿用 `hint()`：`name — description`（description 即路由条件；superpowers 描述已按"何时使用"风格撰写，无需改写）

### 2. Skill 工具（新建 core/tools/SkillTool.java）

- `name()` = `"Skill"`，schema `{name: string}`，isHighRisk = false（只读内存与队列，不改文件）
- 注册：AgentLoop 构造器 `registry.register(new SkillTool(this))`（TaskTool 先例；构造捕获 AgentLoop 引用，需访问 allSkills 与待注入队列）
- `execute`（池线程执行）：
  1. 技能表为空 → 失败 ToolResult（提示检查技能目录配置 skills.dir）
  2. `name` 缺失 → 失败 ToolResult
  3. 按 name 在 allSkills 查找（大小写不敏感）→ 未找到 → 失败 ToolResult（提示 /skills 或可用列表）
  4. **历史标记扫描**：遍历 session.messages 找含 `<skill name="xxx">` 的 user 消息（pinned）：
     - 已存在 → 返回报告 ToolResult：「技能 xxx 的正文已在上下文中（此前已注入），无需重复加载；如你判断正文已失效可再次调用」——**不阻止、不去重，是否重载由模型判断**
     - 不存在（未加载 / 曾被压缩清除——pinned 豁免下不会发生，防御保留）→ 正常加载
  5. 正常加载 → 加入 `pendingSkillLoads` 待注入队列 → 返回成功 ToolResult「已加载技能 xxx（描述），正文将注入当前会话」
- 并发安全：工具线程只写队列，不直接操作 session.messages；历史标记扫描为只读遍历，以 synchronized(session.messages) 保护（主循环线程检查点 add 与之并发，ArrayList 非线程安全）

### 3. 注入机制（AgentLoop）

```
模型调用 Skill 工具（池线程）
  → execute 入队 pendingSkillLoads（线程安全队列）
  → 主循环检查点（工具结果全部入历史后、下一轮请求前，与 drainSupplements 同位置）:
      drainPendingSkillLoads():
        对每项构造 user 消息 "<skill name=\"xxx\">\n{正文}\n</skill>"，pinned=true
        → session.messages.add
```

- **同轮生效**：AgentLoop 每轮迭代重建请求（AgentLoop.java:312），模型调 Skill → 工具结果入历史 → 注入正文 → 下一轮请求已含正文 → 链式衔接无需用户介入
- 手动 `/skill <名>`：保留，行为改为入队（FX 线程写队列），`runUserTurn` 开头的 `drainSupplements()` 顺带 drain → 下一轮请求生效
- 注入消息 ChatView 照常渲染为一条用户消息（透明可审计）

### 4. 压缩豁免（Message + ContextManager）

用户决策：`<skill>` 块内容不参与上下文压缩，正文一旦加载常驻至会话结束。

- `Message` 新增字段 `pinned`（boolean，gson 落盘；旧文件缺字段 → null/false 兜底）
- 新增工厂 `Message.skill(String content)`（user 角色 + pinned=true）
- ContextManager.chunkChains：`pinned` 消息 → flush 当前链 + 跳过（不入链、不参与摘要；与 system/summary 同处理）
- ContextManager.compress：pinned 消息原样保留，置于摘要消息之后、保留链之前
- TokenCounter 估算不变（pinned 消息照常计入上下文占用）
- 收益：正文永不消失 → 无"压缩后静默失效"；代价：技能正文常驻 token，靠目录段引导语（"匹配才加载"）与工具报告（"已在上下文中"）约束堆积

### 5. 持久化——无需新字段

- 幂等判定 = 历史标记扫描 → `AgentLoop.loadedSkills` 字段、`loadSkill()` 方法、`Session.loadedSkillNames` 全部删除（SystemPromptBuilder 已加载段同步删）
- 技能正文消息（pinned）随 messages 自然落盘/恢复，状态单一来源 = 会话历史本身，无并发状态同步问题

### 6. 配置

- `skills.dir` 默认值不变（`./skills`）：部署时技能文件夹复制到程序运行目录；调试期临时改配置指向 `E:/javame/code/skills`（或复制技能到 `./skills`）

## 边界（本设计不解决）

1. **子 agent 不加载技能**：SubAgentLoop.subAgentTools() 剔除 Skill 工具（现有剔除 task/AskUserQuestion 同款模式）。superpowers 模型里子 agent 是纯净执行者——审查维度、实现要求由主 agent 读技能后写进任务描述（技能正文明确要求 never inherit your session's context）。不剔除会出 bug：子 agent 调 Skill 入队到**主** AgentLoop 队列 → 正文污染主会话历史
2. **技能参考文件读取**：ReadTool 已有技能目录读豁免（PathsGuard.errorIfOutside 对 skillsDir 内路径放行），主 agent 填充 code-reviewer.md 等模板畅通，零改动
3. **技能中的 Claude Code 死指令**（plan mode、ExitPlanMode、/loop、CronCreate 等）：靠目录段引导语化解（用 AskUserQuestion 代替审查确认），不改技能内容
4. **技能正文常驻**：豁免压缩是用户决策；技能堆积靠模型判断约束（目录段"匹配才加载" + 工具报告"已在上下文中"）
5. **技能目录为空**（skills.dir 无技能）：Skill 工具返回失败 ToolResult 说明原因，目录段不渲染

## 测试

| 测试 | 断言 |
|---|---|
| SkillToolTest | 正常加载入队；历史已有正文返回"已在上下文中"报告；未知名失败；技能表为空失败 |
| AgentLoopTest | 模型调 Skill 工具 → 下一轮请求消息含 `<skill>` 正文 user 消息（pinned=true，同轮生效，链式衔接固化） |
| SystemPromptBuilderTest | 目录段为路由引导措辞；系统提示词不含已加载技能正文 |
| ContextManagerTest | pinned 技能消息压缩后原样保留、不参与摘要；普通历史照常压缩 |
| CommandDispatcherTest | /skill 入队后下一轮请求生效；/skills 列表不变 |

## 影响面

- LLM 请求新增 function `Skill`（DeepSeek 大小写混合名，AskUserQuestion 先例）；系统提示词删除「已加载技能」段（更短、前缀更稳定）
- `/skill` 手动命令保留，行为改为走注入队列（下一轮生效）
- `/unskill` 不做；`loadedSkills`/`loadSkill()` 删除；Session 无新增字段
- `Message` 新增 `pinned`（旧会话文件兼容：缺字段 → false）
- ContextManager 压缩行为小改（pinned 豁免）
- SubAgentLoop 工具集剔除 Skill
- `config.properties` 无改动；superpowers 文件夹零改动
