# 可插拔工具与只读数据库工具 设计文档

- 日期：2026-09-05
- 状态：待用户审查
- 影响范围：`core/tools/plugin`（新）、`core/tools/db`（新）、`core/tools/browser`、`core/tools/ToolRegistry`、`core/config/Config`、`gui/dialog/SettingsDialog`、`gui/plugin`（新）、`gui/session/SessionManager`、`Main`、`pom.xml`、`src/resource/config.properties`

## 1. 背景与目标

设置窗当前只有「基础设置 / 模型 / MCP / 关于」四页。工具集是硬编码的：`SessionManager.newRegistry()` 在建会话时把 13 个内置工具 + 4 个浏览器工具一次性注册进 `ToolRegistry`，浏览器工具是否加载取决于启动时 `config.properties` 的 `browser.path` 是否为空，运行期无法调整。

本次要做三件事：

1. **可插拔工具框架**：设置窗新增「工具」页（位于 MCP 之后），页内每个工具一行「显示名 + 状态文案 + 启用开关 + 该工具专属的配置入口」。启用/停用**实时生效**于全局所有会话（含正在运行的会话，其下一次请求即生效），生效方式就是「该工具的描述词是否随请求注入」。
2. **浏览器工具纳入框架**：4 个 CDP 工具（`Browser` / `BrowserEval` / `BrowserScreenshot` / `BrowserDebug`）作为第一个插件；浏览器的 5 项配置从 `config.properties` 迁到 `tools.json`，改配置**保存即重建**，不再需要重启。
3. **新增只读数据库工具**：MySQL / PostgreSQL / Oracle 各一个工具，只支持读，**禁用连接池，每次调用新建连接**；每种库有独立的数据源列表（下拉框选「当前数据源」+「数据源管理」弹窗增删改）。

配置统一落在新文件 `jarDir/tools.json`：文件不存在时自动创建，**四个工具全部默认不启用**。

## 2. 需求决策记录（用户已确认）

| # | 决策 |
|---|---|
| 1 | JDBC 驱动三个全部打进 fat jar（MySQL / PostgreSQL / Oracle），开箱即用 |
| 2 | MySQL、Oracle 支持 `query + schema + describe`；PostgreSQL 仅支持 `query`，其 `schema`/`describe` 不执行任何操作、返回固定提示（`describe` 提示用 `SELECT * LIMIT 1` 自行推断；`schema` 说明列出表名在当前环境会报错故禁用） |
| 3 | 查询不弹高危确认窗（`isHighRisk` 恒 false），只读靠三层防护 |
| 4 | 结果限制：`setMaxRows(100)`、字符预算 30000（超出全量落盘 + 返回头部）、`setQueryTimeout(300)` |
| 5 | 结果格式：Markdown 表格 + 元信息行（数据源 / 耗时 / 行数 / 是否截断） |
| 6 | 工具只用「当前选中数据源」，不向模型暴露 `datasource` 参数；当前数据源标识名动态写进工具 description |
| 7 | 数据源管理弹窗需要：测试连接、新建时按类型预填 URL 模板、删除当前选中项时自动回退；密码**明文**存 `tools.json`（与 `model.json` 的 apiKey 一致），不做 Base64 |
| 8 | 浏览器配置迁到 `tools.json` 并**完全实时重建**；`Config` 与 `config.properties` 去掉全部浏览器项；**不做旧配置迁移与兼容**，当全新的做 |
| 9 | 生效机制用**拉模式**：工具常驻 registry，靠 `PluginGate` 在 `schemas()` / `get()` 时按启用状态过滤；不启用的工具其 name/description/parameters 完全不出现在请求中 |
| 10 | 架构用**插件抽象**（`ToolPlugin` 接口 + `ToolPluginManager`），不做声明式字段描述符驱动的通用表单（对数据源管理这类复合交互是过度设计） |
| 11 | 测试不引入 H2；只做纯函数单测，JDBC 执行路径靠手工验证清单 |

## 3. 架构总览

### 3.1 关键前提：为什么必须改 registry 的取用逻辑

`AgentLoop` 每轮请求前都会重新执行 `promptBuilder.build(allSkills)`（系统提示实时拼接）与 `registry.schemas()`（工具表实时拼接）。但 **registry 的内容是会话创建时装配死的**：`newRegistry()` 只在建会话/恢复会话时跑一次，此后除 MCP 连接完成补注册外无人修改。

因此「实时生效」不能靠推模式遍历会话增删工具（要加监听器、要处理「变更时正在跑的那一轮」竞态、新建会话还得再装配一次），而用**拉模式**：工具总是注册进 registry 并打上所属插件标签，registry 持有一个 `PluginGate`（由 `ToolPluginManager` 实现，全局单例、所有会话共享），在 `schemas()` / `get()` 取用时按当前启用状态过滤。改开关 → 无需通知任何会话 → 下一轮取用自动按新状态生效。

### 3.2 组件与数据流

```
tools.json ──load──> ToolStore ──> ToolPluginManager（PluginGate + 配置 + 启用状态）
                                        │                    │
                     ┌──────────────────┼────────────────────┤
                     ▼                  ▼                    ▼
              BrowserPlugin      DbPlugin(mysql)     DbPlugin(postgresql/oracle)
                     │                  │                    │
        createTools(ctx) → Browser/Eval/Screenshot/Debug   DbTool×3
                     │                  │                    │
                     ▼                  ▼                    ▼
        SessionManager.newRegistry：register(pluginId, tool) + registry.setGate(plugins)
                                        │
                                        ▼
        AgentLoop 每轮 registry.schemas()（过滤禁用插件）→ 请求 tools 数组
        AgentLoop 每次 registry.get(name)（禁用返回 null）→ 失败 ToolResult 给模型自调

SettingsDialog「工具」页 ──setEnabled/setCurrent/save/reconfigure──> ToolPluginManager ──> tools.json
```

`BrowserManager` 独立于插件生效链路：它持有 `volatile BrowserSession`，浏览器工具持有 `BrowserManager` 引用（而非 `BrowserSession`），配置改动重建后工具对象无需替换。

### 3.3 提示词残留核查

工具描述的唯一注入通道是 `registry.schemas()`；`SystemPromptBuilder.BUILTIN` 全文不含任何浏览器/数据库工具字样；`SubAgentLoop` 的工具集同样来自 `registry.schemas()`（仅额外剔除 task）。故插件停用后无任何残留注入点。唯一不受本框架控制的是用户自维护的 `project.md` 与技能描述清单（均为项目文档/技能路由，非工具能力声明），本设计不动它们。

## 4. 详细设计

### 4.1 `core/tools/plugin/ToolPlugin`（接口）

```java
public interface ToolPlugin {
    String id();                          // browser / mysql / postgresql / oracle
    String displayName();                 // 浏览器操作 / mysql / postgreSQL / oracle
    String statusText();                  // 页面状态文案（见 4.4、4.5）
    boolean enabled();
    void setEnabled(boolean on);
    List<Tool> createTools(ToolContext ctx);   // 产出工具实例（无条件创建，启停由 gate 决定）
    default void onConfigChanged() { }         // 配置保存后钩子（浏览器插件重建 Chrome）
}
```

- `id()` 同时是 `tools.json` 的顶层键与 registry 里的插件标签，三者一致。
- `createTools` 由 `SessionManager.newRegistry` 每会话调用一次（工具对象会话级，因 `BrowserScreenshotTool` 等携带 `tmpDir`）。
- 插件实现类不依赖任何 JavaFX 类型（GUI 面板在 `gui/plugin`，通过 `ToolPluginManager` 读写同一批配置对象）。

### 4.2 `core/tools/plugin/ToolContext`

```java
public class ToolContext {
    public final Workspace workspace;
    public final String skillsDir;
    public final String tmpDir;              // jarDir/.session/tmp/<sessionId>
    public final ConfirmGate confirmGate;
    public final ToolPluginManager plugins;  // 工具动态读「当前数据源」等运行期状态
}
```

### 4.3 `core/tools/plugin/ToolPluginManager`

```java
public class ToolPluginManager implements ToolRegistry.PluginGate {
    public ToolPluginManager(ToolStore store);      // 内部按 store 内容建 4 个插件
    public List<ToolPlugin> plugins();              // 固定顺序：browser, mysql, postgresql, oracle
    public ToolPlugin plugin(String id);            // 未知 id 返回 null
    @Override public boolean enabled(String pluginId);   // 未知 id → true（不过滤内置/未知）
    public void setEnabled(String id, boolean on);  // 改内存 + save()
    public BrowserManager browserManager();
    public BrowserPlugin browserPlugin();
    public DbPlugin dbPlugin(String id);            // mysql/postgresql/oracle；非 db 插件 id 返回 null
    public void save();                             // 委托 ToolStore
    public void addListener(Runnable onChange);     // 仅供 GUI 面板刷新，不参与生效链路
    public void shutdown();                         // 退出钩子：browserManager.shutdown()
}
```

命名口径：`ToolPluginManager` 上取插件的方法一律 `xxxPlugin()`，`ToolStore` 上取配置对象的方法一律 `xxxConfig()`，避免同名不同返回类型造成混淆。

- `enabled(pluginId)`：`pluginId == null`（内置工具）→ 恒 `true`；插件不存在 → `true`（保守放行，避免拼写错误导致工具全灭）；否则取插件 `enabled()`。
- `setEnabled` 内调用 `plugin.setEnabled` 后 `save()`，再触发 `onChange` 监听（GUI 刷状态文案）。
- 浏览器插件的 `setEnabled(true)` 不需要额外动作（懒启动语义不变）；配置变更走 `onConfigChanged()`。

### 4.4 `core/tools/plugin/ToolStore` 与 `tools.json`

仿 `McpStore`：`jarDir/tools.json`，缺失即生成默认、损坏备份 `.bak` 后重建、原子写（`.tmp` + `Files.move REPLACE_EXISTING`，失败清理 tmp 并打印 `[minion] 写入 tools.json 失败: …`）。

```java
public class ToolStore {
    public static final String FILE_NAME = "tools.json";
    public static ToolStore load(Path jarDir);
    public BrowserConfig browserConfig();
    public DbConfig dbConfig(String id);  // mysql/postgresql/oracle；未知 id 返回 null
    public void save();
}
```

文件结构（gson 直接序列化 POJO，无包裹层）：

```json
{
  "browser": {
    "enabled": false,
    "path": "",
    "port": 9222,
    "userDataDir": "./.minion/browser-profile",
    "headless": false,
    "timeoutMs": 30000
  },
  "mysql":      { "enabled": false, "current": "", "dataSources": [] },
  "postgresql": { "enabled": false, "current": "", "dataSources": [] },
  "oracle":     { "enabled": false, "current": "", "dataSources": [] }
}
```

`dataSources` 元素：`{ "name": "标识名", "url": "jdbc:…", "user": "", "password": "" }`（密码明文）。

- 文件不存在 → 按上述默认值创建，**四项 `enabled` 全 false**、`path` 空、三个 `dataSources` 空数组、`current` 空串。
- 与 `config.properties` **零耦合**：不从 config 读浏览器项，也不把老值迁移过来；老文件里残留的 `browser.*` 行成为无人读取的死行，不清理。
- 反序列化容错：字段缺失取默认值（POJO 字段初始化即默认值）；`dataSources` 为 null 归一化为空列表；`port`/`timeoutMs` 非法（gson 解析异常已在损坏分支处理）。
- `userDataDir` 为相对路径时，按 `Config.jarDir()` 解析（沿用现有 `ChromeLauncher` 调用方口径：`Paths.get(cfg.userDataDir)`，与旧行为一致）。

### 4.5 `core/tools/ToolRegistry` 改造（拉模式核心）

```java
public interface PluginGate { boolean enabled(String pluginId); }

public void register(Tool tool);                       // 等价 register(null, tool)：内置工具永不过滤
public void register(String pluginId, Tool tool);      // 记录 tool → pluginId 归属
public void setGate(PluginGate gate);                  // 由 SessionManager.newRegistry 注入
public Tool get(String name);                          // 禁用插件的工具返回 null
public List<Tool> all();                               // 同样过滤
public List<JsonObject> schemas();                     // 同样过滤（不启用 → 描述词不注入）
```

实现要点：
- 内部保留 `LinkedHashMap<String, Tool> tools`（注册顺序不变）+ 新增 `Map<String, String> ownerOf`（工具名小写 → pluginId，可为 null）。
- 私有 `boolean visible(Tool t)`：`gate == null || ownerOf.get(key) == null || gate.enabled(owner)`。
- `gate == null` 时行为与改造前完全一致 → `ToolRegistryTest` 现有断言与所有既有调用点零改动。
- `all()` 一并过滤是安全的：全仓检索确认 `all()` 当前只被 `ToolRegistryTest` 调用，生产代码无依赖（工具执行走 `get()`，工具表走 `schemas()`）。
- 注册覆盖语义不变（同名后注册覆盖前者），覆盖时同步更新 `ownerOf`。

`AgentLoop` 的工具不存在分支文案由「未知工具」补充为「工具不存在或已停用」（`registry.get()` 返回 null 时），让模型知道该能力当前不可用而非名字写错。

### 4.6 浏览器插件

**`core/tools/plugin/BrowserConfig`**：`enabled/path/port/userDataDir/headless/timeoutMs`（POJO，字段默认值即 4.4 的默认值）。

**`core/tools/plugin/BrowserPlugin implements ToolPlugin`**
- `id()="browser"`、`displayName()="浏览器操作"`。
- `statusText()`：`path` 空 → `未配置浏览器路径`；否则 `<path 文件名> · 端口 <port> · <有头|无头>`（文件名取 `new File(path).getName()`，如 `chrome.exe · 端口 9222 · 有头`）。
- `createTools(ctx)`：4 个工具，构造参数首位由 `BrowserSession` 换成 `BrowserManager`；`BrowserScreenshotTool` 继续接 `ctx.workspace / ctx.skillsDir / ctx.tmpDir / ctx.confirmGate`。
- `onConfigChanged()` → `browserManager.reconfigure(config)`。

**`core/tools/plugin/BrowserManager`**
```java
public BrowserManager(BrowserConfig cfg);
public synchronized BrowserSession session();       // path 空 → null；否则懒建（不拉进程）
public synchronized void reconfigure(BrowserConfig cfg);  // stop 旧 launcher → 换 cfg → session 置 null
public synchronized void shutdown();                // 退出钩子
```
- `session()`：`path` 为空返回 null；否则双检懒建 `new BrowserSession(new ChromeLauncher(path, port, Paths.get(userDataDir), headless, timeoutMs), new CdpClient(10000, timeoutMs))`。构造不启动 Chrome（真正拉起在首次 CDP 调用 `launcher.pageEndpoint()`），故重建代价仅是对象替换 + 旧进程 `stop()`。
- `reconfigure`：若已有 launcher 则 `stop()`（`process == null` 时是空操作，复用外部 Chrome 实例的场景安全），置 `session=null`、`launcher=null`，保存新配置；下次 `session()` 按新配置懒建。
- **代价说明**：重建会关闭 minion 自启的 Chrome（当前已打开的页面丢失）；复用外部实例（非 minion 启动）时 `stop()` 无操作，但 `session` 仍会按新端口重建。

**4 个工具类的改造**：字段 `BrowserSession session` → `BrowserManager browser`；每个 `execute` 首行
```java
BrowserSession s = browser.session();
if (s == null) return ToolResult.error("浏览器未就绪：请在 设置 → 工具 → 浏览器操作 → 配置 中填写浏览器路径");
```
其余逻辑不变（原方法体内的 `session.xxx()` 改为 `s.xxx()`）。

**启用与 path 空的关系**：gate 只判 `enabled`。`enabled=true` 且 `path` 空时工具仍注入，调用返回上面那句明确指引，同时页面 `statusText()` 显示「未配置浏览器路径」——启用语义单一可预期。

**`ChromeLauncher` 文案**：两处提到 `config.properties 配置 browser.path` 的异常消息改为「未找到 Chrome，请在 设置 → 工具 → 浏览器操作 → 配置 中填写浏览器路径」/「Chrome 启动超时(端口 N)，请检查 设置 → 工具 → 浏览器操作 → 配置 中的浏览器路径」。

### 4.7 数据库插件

#### 4.7.1 `core/tools/db/DbType`（枚举）

| 常量 | `id` | `displayName` | 工具名 | 驱动类 | URL 模板（新建预填） | 动作 |
|---|---|---|---|---|---|---|
| `MYSQL` | `mysql` | `mysql` | `DbMysql` | `com.mysql.cj.jdbc.Driver` | `jdbc:mysql://localhost:3306/dbname?useSSL=false&allowPublicKeyRetrieval=true&serverTimezone=Asia/Shanghai` | query, schema, describe |
| `POSTGRES` | `postgresql` | `postgreSQL` | `DbPostgres` | `org.postgresql.Driver` | `jdbc:postgresql://localhost:5432/dbname` | query |
| `ORACLE` | `oracle` | `oracle` | `DbOracle` | `oracle.jdbc.OracleDriver` | `jdbc:oracle:thin:@localhost:1521:ORCL` | query, schema, describe |

枚举另提供 `boolean supports(String action)`、`String driverClass()`、`String urlTemplate()`、`static DbType ofId(String id)`。

#### 4.7.2 `core/tools/db/DataSourceConfig` 与 `DbConfig`

```java
public class DataSourceConfig { public String name, url, user, password; }
public class DbConfig {
    public boolean enabled;
    public String current = "";
    public List<DataSourceConfig> dataSources = new ArrayList<>();
    public DataSourceConfig currentDataSource();   // current 空或找不到 → null
}
```
数据源增删改由 `DbPlugin` 提供方法（内部维护 `DbConfig` 并触发 `manager.save()`）：
`addDataSource / updateDataSource(旧名, 新对象) / removeDataSource(name) / setCurrent(name) / testConnection(name)`。
- `updateDataSource` 改名且旧名 == `current` → 同步 `current`。
- `removeDataSource` 删的是 `current` → 回退到列表第一个；列表空则 `current=""`。
- 标识名唯一性、URL 前缀校验由 `DataSourceValidator`（纯函数）负责，GUI 只弹提示。

#### 4.7.3 `core/tools/db/DataSourceValidator`（纯函数，单测覆盖）

```java
public static String validate(String name, String url, List<DataSourceConfig> all, String originalName);
// 返回 null = 通过；否则返回中文错误原因
```
规则：
- `name` trim 后为空 → 「标识名不能为空」
- `name` 与 `all` 中**其它**项重名（忽略大小写；等于 `originalName` 自身不算）→ 「标识名已存在：<name>」
- `url` trim 后为空 → 「URL 不能为空」
- `url` 不以 `jdbc:` 开头（忽略大小写）→ 「URL 必须以 jdbc: 开头」
- `name` 含 `"` `\` `/` 等文件路径非法字符不拦（标识名不落文件名），但长度 > 40 → 「标识名过长（≤40 字符）」

#### 4.7.4 `core/tools/db/SqlGuard`（纯函数，单测覆盖）

```java
public static String check(String sql);   // null = 放行；否则返回拒绝原因
```
1. `sql` 为 null / trim 后为空 → 「SQL 不能为空」。
2. **剥前导注释与空白**（循环，直到不再变化）：`--…\n`、`#…\n`（MySQL 行注释）、`/*…*/`、空白。防 `/*c*/DROP TABLE t` 绕过。
3. 首关键词（到第一个空白/括号/分号为止，转大写）必须 ∈ `SELECT, WITH, SHOW, DESC, DESCRIBE, EXPLAIN`，否则 → 「只读工具拒绝执行：语句以 <词> 开头（仅允许 SELECT/WITH/SHOW/DESC/DESCRIBE/EXPLAIN）」。
4. **多语句**：去掉末尾 `;` 与空白后，若剩余部分仍含 `;` → 「只读工具拒绝执行：不允许多条语句」。
5. **危险子串**（整词边界匹配、忽略大小写）：`INTO OUTFILE`、`INTO DUMPFILE`、`FOR UPDATE`、`LOCK IN SHARE MODE` → 「只读工具拒绝执行：语句含 <子串>」。

`DESC`/`DESCRIBE` 在 Oracle 上是 SQL*Plus 命令、JDBC 执行会报错，但保留在白名单内（无害，错误由驱动消息透传，MySQL 上可用）。

#### 4.7.5 `core/tools/db/DbExecutor`（每次新建连接，无池）

```java
public class DbExecutor {
    public DbExecutor(Path tmpDir);                       // 落盘目录（会话级）
    public String query(DataSourceConfig ds, DbType type, String sql);
    public String listTables(DataSourceConfig ds, DbType type);      // schema
    public String describe(DataSourceConfig ds, DbType type, String table);
    static Connection open(DataSourceConfig ds, DbType type) throws Exception;  // 包级可见，便于替换/测试
}
```
连接与执行口径（三库统一）：
1. `Class.forName(type.driverClass())` —— 显式加载，不依赖 shade 后的服务发现。
2. `DriverManager.setLoginTimeout(10)`；`Connection c = DriverManager.getConnection(url, user, password)`。
3. `c.setAutoCommit(true)`；`c.setReadOnly(true)`。
4. `Statement st = c.createStatement()`；`st.setMaxRows(101)`（多取 1 行用于判定截断）；`st.setQueryTimeout(300)`。
5. `ResultSet rs = st.executeQuery(sql)` —— 第三层防护。
6. try-with-resources 关 `rs/st/c`：**每次调用新建、用完即关，绝不缓存连接（禁用连接池）**。

结果渲染：
- 前 100 行入表；若取到第 101 行 → `truncated = true`。
- `MarkdownTable.render(columns, rows)`（纯函数）生成表格；元信息行由 `MarkdownTable.header(dsName, elapsedMs, rowCount, truncated, maxRows)` 生成：
  - 未截断：`数据源: prod-mysql · 耗时: 1.24s · 行数: 37`
  - 截断：`数据源: prod-mysql · 耗时: 1.24s · 行数: 100（已达上限 100 行，结果被截断，可加 LIMIT/WHERE 细化）`
- 0 行 → `查询成功，0 行结果`（仍带数据源与耗时）。

`schema` / `describe` 走 **JDBC `DatabaseMetaData`，不拼 SQL**（零注入风险、跨库一致）：
- `listTables`：`metaData.getTables(catalog, schemaPattern, "%", new String[]{"TABLE","VIEW"})`
  - MySQL：`catalog = c.getCatalog()`、`schemaPattern = null`
  - Oracle：`catalog = null`、`schemaPattern = metaData.getUserName()`（不限定会拉出 SYS/SYSTEM 海量对象）
  - 输出列：`表名 / 类型 / 注释`（`REMARKS`）；上限 500 行，超出截断并在末行提示「…（已达 500 行上限，可用 query 精确检索）」
- `describe`：`metaData.getColumns(catalog, schemaPattern, tablePattern, "%")`，`tablePattern` 直接取参数 `table`（含 `%`/`_` 时按模式匹配多表，结果带表名列）
  - 输出列：`表名 / 列名 / 类型 / 长度 / 可空 / 默认值 / 注释`；`长度` 取 `COLUMN_SIZE`（`DECIMAL_DIGITS` > 0 时附 `,精度`）；`可空` 由 `NULLABLE` 映射为 `是/否/未知`
  - 上限 100 行；`table` 空 → 「describe 需要 table 参数」；无匹配 → 「未找到表：<table>」

PostgreSQL 的 `schema` / `describe`：`DbTool` 在调用前直接返回固定提示，**不进 `DbExecutor`、不建连接**：
- `schema` → `postgreSQL 数据源不支持列出表名（当前环境查询系统表会报错），请直接使用 query，例如 SELECT * FROM 表名 LIMIT 1 推断结构`
- `describe` → `postgreSQL 数据源不支持表结构查询，请用 query 执行 SELECT * FROM 表名 LIMIT 1 自行推断字段`

字符预算与落盘（沿用项目现有 30000 口径，同 `GrepTool.DISPLAY_CHARS` / `BashTool` 总预算）：
- 渲染结果 ≤ 30000 字符 → 原样返回。
- 超出 → `OutputDump.write(tmpDir, "db", full)` 全量落盘，返回 `full.substring(0, 30000)` + `\n\n…（完整结果 <N> 字符已落盘：<绝对路径>，可用 Read 查看）`；表格式数据头部比尾部有用，故返回头部（不用 `OutputDump.tail`）。
- 落盘失败（返回 null）→ 降级为纯内存截断，追加 `…（结果过长已截断，共 <N> 字符）`。

#### 4.7.7 `core/tools/db/DbTool implements Tool`

一个类按 `DbType` + `DbPlugin` 参数化，三处实例化（每会话各 3 个对象）。

- `name()` → `type.toolName()`（`DbMysql` / `DbPostgres` / `DbOracle`）。
- `description()` **动态拼接**（每轮实时取值，切数据源无需重建工具）：
  - 有当前数据源：`mysql 只读查询（当前数据源: prod-mysql，jdbc:mysql://10.0.0.5:3306/shop）。action=query 执行只读 SQL 返回 Markdown 表格（最多 100 行）；action=schema 列出表与视图；action=describe 查看表字段。仅允许 SELECT/WITH/SHOW/DESC/DESCRIBE/EXPLAIN，禁止多语句与写操作。`
  - 无当前数据源：`mysql 只读查询（当前未选择数据源，调用会返回提示，请在 设置 → 工具 中选择数据源）。…`
  - PostgreSQL 版本额外写明：`仅支持 action=query；schema/describe 在本类型下不可用，会返回提示，表结构请用 SELECT * FROM 表名 LIMIT 1 自行推断。`
- `schema()`：`SchemaGenerator.objectSchema(描述, new String[]{"action","sql","table"}, new String[]{"action"})`。
- `execute(args)`：
  1. `action` 缺失 → 「缺少 action 参数」；未知 action → 「未知 action: x（支持 …）」
  2. `DbConfig.currentDataSource() == null` → 「<类型> 插件未选择数据源，请在 设置 → 工具 → <显示名> 中选择」
  3. `query`：`sql` 缺失 → 「query 需要 sql 参数」；`SqlGuard.check(sql)` 非 null → 原样返回拒绝原因；否则 `DbExecutor.query`
  4. `schema` / `describe`：PostgreSQL → 固定提示；否则 `DbExecutor.listTables` / `describe`
- `isHighRisk(args)` → 恒 `false`（查询不弹确认窗）。

### 4.9 装配与生效链路

**`Main`**：
```java
ToolPluginManager plugins = new ToolPluginManager(ToolStore.load(jarDir));
```

`plugins` **不走 `MinionApp` 静态注入**：现有 MCP 就是靠 `SessionManager.mcpManager()` getter 暴露给 `MainWindow` 的（`MainWindow.java:370-371`），照此办理 —— `SessionManager` 新增 `public ToolPluginManager plugins()`，`MainWindow` 调用改为

**`SessionManager`**：
- 字段 `BrowserSession browserSession` → `ToolPluginManager plugins`；构造参数同步（`browser` 包 4 个 import 删除，改 import `plugin` 包）。

```java
ToolContext tc = new ToolContext(ctx.workspace, ctx.skillsDir, tmpDirOf(sessionId).toString(),
```

- MCP 注册逻辑不变（`register(tool)` 无标签 → 不被 gate 过滤，MCP 的启停仍由 `McpManager` 自己的 enabled + 注册/断开控制）。

**生效验证点**：改开关后不需要任何会话遍历；`AgentLoop` 下一次 `registry.schemas()` 即反映新状态。运行中会话若正处于「已发出请求、等待响应」阶段，本轮 tools 数组已定型，变更从下一次请求开始生效（符合「实时生效，缓存代价忽略」）。

3. 停用状态下发消息，抓请求确认 `tools` 数组不含 `Browser*` / `Db*`（可用现有 LLM 请求日志或临时打印验证）。
4. 浏览器：勾启用 → 配 path → 保存 → `Browser status` 可用；改 port/headless 保存 → 旧 Chrome 被关闭、新配置生效；取消勾选 → 下一轮 `tools` 数组不再含 4 个浏览器工具；模型若仍调 `Browser` → 得到「工具不存在或已停用」。
5. 三种数据库各配一个真实数据源：`query`（含 NULL 值、超长文本、100+ 行截断）、`schema`、`describe`；PostgreSQL 的 `schema`/`describe` 返回固定提示。
6. 只读防护：对真实库执行 `UPDATE`/`DELETE`/`DROP`/`SELECT 1; DROP TABLE t`/`SELECT … FOR UPDATE` 均被拒且库无变更。
7. 切换数据源下拉框 → 当前会话下一轮工具 description 中的「当前数据源」立即变化（无需新建会话）；运行中会话在下一次请求生效。
8. 数据源管理：新建重名被拦、修改标识名同步下拉框与 `current`、删除当前项自动回退、删空后下拉禁用、测试连接成功/失败两种提示。
9. 重启后 `tools.json` 配置与启用状态保持；手改 `tools.json` 为非法 JSON → 生成 `.bak` 并重建默认。
10. 退出软件 → 自启 Chrome 进程被清理（无残留 chrome.exe）。

## 7. 风险与缓解

| # | 风险 | 缓解 |
|---|---|---|
| 1 | jar 体积 +8–10MB | 已排除 `protobuf-java`；用户已确认接受 |
| 2 | shade 未合并 `META-INF/services/java.sql.Driver` → 驱动自动注册失效 | 加 `ServicesResourceTransformer` + 代码显式 `Class.forName` 双保险 |
| 3 | Oracle `getTables` 不限定 schema → 返回 SYS/SYSTEM 海量对象 | 用 `metaData.getUserName()` 限定 + 500 行上限 |
| 4 | `executeQuery` 在三大驱动上都是「先执行再报错」，单独用会漏写 | 三层防护（SqlGuard 白名单/多语句/危险子串 → `setReadOnly(true)` → `executeQuery`）；README 建议为数据源配只读数据库账号作为最终兜底 |
| 5 | 300s 长查询占住该会话工作线程；`Thread.interrupt()` 不保证中断 JDBC socket 读，点「停止」可能仍等到超时 | 每会话独立线程，其他会话不受影响；`setQueryTimeout(300)` 保证最终释放；文档说明该行为 |
| 6 | 密码明文存 `tools.json` | 用户已确认（与 `model.json` apiKey 一致）；README 提示注意文件权限 |
| 7 | 浏览器配置重建会关闭已打开页面 | 配置弹窗顶部明确标注；用户已确认接受 |
| 8 | MySQL 8 驱动连 5.x 服务端握手失败 | URL 模板预填 `useSSL=false&allowPublicKeyRetrieval=true`；连接失败时透传驱动 message 供排查 |
| 9 | `ToolRegistry` 改造影响既有 13 个内置工具与全部测试 | `register(Tool)` 语义不变（pluginId=null 永不过滤）；`gate == null` 时行为与改造前完全一致 |
| 10 | 三个 `dataSources` 列表可能同名标识跨类型混淆 | 唯一性校验限定在**同一类型内**（mysql 与 oracle 可各有 `prod`），下拉框与 `current` 也按类型独立 |

## 8. 非目标（YAGNI）

- 不做数据库写操作（INSERT/UPDATE/DDL）、不做事务控制、不做导出文件。
- 不做连接池、不做连接复用、不做查询缓存。
- 不做声明式字段描述符驱动的通用配置表单（方案 C，已否决）。
- 不做工具级细粒度权限（如「只允许查某几张表」）、不做 SQL 审计日志。
- 不做 `config.properties` → `tools.json` 的浏览器配置迁移。
- 不新增 SQL Server / SQLite / 达梦等其它数据库类型（框架已可插拔，后续按需加一个 `DbType` + 一个插件实例）。
- 不做数据源密码加密存储。
