# 会话页签懒加载与关闭语义改造 — 设计文档（2026-08-22）

## 背景与目标

当前页签行为与预期不符，共 5 项改造需求：

1. **启动懒加载**：启动时不要为所有历史会话建页签、不打开任何会话；页签栏只反映「启动后打开过的会话」
2. **页签与工作空间解耦**：切换工作空间时页签栏保持不变（当前会 rebuildTabs 重建）
3. **页签 × = 关闭而非删除**：点击 × 关闭页签，会话保留（非运行中直接关闭，运行中弹确认、确认后中断运行再关闭）
4. **关闭后再打开 = 重新加载**：关闭页签即卸载视图缓存，再从左侧列表点击该会话时重建视图、重放历史
5. **跨空间页签可点**：点击旧工作空间的页签时自动切回该空间并打开会话

已确认的事实：切换工作空间不影响后台运行中的会话（各自空间上下文隔离），会话系统提示词中的工作路径在创建时快照，切空间不重建。

## 现状分析

| 位置 | 现状 | 问题 |
|---|---|---|
| `MainWindow.show()` 末尾 `rebuildTabs()` | 启动为所有有标题的历史会话建页签 | 违反需求 1 |
| `onWorkspaceChanged` | `clearChatPane` + `viewCache.clear` + `rebuildTabs` | 违反需求 2 |
| 页签 `onCloseRequest` | 弹确认框 → `manager.deleteSession` 删除会话 | 违反需求 3 |
| `onSessionActivated` | 只显示视图，不建页签 | 历史会话页签依赖启动补齐；改为激活即建页签（需求 1/4） |
| `updateTab` | 页签不存在且 title 非空 → `addTab` | 运行中会话关页签后，running 通知会复活页签 |
| 页签选中监听 | `activateSession(h)`（内部守卫拒绝跨空间） | 违反需求 5 |

## 方案对比

| 方案 | 思路 | 权衡 |
|---|---|---|
| **A（采用）** | MainWindow 维护 `openedIds` 集合标记「已打开会话」（页签存在性唯一权威）；激活即建页签、关闭即卸载；SessionManager 补 1 个方法 + 1 个通知 | 改动集中在 UI 层，符合「页签是 UI 状态」的边界；语义清晰 |
| B | 页签集合挪进 SessionManager 统一管理 | UI 状态下沉 core，过度设计，否决 |
| C | 用现有 `viewCache` 兼作已打开标记 | 切空间清缓存会丢标记；titlePending 会话切空间后不补页签，语义混乱，否决 |

## 详细设计（方案 A）

### 1. MainWindow.java

**新增字段**

```java
/** 已打开会话 id 集合：页签存在性的唯一权威（页签 ⇔ openedIds 含 id）；切工作空间保留 */
private final Set<String> openedIds = new HashSet<String>();
```

**改动点**

1. **删除启动重建**：删除 `show()` 末尾 `rebuildTabs()` 调用、`rebuildTabs()` 方法与 `suppressingTabSelect` 字段（不再有批量重建；启动即无页签、右侧空白占位，天然满足懒加载）。

2. **激活即建页签**：`onSessionActivated` 显示视图后，若 `openedIds` 不含 `h.id` → `openedIds.add(h.id)` + `addTab(h)`（`addTab` 内部已有 title 非空守卫；titlePending 会话等标题生成后由 `updateTab` 补建）。

3. **updateTab 防复活**：`addTab` 分支条件由 `h.title != null` 改为 `h.title != null && openedIds.contains(h.id)`——已关闭页签的会话，其运行状态/标题变化不再重建页签。

4. **页签 × 关闭语义**（`onCloseRequest`，无删除动作）：
   - 非运行中：直接关闭。
   - 运行中：弹确认框（复用现有 Alert 深色样式），文案「会话「标题」正在运行，关闭将中断运行，确认关闭？」；确认 → `manager.stop(h)` 中断运行；取消 → 不做任何事。
   - 关闭流程（确认后）：
     - `openedIds.remove(h.id)`、`viewCache.remove(h.id)`（卸载视图缓存）
     - 移除页签
     - 若该会话正在显示（`chatView.handle() == h`）→ `manager.deactivateSession(h)` + `clearChatPane()`（右侧回空白占位、输入框解绑）
   - 注意：`e.consume()` 必须保留（不触发 TabPane 默认移除），由本流程显式移除。

5. **切工作空间页签不变**：`onWorkspaceChanged` 保留 `clearChatPane` + `viewCache.clear` + `wsList.refresh` + `sessionList.refresh`，删除 `rebuildTabs()`；`openedIds` 不清理（页签保留）。

6. **死页签统一清理**：Listener 新增 `onSessionDeleted(SessionHandle h)` 通知（default 方法），`deleteSession` 与 `deleteWorkspace`（任意空间，含非当前空间）均调用；MainWindow 监听并幂等清理：`openedIds.remove` + `viewCache.remove` + `removeTabById` + 显示中则 `clearChatPane`。删除工作空间的死页签由此覆盖，无需依赖 `onWorkspaceChanged`（它只在删除当前空间时触发）。
   - `SessionListView.onDeleted` 回调保留（现有路径，幂等共存）。

7. **跨空间页签点击**：页签选中监听中，若 `h.workspaceName` 不等于当前空间 → 先 `manager.switchWorkspace(h.workspaceName)` 再 `manager.activateSession(h)`。
   - 时序论证：`switchWorkspace` 同步触发 `notifyWorkspaceChanged`（监听器内 `Platform.runLater` 排队：清 UI/清缓存/刷列表），随后 `activateSession` 触发 `notifyActivated`（`runLater` 排队：显示视图/建页签）。先清后显，最终正确显示目标会话视图（缓存未命中 → 重建重放）。
   - `activateSession` 的 `deleted` 守卫与 `workspaceName` 守卫（切换后已相等）均保留。

8. **删除会话联动**（左侧 ✕ 删除）：现有 `onDeleted` 回调补 `openedIds.remove(h.id)`（当前已有 `removeTabById` + `viewCache.remove` + 必要时 `clearChatPane`）；`onSessionDeleted` 通知路径幂等共存。

### 2. SessionManager.java（新增 1 个方法 + 1 个通知）

```java
/** 取消激活态（关闭激活中会话的页签时调用）。
 * UI 已卸载该会话视图，但 currentSession 仍指向它——activateSession 的幂等守卫
 * （currentSession == h 直接 return）会挡住用户从左侧再次打开，故须置空。 */
public void deactivateSession(SessionHandle h) {
    if (currentSession == h) {
        currentSession.controller.eventList().setActive(false, null);
        currentSession = null;
    }
}
```

Listener 接口新增（default，不破坏现有实现）：

```java
/** 会话被删除（deleteSession / deleteWorkspace 均通知）：UI 清理页签与缓存 */
default void onSessionDeleted(SessionHandle h) { }
```

`deleteSession` 与 `deleteWorkspace` 在置 `deleted` 后对每个被删会话调用 `notifySessionDeleted(h)`。

## 行为矩阵（验收标准）

| 操作 | 行为 |
|---|---|
| 启动 | 无页签、右侧空白占位（懒加载） |
| 左侧点击会话 | 激活 + 重建视图重放历史 + 建页签 |
| ＋新建会话 | 激活 + 显示；标题生成后自动建页签 |
| 页签 ×（非运行中） | 直接关闭：移除页签 + 卸载视图缓存；激活中则右侧回空白；会话不删除 |
| 页签 ×（运行中） | 弹确认框；确认 → 中断运行 + 关闭页签；取消 → 无操作 |
| 关闭后再点左侧 | 重新加载（重建 ChatView，全部历史重放） |
| 切工作空间 | 右侧清空、视图缓存清空；页签栏保持不变 |
| 点旧空间页签 | 自动切回该空间并打开会话（后台运行中会话不受影响） |
| 左侧 ✕ 删除会话 | 移除页签 + 卸载缓存 + 删除会话 |
| 删除工作空间（任意空间） | 指向已删会话的死页签经 onSessionDeleted 通知清理 |

## 边界情况

- **运行中会话关页签**：确认后 `stop(h)` 中断；`running=false` 通知因 `openedIds` 已移除不会复活页签；会话保留在列表，可从左侧重新打开（中断后历史消息保留）。
- **titlePending 新会话**：标题未生成前无页签（`addTab` 守卫）；标题生成后 `updateTab` 因 `openedIds` 含 id 自动补建。
- **切空间时序**：`switchWorkspace` 的 UI 清理（runLater）先于激活显示（runLater），顺序正确。
- **重复激活幂等**：`activateSession` 的 `currentSession == h` 守卫不变，页签选中/左侧点击重叠无闪烁。
- **重命名工作空间**：`renameWorkspace` 触发 `onWorkspaceChanged`，页签保留（会话仍存活，仅 workspaceName 同步），死页签清理不受影响。
- **删除会话竞态**：`activateSession` 的 `h.deleted` 守卫保留。

- 页签 GUI 行为：手动验证清单（按行为矩阵逐项执行，重点：启动无页签、切空间页签不变、× 关闭后左侧重开、运行中 × 弹窗中断、跨空间页签自动切空间）。
- 回归：`mvn compile` + `mvn test` 通过；README/相关设计文档同步说明页签新语义。

## 影响面与风险

- 改动集中于 `MainWindow.java`（页签/激活/工作空间监听）与 `SessionManager.java`（1 个新方法 + 1 个 default 通知方法），无 core 层行为变化。
- 风险点：跨空间页签点击的 runLater 时序（设计已论证）；`onSessionDeleted` 与 `SessionListView.onDeleted` 双路径清理需幂等（已设计为幂等）。
- 低风险，无需灰度。
