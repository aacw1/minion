# 2026-08-14 UI 优化 5 项设计

## 背景

GUI 使用体验优化，共 5 项：侧栏激活微亮框、页签行固定、输入框加高上移、删除分区标题文案、最大化不挡任务栏。全部为 JavaFX 8（JDK 自带 jfxrt）纯界面改动，不涉及 core 逻辑。

## 需求与设计

### 1. 侧栏列表条目激活时背景微亮（参考页签 selected 效果）

**现状**：`.list-view .list-cell:selected` 背景 `#2a3344`；页签 selected 背景 `#232a38`（`.tab-pane .tab:selected`）。会话列表选中态可能与激活态不同步（如删除会话后刷新列表不重选）；工作空间列表 refresh 时已 `select(currentName())` 同步。

**设计**：
- `theme.css`：`.list-view .list-cell:selected` 背景改为页签同款微亮色 `#232a38`，未选中条目不变
- `SessionListView.refresh()` 增加 `select(manager.currentSession())`，使选中=激活，微亮框即激活指示

### 2. 正文上方页签行固定一行（消息增多时不再消失）

**根因（已用探针复现验证）**：消息增多 → `ScrollPane` 的 prefHeight 随内容增长（ScrollPaneSkin.computePrefHeight 基于内容）→ 右侧 VBox 空间不足 → 布局把非 vgrow 节点（tabsBar/inputView）压缩到 min → tabsBar 被压扁至 ~5px（一条线），即"页签消失"。ScrollPane 的 minHeight 是固定的（36，不随内容），TabPane 尺寸也固定，均非根因。

**修复**（探针验证：500 消息/30 会话下 tabsBar 恒 33px、聊天区撑满无空白）：
- `MainWindow`：`chatScroll.setPrefHeight(200)` 固定 pref（chatScroll 为 vgrow，实际高度仍由剩余空间分配，pref 只影响父级行高计算）
- `MainWindow`：GridPane 加 `RowConstraints vgrow=ALWAYS`，行撑满可用空间，防止 pref 固定后底部留白

### 3. 输入框加高一行、上移半行

**设计**（`InputView`）：
- `input.setPrefRowCount(2)` → `3`（加一行）
- 外层 `setPadding(12, 16, 12, 16)` 底部 12 → 0（半行 ≈ 12px，输入区整体上移半行）
- `setMaxHeight(6 * 24)` 不变（3 行仍在上限内，无需调整）

### 4. 删除「会话管理/工作空间」分区标题文案

**设计**（`MainWindow`）：
- 删除 `sessionTitle`（"会话管理"）、`wsTitle`（"工作空间"）两个 Label 及 `section-title` 样式类在此处的使用
- 侧栏子节点变为：`[＋新建会话, 会话列表, ＋新建工作空间, 工作空间列表]`，VBox(8) 间距自然分隔上下两区，不另加分隔线

### 5. 最大化时不挡 Windows 任务栏（给任务栏留一行）

**现状**：无边框窗口 `stage.setMaximized(true)` 在 Windows 上会覆盖任务栏。

**方案选择**：
- 方案 A（采用）：手动最大化——记录还原 bounds，最大化时 `setX/Y/Width/Height` 到 `Screen.getPrimary().getVisualBounds()`（系统已排除任务栏区域）；自管理 `maxed` 标志；TitleBar 的 □ 按钮与双击标题栏统一走此逻辑；图标同步（❐/□）
- 方案 B（不采用）：保留 `setMaximized` + 监听修正——窗口管理器会再次调整，不可靠

**设计**（`TitleBar`）：
- 新增 `maxed` 标志 + 还原 bounds 记录
- □ 按钮与双击标题栏改为调用 `toggleMaximize()`：未最大化 → 记录当前 bounds、窗口移到 `visualBounds`；已最大化 → 还原记录 bounds
- 移除 `stage.maximizedProperty` 监听（第 45 行，随旧逻辑一并删除）
