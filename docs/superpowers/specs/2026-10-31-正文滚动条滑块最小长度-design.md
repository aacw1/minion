# 正文滚动条滑块最小长度修复

日期：2026-10-31
状态：已实施（2026-10-31，真实 JavaFX 探针 + 全量 1314 项测试通过）

## 现象

用户报告：正文（消息区）右侧的竖向滚动条「只剩一个点，太小」——长会话/长工具输出后，
滑块缩到 1~2px，既看不出当前滚动位置，也无法用鼠标抓住拖动。

## 根因

JavaFX 8 `ScrollBarSkin` 的滑块长度计算（`com/sun/javafx/scene/control/skin/ScrollBarSkin.java`）：

```java
// layoutChildren（纵向）
trackLength = snapSize(h - (decHeight + incHeight));
thumbLength = snapSize(Utils.clamp(minThumbLength(), trackLength * visiblePortion, trackLength));
// minThumbLength
double minThumbLength() { return 1.5f * getBreadth(); }
// getBreadth（纵向）
return Math.max(decButton.prefWidth(-1), incButton.prefWidth(-1)) + snappedLeftInset() + snappedRightInset();
```

滑块长度本有「最小 1.5×breadth」保护，但 `breadth` 取的是**两端箭头按钮**的 prefWidth，
而箭头按钮的 prefWidth = 按钮内边距 + 箭头（Region）内边距宽度。本主题为了隐藏两端箭头，
把两者尺寸都归零：

```css
.scroll-bar .increment-button, .scroll-bar .decrement-button { -fx-padding: 0; }
.scroll-bar .increment-arrow, .scroll-bar .decrement-arrow { -fx-shape: " "; -fx-padding: 0; }
```

于是 `breadth = 0` → `minThumbLength = 0`，最小长度保护完全失效；内容极高时滑块只剩
`轨道长 × 视口高/内容高`，低至亚像素，被 `snapSize` 取整后表现为一个点。

FX 探针实测（54000px 内容 / 618px 视口，真实 `theme.css`）：

| 状态 | 竖向条 | 滑块 | breadth（minWidth） |
| --- | --- | --- | --- |
| 修复前 | 9×620 | 9×**8** | 0 |
| 修复后 | 9×620 | 9×**30** | 20 |

真实会话段数上限 200、工具输出可上万像素，内容高度可达数十万像素，滑块会进一步缩到 1~2px。

## 修复

纯 CSS（`src/resource/theme/theme.css`）：给**不可见**的箭头按钮补「垂直于轨道」的内边距，
把 `breadth` 撑到 20px，从而让 JavaFX 自带的 `minThumbLength` 生效为 30px：

```css
.scroll-bar:vertical > .increment-button, .scroll-bar:vertical > .decrement-button { -fx-padding: 0 10 0 10; }
.scroll-bar:horizontal > .increment-button, .scroll-bar:horizontal > .decrement-button { -fx-padding: 10 0 10 0; }
```

- 纵向条：水平内边距 10+10 → breadth 20 → 滑块最小 30px；按钮高度仍为 0（垂直内边距 0），
  箭头 shape 为空，不产生可见绘制。
- 横向条：垂直内边距 10+10 → breadth 20 → 滑块最小 30px；按钮宽度仍为 0，不占轨道长度。
- 条宽/条高仍由 `-fx-pref-width/-fx-pref-height: 9px` 固定，**不随 breadth 变化**（探针实测 9px），
  因此不影响 `MessageTextArea.INNER_SLOT`（内部滚动条槽位 12px）的测量假设。
- 滑块位置/拖拽仍由 JavaFX 原生皮肤计算：`thumbLength` 字段已按最小长度参与
  `positionThumb` 与拖拽换算，贴底时滑块底边 = 轨道底边（探针：ty=609、h=30、轨道高 640）。

## 不采用的方案

- **`.thumb { -fx-min-height: 30; }`**：`ScrollBarSkin.layoutChildren` 直接 `thumb.resize(w, thumbLength)`，
  `Region.resize` 只写 width/height，绕过 min/max 约束 → 无效。
- **自定义 `ScrollBarSkin`**：`minThumbLength()` 是包级私有方法；`jfxrt.jar` 由 JDK ext
  classloader 加载，应用侧类即使声明同一包名也属不同 runtime package，无法覆写（JVM 包访问按
  classloader 隔离）。在 `layoutChildren` 里事后钳制则与皮肤私有的 `thumbLength` 字段冲突：
  `positionThumb()`（值变化时调用）和拖拽换算仍按旧的小长度算，滑块会越出轨道/拖动错位。
- **加宽滚动条**（9→12px）：会改变 TextArea 内部 wrap 槽位，需同步校准 `INNER_SLOT` 并回归长文本
  高度自适应，改动面大于收益；本次只解决「点状滑块」。
- **在 MainWindow 里监听 visibleAmount 强行改大**：`ScrollPaneSkin.updateVerticalSB()` 每次布局都会
  重算 visibleAmount，监听器反改会触发无限布局循环。

## 影响面

- 全部竖向/横向滚动条（正文消息区、列表、文本区内部等）滑块最小长度 30px；条宽/条高不变。
- 隐藏箭头按钮的 prefWidth/prefHeight 变大，但沿轨道方向尺寸为 0，不占轨道长度、不绘制；
  不可见滚动条不参与布局。
- `minWidth/minHeight` 变为 20/42，但 `ScrollPaneSkin`/`VirtualFlow` 均按 pref 尺寸布置滚动条，
  探针实测竖条仍为 9px 宽。
