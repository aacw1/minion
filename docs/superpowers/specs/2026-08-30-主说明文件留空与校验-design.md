# 设计：主说明文件留空语义与路径校验

日期：2026-08-30　状态：已实施（用户确认方案 2「取消兜底」后落地）

## 需求

1. 无 `workspace.json` 首次启动时生成的 `default` 空间，「项目主说明文件」一栏**留空**（不再预置 `./project.md`）。
2. 主说明文件**填了才校验**：必须指向一个已存在的文件；路径不存在或指向文件夹 → 相应报错。

## 关键决策：取消「留空 = `<项目路径>/project.md`」的隐式兜底

原行为（`WorkspacePaths.projectMd`）：`projectMd` 未配置时回落到 `<项目路径>/project.md`。
两处毛病：

- 界面「留空」与实际是否注入取决于磁盘上是否碰巧有那个文件，用户在表单里看不出差别；
- 兜底路径天生可能不存在，core 无法用「填了才校验」的统一口径处理它，需求 1 也就无法真正生效
  （预置 `./project.md` 与留空在旧语义下等价，改不改没区别）。

用户选定方案 2：**留空即完全不注入主说明文件**。代价是既有依赖兜底的配置行为变化（本次会话内确认接受），
同步改动 README 与 `WorkspacePathsTest` 的既有用例。

## 改动点

| 位置 | 改动 |
| --- | --- |
| `WorkspaceManager.load` | default 条目 `projectMd` 由 `"./project.md"` 改为 `null` |
| `WorkspacePaths.projectMd` | 去掉 `<项目路径>/project.md` 回落；未配置（null/空白）返回 `null` |
| `WorkspacePaths.isExistingFile` | 新增：口径同 `isExistingDir`（相对按 baseDir 解析，非法字符不抛，空白/不存在/是文件夹一律 false） |
| `WorkspaceManager.pathsUsable` | 新增主说明文件校验：`null` 合法；填了必须是已存在文件。`add`/`update` 共用，界面与 API 同一口径 |
| `SystemPromptBuilder.loadProjectMd` | `path` 为 null/空白直接返回空串（`projectMd()` 现在会返回 null，防 `Paths.get(null)` NPE） |
| `WorkspaceFormDialog` | 点击「确定」时按 `notAFileMessage` 校验，**区分两种原因**分别弹框：「该路径是文件夹」/「文件不存在」；提示里给出按项目路径解析后的绝对路径 |
| README / ARCHITECTURE | 留空语义、default 空间字段、校验规则同步 |

## 校验矩阵（core 与界面一致）

| 主说明文件填写 | 结果 |
| --- | --- |
| 留空 / 纯空格 | 通过，落盘存 `null`，提示词不含「项目介绍」段 |
| 指向已存在文件（绝对或相对 `<项目路径>` 写法） | 通过，落盘存原样写法 |
| 指向不存在的文件 | 拒绝：界面弹框「项目主说明文件不存在：…」，core `add`/`update` 返回 false 且不落盘 |
| 指向文件夹 | 拒绝：界面弹框「…必须是一个文件，但该路径是文件夹：…」，core 同上 |
| 含非法字符 | 拒绝（`isExistingFile` 不抛，判 false） |

注：`load` 不校验历史数据——手改或旧版 `workspace.json` 里的失效路径不会阻止启动，
只在下次 `add`/`update` 该空间时要求修正。
