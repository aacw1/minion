# 四问题修复：确认键防重、工具参数解析、聊天区滚屏、SQL 只读误判

日期：2026-09-13
状态：已实施（四项方案均经用户确认；滚屏容差按用户要求放宽到 2 屏）

## 背景与问题

用户报四个线上问题，逐一根因定位如下（修复前均先复现）。

### 1. 连按两下确认键，整个流程被终止

现象：回答模型提问 / 发送消息后，紧接着再按一次 Enter，当前会话运行直接中止。

根因：发送后输入框被 `clearComposer()` 清空、会话仍在运行，此时 `InputView.buttonMode`
判定为 `STOP`（运行中 + 空输入 = 终止），第二次 Enter（或按钮连点）经同一 `onAction`
直接落到 `manager.stop(current)`。第一次动作与第二次按键共用一条路径，没有任何去抖。

### 2. 提问工具频繁报「工具参数 JSON 解析失败: ... Use JsonReader.setLenient(true)」

现象：`AskUserQuestion` 调用偶发整段参数作废，报 MalformedJsonException（line 1 column 435）。

根因：`JsonParser.parseString` 读完第一个 JSON 值后，会用**非 lenient** 的 reader 再检查
「文档是否消费完」；arguments 在完整 JSON 值之后带任何尾部杂讯（多余 `}`、中文标点、
markdown 反引号、第二个 JSON 等，探针实测 13 种全部复现）即抛异常。模型侧的真实 JSON 内容
（含 `AskUserQuestionTool.normalize` 自身很强的容错）因此根本没机会执行。

### 3. 聊天区滚屏不跟随 / 中途停止

现象：长工具输出、长回复、提问段之后，消息区停在中途不再跟随；回复结束也不回底。

根因：`AutoScrollPolicy` 贴底容差只有「半屏」（eps = 0.5×视口高/可滚动行程），单次内容
增长超过半个视口的像素量时，vvalue 距底距离瞬间超出容差，被 `vvalue` 监听判成「用户主动
上滚」而**永久停跟**（此后内容再增长也不恢复）；且回复结束（STATS 行）、工具提问时没有
强制置底；`setVvalue(1.0)` 在 vvalue 已是 1.0 时是 no-op，视口不因内容变高重新定位。

### 4. PostgreSQL 含 replace 关键字被误判为写操作

现象：`SELECT COALESCE(replace(name,'a',''),'x')` 等合法只读查询被拒。

根因：`SqlGuard.checkDmlPositions` 对「紧跟 `(` 或 `)` 的首个词」命中 `DML_HEADS`
（含 REPLACE/INSERT 等）即拒。该检查本为堵 WITH 起手的两条写通道（改写型 CTE、
`WITH … DELETE`），但没区分「函数调用」：`replace(`、`max(replace(`、`(replace(`
全被误杀（三库共用同一 SqlGuard，MySQL/Oracle 一并受影响）。

## 修复方案

1. **确认键防重（InputView）**：新增 `shouldIgnoreTrigger(mode, now, lastSendActionMs, guardMs)`
   纯函数与 `STOP_GUARD_MS = 500`；`onAction` 只在真正发出 SEND/SUPPLEMENT/ANSWER 时记录
   时刻，STOP 触发若距上次发送类动作不足 500ms 直接忽略（判为重复按键）。防抖只挡 STOP，
   连发消息/连续回答不受影响；从未发送过（lastSendActionMs=0）时终止照常可用。
2. **工具参数宽松解析（ToolArguments）**：新增 `com.minion.core.llm.ToolArguments.parse`，
   用 `JsonReader.setLenient(true)` + `JsonParser.parseReader` **只读第一个完整 JSON 值、
   不检查尾部**——尾部杂讯丢弃，值内部的真畸形（截断、非法转义）照旧抛异常报给模型重发。
   `AgentLoop`、`SubAgentLoop` 两处解析统一改走该方法。
3. **滚屏**：`MainWindow.FOLLOW_SCREENS` 由 0.5 放宽到 2.0（`followEps` 纯函数抽算）；
   `contentGrew` 回调按增长后的新行程重算贴底（单次大段增长不再被旧容差误判为离开底部）；
   AskUserQuestion 的工具调用事件与每轮结束的 STATS 事件触发 `scrollBottomRequest`
   （forceFollow + 双 runLater 置底）；置底前若 vvalue 已是 1.0，先设 0.999999 再设 1.0，
   防 `setVvalue(1.0)` no-op。
4. **SQL 校验（SqlGuard）**：`checkDmlPositions` 增加函数调用例外——词后（跳过空白）紧跟
   `(` 视为函数调用放行；语句位上的 DML 后只跟表名/INTO，故 `WITH … (REPLACE INTO …)`、
   `REPLACE INTO`、`WITH … DELETE` 等真写通道照旧拦截。

## 测试与验证

新增/扩展单测（全部通过，全量 1073 个用例 0 失败）：

- `ToolArgumentsTest`（11 例）：尾部多余括号/中文标点/第二个 JSON/反引号、未转义换行、
  单引号裸键、空输入、截断报错、非对象报错；
- `SqlGuardTest` 增 2 例：`replace(...)`/`insert(...)`/嵌套函数调用放行（10 条合法 SQL）、
  `WITH … REPLACE INTO` 与 `REPLACE INTO` 仍拒；原有 45 例（含 `SqlGuardTest:428` 用例）全过；
- `InputViewButtonTest` 增 5 例：防抖窗口内忽略、窗口外执行、边界严格小于、无发送史可终止、
  发送类动作不受限；
- `MainWindowFollowEpsTest`（4 例）：容差公式、未超一屏恒贴底、2 屏 vs 0.5 屏对照。

手工验收（GUI）：连按 Enter 不终止、提问/回复结束自动回底、长输出过程跟随、PG 的
`replace()` 查询可执行。
