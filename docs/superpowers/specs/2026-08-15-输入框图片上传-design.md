# 输入框图片上传设计

日期：2026-08-15
状态：已确认（用户审阅通过前为草案）

## 背景与问题

输入框目前只能发文本（/命令、@文件、粘贴长文本块）。用户希望上传图片让模型直接看图（如截图问问题）。

现状约束：

- `Message.content` 是纯字符串，`toApiJson()` 只输出字符串 content；OpenAI 兼容视觉协议要求 `content` 数组（`text` + `image_url`）。
- 默认模型 deepseek-v4-flash、qwen3-max 均不支持视觉；仅用户自配的 qwen-vl 系列支持看图。
- 会话经 Gson 持久化（`SessionStore.save`），新字段自动落盘。

## 目标

- 输入框新增「上传图片」按钮，图片以块（chip）形式加入输入区，随消息发给模型（OpenAI 标准 `content` 数组格式，qwen-vl 原生支持）。
- UI：输入框底部加一行——上传按钮在左下，发送按钮移到右下；发送按钮背景由蓝（btn-primary）改红（btn-danger），与停止按钮同风格。
- 图片随会话持久化，重启后仍能回传模型。

## 非目标

- 不在聊天区渲染图片本体（仅文件名占位，用户已确认）。
- 不做模型视觉能力检测/拦截（照发，API 报错自然展示，用户已确认）。
- 不做图片压缩/缩放/编辑。
- 不支持拖拽粘贴图片、剪贴板直接粘贴图片（仅按钮 + FileChooser）。
- 回答（ANSWER）模式不支持带图（见「各路径行为」）。
- 不做像素级图片 token 精确计算（每图固定 500 粗估）。

## 关键约束

- **JDK 8**：JavaFX 8 FileChooser 可用；无新依赖。
- **零回归**：无图时 `toApiJson()` 输出与现状完全一致（content 纯字符串）。
- **上限**：单张 ≤5MB，每条消息最多 3 张（用户已确认）。

## 数据模型

### ImagePart（新增，core/llm 包，与 Message 同包）

```java
public class ImagePart {
    public String mime;    // image/png 等（上传时由文件后缀推断）
    public String base64;  // 纯 base64 数据（不含 data: 前缀）
    public String name;    // 原始文件名（chip 与聊天区占位展示用）
}
```

### Message 扩展（core/llm/Message.java）

- 新增字段 `public List<ImagePart> images;`（仅 user 消息使用，其他角色忽略）。
- 新增工厂 `Message.userWithImages(String text, List<ImagePart> images)`。
- `toApiJson()` 分支：user 消息带图（images 非空）时 content 输出数组：

```json
"content": [
  {"type": "text", "text": "…"},
  {"type": "image_url", "image_url": {"url": "data:image/png;base64,<base64>"}}
]
```

无图时保持现状（`o.addProperty("content", content)`），现有测试零影响。

### InputChip 扩展（gui/input/InputChip.java）

- 新增 `Type.IMAGE` 类型；`content` 存 base64（含 `data:<mime>;base64,` 前缀，图片通道直接使用）；`display` = `图片：<文件名>`。
- `compose()` 组装文本时跳过 IMAGE 块（图片走独立通道，不进入文本）。

## UI 布局

输入大框（frame）从单行 HBox 改为上下两层 VBox：

```
┌─────────────────────────────────────┐
│ [chip行: @文件 / 图片:截图.png]       │
│ [          输入框 textarea      ]    │
├─────────────────────────────────────┤
│ 📎 上传图片            [⇧ 发送]      │  ← 新增底部行
└─────────────────────────────────────┘
```

- frame = VBox{ composer（chip行+输入框），bottomRow }。
- bottomRow = HBox{ 上传按钮，Region 弹性空白（Hgrow ALWAYS），发送按钮 }。
- **竖分割线删除**（`.input-divider` 不再使用，CSS 保留不删亦可）。
- **上传按钮**：回形针 SVGPath + 半透明幽灵风格（新样式类 `.btn-upload` / `.icon-upload`，参照 btn-ghost）；点击弹 FileChooser，过滤器 `*.png *.jpg *.jpeg *.gif *.bmp *.webp`。
- **发送按钮**：`applyStyle` 中 SEND/SUPPLEMENT/ANSWER 三态背景类由 `btn-primary` 改为 `btn-danger`（红色）；STOP 仍 `btn-danger`——发送与停止同色，靠图标（箭头/方块）区分。
- **图片 chip**：复用现有 chip 机制（chipRow + ✕ 删除 + Backspace 删最后一个块），样式类 `.input-chip-image`。

## 限制校验（点击上传时）

- 单张 >5MB → 聊天区提示「图片超过 5MB，拒绝上传」。
- 已有 3 张再传 → 提示「最多上传 3 张图片」。
- 文件读取出错 → 提示「读取图片失败: <原因>」。
- 校验失败不中断输入，也不清空输入区。

## 发送链路

```
InputView（IMAGE chip → List<ImagePart>）
  → composedPayload()：{文本, List<ImagePart>}
  → SessionManager.send(h, text, images)
  → AgentLoop.runUserTurn(text, images)
  → Message.userWithImages(text, images)
  → toApiJson() → content 数组 → LLM
```

- `InputView`：新增 `composedImages()`（遍历 chips 收集 IMAGE 块 content → ImagePart 列表，解析 `data:<mime>;base64,` 前缀拆 mime/base64）。
- `SessionManager.send`：新增 `send(SessionHandle h, String text, List<ImagePart> images)` 重载；原方法委托新方法传 null（零回归）。
- `AgentLoop.runUserTurn`：新增带 images 重载；内部 `Message.user(input)` 改 `Message.userWithImages(input, images)`（images 为空时等价，行为不变）。

## 各路径行为

| 路径 | 行为 |
|------|------|
| 发送（SEND） | 图片随新消息发送 ✅ |
| 补充（SUPPLEMENT） | `sendSupplement`/`offerSupplement` 增加 images 参数，补充消息带图，合并进下一轮 user 消息时图片一并带上 ✅ |
| 回答（ANSWER） | v1 不支持：输入区有图时点击发送 → 聊天区提示「回答模式暂不支持图片」，不发送 |
| 终止（STOP） | 不变（无文本/图片概念） |

## 聊天区展示

- USER_MESSAGE / USER_SUPPLEMENT 事件文本在事件生成层拼入占位：`图片：<文件名> ` 前缀（多张按顺序拼接，与文本用空格分隔）。ChatView 零改动，不渲染图片本体。

## 持久化

- Gson 自动序列化 Message.images（base64 随会话 JSON 落盘；受 5MB×3 上限约束，体积可控）。
- 恢复会话后 images 原样读回，历史回传 LLM 时图片自动带上（重启后模型仍能看图）。

## 上下文压缩与 token 统计

- **ContextManager 无需改动**：压缩按完整回合链切块，带图消息的文本照常进入摘要批次（图片数据不参与摘要，历史摘要不需要图片）；最近 keepRecent 条原样保留（含图）。
- **TokenCounter**：带图消息 token = 文本 token + 每图固定 500 粗估（防压缩阈值低估）。

## 错误处理

- 模型不支持视觉：不拦截照发，API 报错 → `LlmException` → 现有 `notifyError` 路径展示到聊天区。
- 图片上传/读取失败：聊天区提示（见「限制校验」），不打断输入。
- ANSWER 模式带图：提示后取消发送。

## 测试

- `InputChipTest`（或现有 chip 测试扩展）：IMAGE 类型 `compose()` 跳过图片块；display 格式。
- `MessageTest` 扩展：`toApiJson()` 带图输出 content 数组断言（含 data URI 格式）；无图时输出纯字符串（零回归保护）。
- `InputViewButtonTest`：SEND/SUPPLEMENT/ANSWER 应用 `btn-danger`。
- `SessionManager` 发送链路：带图 send 落库消息含 images（mock 层验证）。
- 手动验证：qwen-vl 模型真实发送一张截图，确认模型能描述图片内容。
