# 临时文件迁移到 .session/tmp/<会话id>/ 设计

日期：2026-08-27
状态：待审查

## 背景与问题

工作空间（`.minion/tmp/`）会积累工具运行产生的临时文件，污染用户代码目录：

1. **工具超限输出落盘在工作空间内**：`OutputDump` 将 Bash/Grep 超限输出写入 `<workDir>/.minion/tmp/`，用户代码目录出现 `.minion/tmp/` 目录与 `bash-*.txt`/`grep-*.txt` 文件。
2. **模型可能在工作空间创建临时文件**：提示词未约束，模型（LLM）可能把调试输出、中间结果直接写在当前工作目录。
3. **nul 文件（实测）**：模型按 Windows 习惯写 `> nul` 丢弃输出，但 Bash 工具在 Git Bash（MSYS）环境执行——MSYS 不把 `nul` 映射为设备（只有 `/dev/null` 是设备），`> nul` 被当作普通文件名，在工作目录创建真实的空 `nul` 文件。提示词未说明环境，模型无从避免。

## 设计目标

1. **工作空间零临时文件**：工具超限落盘与模型自建临时文件统一迁移到 jar 运行目录的 `.session/tmp/<会话id>/`。
2. **按会话隔离**：多会话并行时落盘互不干扰；删除会话时该会话的临时文件一并清除。
3. **提示词引导**：明确临时文件位置与 Git Bash 环境规则（`/dev/null` 而非 `nul`）。
4. 约束：**不超限不落盘**行为不变；落盘功能（防上下文爆炸 + 全量可回溯）不变，仅搬家。

## 现状

- `OutputDump`：静态工具类，`dumpDir(workDir)` 返回 `<workDir>/.minion/tmp/`；`write`/`tail`/`cleanup`/`workDirRelative` 全部基于 workDir。被 BashTool（超限落盘）、GrepTool（超限落盘）与 Main（启动清理）使用。
- 工具构造：`newRegistry(ctx)` 每会话调用（每个会话独立 ToolRegistry），但工具构造参数为空间级对象（workspace/skillsDir/gate），**无会话 id**。
- 路径守卫：`PathsGuard.errorIfOutside(workDir, skillsDir, p)` 只放行工作空间与技能目录；ReadTool/WriteTool/EditTool/GrepTool/GlobTool/BrowserScreenshotTool 均使用。
- 会话 id：`yyyyMMdd-HHmmss-SSS-NNNN`（毫秒+自增序号），无非法字符，可直接作目录名。
- 删除链路：`SessionManager.deleteSession` 只删 `jarDir/session/<ws>/<id>.json`；`deleteWorkspace` 删除空间所有会话；Main 启动时按工作空间清理 `.minion/tmp/` 修改超 3 天旧文件。

## 方案细节

### 目录结构

- 临时根目录：`jarDir/.session/tmp/`（与现有 `jarDir/session/` 会话落盘并列，互不影响）。
- 每会话一个子目录：`.session/tmp/<sessionId>/`。
- 落盘文件命名沿用现有：`bash-<时间戳>-<序号>.txt`、`grep-<时间戳>-<序号>.txt`。
- Bash 执行用的 pid 探针/命令脚本**保持系统临时目录不动**（`File.createTempFile` + deleteOnExit）：不污染工作空间、执行完即删、系统 temp 对当前用户读写执行权限完整；迁入会话目录反而会与"删除会话时删目录"产生运行中文件占用竞争。

### OutputDump 改造

API 从"基于 workDir"改为"基于 jarDir + 会话 id"：

- `dumpDir(jarDir, sessionId)`：返回 `jarDir/.session/tmp/<sessionId>/`。
- `write(jarDir, sessionId, prefix, content)`：写入会话临时目录（自动建目录）；失败返回 null，调用方降级（行为不变）。
- `tail(file, maxChars)`：不变。
- `cleanup(jarDir, olderThanMillis)`：扫 `.session/tmp/` 下所有会话子目录，删除其中修改时间超过阈值的文件（目录保留——会话未删除时旧文件允许保留供回溯）。
- `workDirRelative` 删除：落盘文件已不在工作空间内，相对路径（`../../` 形态）不可读；返回提示改为直接输出**绝对路径**。

### 工具层注入会话 id

- `SessionManager.newRegistry(ctx)` → `newRegistry(ctx, sessionId)`：BashTool/GrepTool 构造新增 sessionId 参数（`new BashTool(workspace, sessionId)`、`new GrepTool(workspace, skillsDir, sessionId, gate)`），注入点已存在，架构零变化。
- BashTool 超限提示：`... 完整输出已保存到 <绝对路径>，可用 Read 查看 ...`。
- GrepTool 超限提示：同改绝对路径。
- GrepTool 的 SKIP_SUBTREE（跳过 dump 目录）逻辑删除：dump 目录已不在工作空间搜索树内，判断永不命中，属死代码。

### 文件工具白名单

- `PathsGuard.errorIfOutside(workDir, skillsDir, p)` 增加 tmpDir 参数 → `errorIfOutside(workDir, skillsDir, tmpDir, p)`；`inside` 检查同理。
- ReadTool/WriteTool/EditTool/GrepTool/GlobTool/BrowserScreenshotTool 构造新增 sessionId（或直接传 tmpDir 绝对路径），守卫调用同步传参。
- 效果：模型 Read 落盘文件、Write 临时文件**免确认**；按会话隔离——每会话工具只放行自己会话的 tmp 目录。
- 系统提示词"工作目录之外：读取需经系统授权确认"一条同步豁免 tmp 目录。

### 删除清理

- `SessionManager.deleteSession`：stop/shutdown 之后递归删除 `.session/tmp/<sessionId>/`；运行中会话删除时落盘文件可能被写入占用（Windows 句柄），删除失败静默容错，由启动清理兜底。
- `SessionManager.deleteWorkspace`：对该空间所有会话删除对应 tmp 目录（现有循环内逐个处理）。
- Main 启动清理：从"按工作空间 `OutputDump.cleanup(workDir, ...)`"改为 `OutputDump.cleanup(jarDir, RETENTION_MS)`——扫所有会话子目录删超 3 天文件；不再遍历工作空间（顺带移除对 workspaces 列表的启动遍历依赖）。

### 提示词修改（SystemPromptBuilder）

工作目录段（`=== 当前工作目录 ===`）内新增"临时文件"说明：

- 临时文件（调试输出、中间结果、工具超限落盘等）统一放到 `<jarDir>/.session/tmp/<sessionId>/` 目录；**不要在工作空间创建临时文件**。
- 该目录可自由读写，无需授权确认。
- **Bash 环境说明**：Bash 命令在 Git Bash 中执行；丢弃输出必须用 `/dev/null`，写 `> nul` 会被当作文件名在工作目录创建真实的 `nul` 文件。
- "工作目录之外读取需授权"豁免上述临时目录。

### 错误处理

- 落盘失败降级为纯内存截断（现状不变），不阻断工具执行。
- 会话临时目录删除失败：静默（Windows 占用容错），启动清理兜底。
- 会话 id 目录创建失败：落盘降级，工具正常执行。

### 测试

- OutputDump：新目录结构（jarDir/.session/tmp/<id>/）、cleanup 跨会话子目录清理 3 天边界、workDirRelative 移除后返回绝对路径。
- BashTool/GrepTool：超限落盘路径断言改为 `.session/tmp/<id>/` 下的绝对路径；不超限零落盘不变。
- PathsGuard：tmpDir 白名单——tmp 内放行、工作空间外非 tmp 仍拦截。
- SessionManager：deleteSession 后 tmp 目录被删除；deleteWorkspace 后各会话 tmp 目录被删除；运行中删除占用失败静默不抛。
- SystemPromptBuilder：提示词含临时目录段与 /dev/null 说明。
