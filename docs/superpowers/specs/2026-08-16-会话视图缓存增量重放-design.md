# minion 切页签卡死治理（会话视图缓存 + 增量重放）设计

日期：2026-08-16
状态：待用户审查

## 背景

连续点击消息页签后 UI"不停切换、停不下来"。BenchSwitch 基准（真实数据副本 + 真实 MainWindow）实测：每次切页签 FX 队列排空需 0.5~1.5s（96 事件 756ms / 21 事件 1433ms / 3 事件 529ms；热切换 110~726ms），队列能排空非死循环——根因是**每次切换全量重建消息区**：

```
onSessionActivated → ChatView.forSession(h) 新建实例
  → bind(true)：clear() + EventList 全量重放（几百个 runLater 入队）
  → 每段 MessageTextArea 双 runLater 布局精校
  → chatScroll.setContent(新节点)
```

连点几下 → 切换请求在 FX 队列排队逐个执行（每个 0.5~1.5s）→ 视觉上"自动不停切换"。此症状与最近功能改动无关（旧问题）。

已确认的「截断保活 200 段」治长会话滚动卡顿，但**不减少切换时的全量重建开销**（重放遍历全部事件 + 逐段重建节点，截断只在尾部删节点）——对 200 段以下会话（用户大会话仅 96 事件）完全无效。本方案从根上消除重建：**每会话缓存视图，切回只增量渲染新事件**。

## 方案

### 1. EventList 新增原子增量重放 rebind

现状 `setActive(true, l)`：锁内注册 listener + 全量重放。增量重放不能拆成"先取尾部快照、再注册直通"两步——两步间隙后台 add 的事件会丢（进缓冲但 listener 未注册）；反过来"先注册后取快照"会重复（事件既入缓冲又直通）。必须锁内原子完成。

```java
/** 增量重放 + 注册直通（原子）：锁内快照 [from, size) 并设 active/listener。
 *  拆两步会在间隙丢事件或重复渲染（add 与 rebind 同锁互斥）。 */
public synchronized List<Ev> rebind(Listener listener, int from) {
    this.active = true;
    this.listener = listener;
    int n = events.size();
    if (from >= n) return new ArrayList<Ev>();
    return new ArrayList<Ev>(events.subList(Math.max(0, from), n));
}
```

`setActive(false, null)` 保留作解绑路径。纯逻辑无 JavaFX 依赖，可单测。

### 2. ChatView.bind 改为增量重放

- 新增游标 `int replayed`：已渲染到缓冲第几个事件（只被 FX 线程读写，无需 volatile）。
- 直通监听器推进游标：`e -> Platform.runLater(() -> { replayed++; onEventFx(e); })`——渲染完成才推进，下次 bind 不重复渲染直通过的事件。
- `bind(true)`：`List<Ev> tail = events.rebind(listener, replayed); replayed = events.size(); for (Ev e : tail) onEventFx(e);`——首次绑定 replayed=0 全量重放（语义不变），再次绑定只重放新事件，**不再 clear()**。
- 视图保留 stream 缓冲与 segs → 流式合并状态连续：切走时若停在流式中段（THINKING 半段），切回新事件直接就地更新末段，无需重放历史 chunk。
- 新增滚动位置保存字段：`rememberVvalue(double)` / `savedVvalue()`（默认 1.0 贴底）。

### 3. MainWindow 视图缓存

- 新增 `Map<String, ChatView> viewCache`（key = 会话 id，UUID 全局唯一）。
- `onSessionActivated` 改造：
  1. 切走前记旧视图滚动位置：`if (chatView != null) chatView.rememberVvalue(chatScroll.getVvalue())`（内容连续，vvalue 语义保留）
  2. 缓存命中：`bind(true)` 增量 + `setContent` + `setVvalue(savedVvalue)` 恢复位置
  3. 未命中：`forSession` 新建 + 注入 scrollBottomRequest/trimListener + 入缓存 + `bind(true)` 全量
- 缓存清理：
  - 会话删除（页签关闭 OK、侧栏删除回调两处）：`viewCache.remove(h.id)`
  - 工作空间切换（onWorkspaceChanged）：`viewCache.clear()`（跨空间不残留）
- `clearChatPane` 改造：`bind(false)` 后**不再 `clear()`**（视图内容保留供缓存增量），`setContent(占位 Region)` 清视觉，`chatView = null`。

### 4. 并发安全

- `add` 与 `rebind` 同锁互斥：rebind 内注册后，后续 add 直通与快照渲染顺序由 FX 队列 FIFO 保证（直通经 runLater 入队，快照渲染在 FX 线程同步完成于入队之前）。
- 全部 bind/渲染路径在 FX 线程，`replayed` 无跨线程访问。

## 与截断保活协同

缓存视图内容不重建 → 截断只在 append 时发生（更彻底）；每视图 ≤200 段（截断保活兜底）→ 缓存多个会话视图内存可控，无泄漏。

## 实施落点

- [EventList.java](src/main/java/com/minion/gui/session/EventList.java)：新增 `rebind(Listener, int)`；`setActive` 保持。
- [ChatView.java](src/main/java/com/minion/gui/chat/ChatView.java)：`bind` 增量化 + `replayed` 游标 + 滚动位置保存；`clear()` 保留（删除会话回收用）。
- [MainWindow.java](src/main/java/com/minion/gui/MainWindow.java)：`viewCache` + onSessionActivated 缓存分支 + 两处删除清理 + onWorkspaceChanged 清缓存 + clearChatPane 不毁视图。

## 测试

1. EventListTest 新增（纯逻辑单测）：
   - rebind 增量快照正确（from 位置起）
   - rebind 后 add 直通
   - 二次 rebind 不重复渲染
   - from 负数/超界 clamp
   - setActive(false) 后 add 不直通，rebind 再增量
2. BenchSwitch 重跑回归：热切换 drain 预期从 110~726ms 降到个位数毫秒。
3. 全量 `mvn test`。
4. 手工验证清单：
   - 切页签：单次切换毫秒级，连点 10 下立即停稳
   - 切回会话：回到上次滚动位置；有新消息时贴底跟随正常
   - 流式输出中切走再切回：输出连续（末段就地更新）
   - 删除会话/切换工作空间：无视图残留（右侧空白 + 缓存释放）
   - 长会话重放 >200 段：截断保活照常工作

## 影响面

- 仅 EventList/ChatView/MainWindow 三处；不改事件流、不改消息历史（EventList 全量保留）、不改落盘、不改输入区。
- 首次绑定全量重放语义不变（启动自动激活最近会话与现状一致）。
