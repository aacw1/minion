# 429 限流长重试设计

日期：2026-08-24
状态：已批准

## 背景

公司内网模型网关资源紧张，请求频繁返回 429 限流。现状（AgentLoop / SubAgentLoop）对所有 retryable 错误只重试 1 次（429 退避 2s、其余 0.5s），429 恢复前必然失败退出，用户体验差。

## 目标

- 429：长时间自动重试（线性递增退避），期间每次重试更新"正在重试中…第 N 次"提示（动态反馈，避免误以为卡死），成功或超时后一次性反馈
- 500 及其他错误：行为不变（重试 1 次）——500 为网关报文错误，重试过多无意义
- 主循环与子 agent（SubAgentLoop）行为一致
- 用户中断可立即退出重试

## 参数（硬编码常量，不加配置项）

| 参数 | 值 |
|------|-----|
| 起始间隔 | 2 秒 |
| 每次递增 | +2 秒（线性，非指数） |
| 间隔上限 | 10 秒 |
| 总时长上限 | 30 分钟 |

退避序列：2、4、6、8、10、10、10…（约 182 次重试打满 30 分钟）

## 组件改动

### 1. 新增 `core/agent/RetryPolicy.java`（纯算法类）

- 字段：`initialDelayMs`、`incrementMs`、`maxDelayMs`、`maxTotalMs`
- `delayMs(int attempt)`：第 attempt 次重试前等待 = `min(initial + increment * (attempt-1), maxDelay)`
- `isExhausted(long elapsedMs)`：累计等待是否超过总时长
- 静态工厂 `rateLimit()`：返回默认 429 策略（2000/2000/10000/1800000）

### 2. AgentLoop（core/agent/AgentLoop.java）

`runUserTurn` 中 `catch (LlmException e)` 分支重构：

- 新增注入字段（仿 `roundLimit` 风格，测试可覆写小参数）：
  `public RetryPolicy retryPolicy429 = RetryPolicy.rateLimit();`
- **RATE_LIMIT 类型**走长重试循环：
  1. 首次失败：`ui.onWarning("请求失败(429)，正在重试中…第 1 次")`
  2. 循环：`Thread.sleep(delayMs(attempt))` → 重发本轮请求（消息未变）；每次重试失败后更新 `ui.onWarning("正在重试中…第 N 次")`（N = 已重试次数，动态反馈不刷屏式重复）
  3. 成功：`ui.onWarning("已恢复，继续执行")` → 正常继续
  4. 累计等待超总时长：`ui.onError("重试了 N 次，持续 M 分钟，429 仍失败，已停止重试")` → break 结束本轮
  5. 用户中断：`interrupt()` 只设标志 + cancel（不中断主线程），故等待不能直接 `Thread.sleep`——改为**小片轮询**：以 100ms 为片循环 sleep，每片后检查 `interrupted` 标志，响应延迟 ≤ 100ms
- **其他 retryable（NETWORK / TIMEOUT / 5xx）**：保持现状（重试 1 次、0.5s 退避）
- 非 retryable（400/401/403 等）：不变

### 3. SubAgentLoop（core/agent/SubAgentLoop.java）

- 同样新增 `retryPolicy429` 注入字段
- `catch (LlmException e)` 分支同步 429 长重试（提示前缀"子 agent"）；
- 中断检查沿用现有 `Thread.currentThread().isInterrupted()` + catch InterruptedException（子 agent 线程被 future.cancel(true) 真实中断，sleep 会被唤醒，走现有 catch 路径）

### 4. RunningIndicator 重试进度显示（正文左下角齿轮+文案区）

重试次数提示显示在正文左下角运行状态指示器（齿轮旋转 + 文案），替代原"正在加载中..."轮换文案，动态反馈防误以为卡死。链路仿上下文压缩：

- **AgentUi**（core/agent/AgentUi.java）：加 `default void onRetryProgress(int attempt) { }`——attempt ≥ 1 进入/更新重试态，attempt == 0 退出重试态
- **SessionController**（gui/session/SessionController.java）：加 `retryStateListener`（Consumer&lt;Integer&gt;）+ setter，覆写 onRetryProgress 转发
- **SessionManager**（gui/session/SessionManager.java）：Listener 接口加 `default void onRetryProgress(SessionHandle h, int attempt)`；新增 `notifyRetryProgress`；新建会话与恢复会话两处注入 retryStateListener（仿 compressing 接线，约 221/351 行）
- **MainWindow**（gui/MainWindow.java）：实现 `onRetryProgress` → Platform.runLater → 仅当前激活会话时 `runningIndicator.setRetryProgress(attempt)`
- **RunningIndicator**（gui/RunningIndicator.java）：加 `retryAttempt` 字段；`setRetryProgress(int attempt)`——attempt ≥ 1：停轮换、显示 `retryText(attempt)`（"正在重试中…第 N 次"）；attempt == 0：恢复轮换/压缩文案；`setRunning(false)` 复位 retryAttempt=0；文案优先级 retrying > compressing > 轮换
- **AgentLoop / SubAgentLoop**：重试循环内每次重试前 `ui.onRetryProgress(attempts)`；退出重试（成功/超时/中断）后 `ui.onRetryProgress(0)` 复位；消息区不再发"正在重试中"警告（移入指示器），保留"已恢复，继续执行"onWarning 与超时 onError 总结

## 不改动的部分

- 500 / 网络 / 超时：仍重试 1 次
- 图片降级路径（degradeImagesOnFailure）、上下文压缩路径、STUCK 止损：不变
- config.properties：无新增配置项
- DeepSeekClient：无改动（429 已由 `LlmException.of` 归为 RATE_LIMIT + retryable）

## 测试

AgentLoopTest / SubAgentLoopTest 新增：

1. **429 重试成功**：FakeLlmClient 先 429 后正常 → 断言 onRetryProgress 序列 [1, 0]、消息区仅"已恢复"1 条警告、最终正常完成
2. **429 持续失败超时**：注入小参数策略（如 10ms 起步、总时长 100ms）→ 断言"N 次 / M 分钟"总结提示、onRetryProgress 末位 0、不再重发、本轮报错结束
3. **重试 sleep 中 interrupted**：429 持续失败 + 中途 interrupt() → 小片轮询 ≤100ms 内退出，不等待下一完整间隔

RunningIndicatorTest 新增：`retryText(3)` == "正在重试中…第 3 次"（纯静态方法单测）

## 验收标准

- `mvn compile` 通过，相关测试通过
- 429 长重试期间左下角指示器显示"正在重试中…第 N 次"（动态次数，替代"正在加载中..."轮换）；成功/超时后复位并各一次消息区提示
- 主循环与子 agent 行为一致；用户停止立即生效
