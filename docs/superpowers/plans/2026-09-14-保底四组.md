# 压缩保留区保底四组实施计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 把 `ContextManager` 保留区的保底从"最新 1 组"改为"常态最近 4 组、危险区（estimate ≥ 85%×max）降为 1 组"，使最近 4 个原子组在常态下绝不被压缩，同时保留贴窗保命能力。

**Architecture:** 改动全部收敛在 `ContextManager`（常量 + `minKeepGroups` + `keepCount` 签名/返回值 + 调用点接线）；`AgentLoop` / `SubAgentLoop` 主代码零改动。端到端行为由既有测试文件更新与新增用例锁定。

**Tech Stack:** Java 8、Maven、JUnit 4、`FakeLlmClient` 测试替身、`TemporaryFolder`。

**设计文档:** `docs/superpowers/specs/2026-09-14-保底四组-design.md`（已获批，提交 `74ce3fe`）

## Global Constraints

- **常量定稿（逐字）**：`KEEP_MIN_GROUPS = 4`（常态保底，超预算仍保）；新增 `KEEP_CRITICAL_GROUPS = 1`（危险区保底）；`KEEP_BUDGET_RATIO = 0.2`、`MIN_COMPRESSIBLE_RATIO = 0.05`、`FORCE_COMPRESS_RATIO = 0.85`、`THRESHOLD = 0.65`、`SUMMARY_MAX_CHARS = 5000` **不变**。
- **`keepCount` 返回值必须 ≤ 组数**：用 `return keep;`（循环已保证下限：不 break 直到 `keep ≥ minKeep` 或组耗尽），**不得**再写 `Math.max(keep, minKeep)`。
- **同一判定**：`compress` 与 `compressibleTokens` 必须共用同一 `minKeepGroups(messages)` 结果（口径一致，不允许出现"门槛通过但 take=0"）。
- **不改**：`chunkGroups` 分组规则、压缩指令与摘要上限、提示文案、`AgentLoop` / `SubAgentLoop` 主代码、`config.properties`、GUI、危险区阈值与收益门槛。
- **JDK 8 语法**（禁 `var`/`List.of`/文本块）；中文注释与提交信息（conventional 格式）。
- **TokenCounter 口径**（写测试注释与推演数字时用）：中文 1 字 ≈ 0.7，其他 1 字符 ≈ 0.25，每消息 +4，向上取整。本计划中的预期 token 数字均按此推演；**实测不符时以实测为准**（在注释中写明实际值与推演依据，实施报告说明偏离原因），但测试场景前提（超阈值/危险区/组数等）必须成立。
- 每任务结束：相关测试全绿并提交；最后 `mvn test` 全量（基线 1159）+ `mvn -q package -DskipTests`。
- 测试文件中的既有"场景前提"自证断言风格（`assertTrue("场景前提：…")`）沿用。

**(b)** 新增 `minKeepGroups`，并改写 `keepCount`（含 `compress` / `compressibleTokens` 调用点）：

```java
    /** 本次压缩的保底保留组数：危险区（estimate ≥ 85%×max）降为最新 1 组，常态保底最近 4 组 */
    private int minKeepGroups(List<Message> messages) {
        return estimate(messages) >= maxContextTokens * FORCE_COMPRESS_RATIO
                ? KEEP_CRITICAL_GROUPS : KEEP_MIN_GROUPS;
    }

    /** 保留的原子组数：从最新组往前累加 token，累计 ≤ 预算的最大组数；
     *  下限 minKeep（常态 4 组保底 / 危险区 1 组），无上限（预算内尽量多留）；
     *  组数 < minKeep 时返回组数本身（take = 0 → 不压缩）。
     *  组内是协议不可拆单位（assistant(tool_calls)+tool 配对），只能整组保留/整组压缩。 */
    private int keepCount(List<List<Message>> groups, int minKeep) {
        if (groups.isEmpty()) return 0; // 空组：keep=0（take=0，compress 同引用返回）
        long budget = (long) (maxContextTokens * THRESHOLD * KEEP_BUDGET_RATIO);
        long acc = 0;
        int keep = 0;
        for (int i = groups.size() - 1; i >= 0; i--) {
            long t = TokenCounter.estimateMessages(groups.get(i));
            if (keep >= minKeep && acc + t > budget) break;
            acc += t;
            keep++;
        }
        return keep; // 循环语义已保证：不 break 直到 keep ≥ minKeep 或组耗尽（返回值 ≤ 组数、take ≥ 0）
    }
```

